> [!abstract] Определение
> **Тип данных** (*type*) — известное на этапе компиляции свойство [[Объект|объекта]], [[Левая ссылка|ссылки]], [[Функция|функции]] или [[Выражение|выражения]], которое определяет множество допустимых значений, их представление в памяти (размер объекта и смысл его битов) и набор применимых операций вместе со смыслом этих операций.

## Примечания и тонкости

- В стандарте термин — просто «тип» (*type*); «тип данных» — общепрограммистское словосочетание. Типы описывают объекты, ссылки и функции (`[basic.types]`); кроме того, тип есть у каждого выражения.
- **Три вопроса, на которые отвечает тип:** какие значения возможны; сколько байт занимает объект и как читать его биты; что с ним можно делать. Одни и те же биты `01000001` как [[Символьный тип|char]] — символ `'A'`, как [[Целый тип|int]] — число 65. Тот же эффект у [[Оператор|операторов]]: `7 / 2` для `int` — целочисленное деление, `7.0 / 2` — вещественное.
- **Статическая типизация.** Тип каждой [[Переменная|переменной]] и каждого выражения установлен при компиляции и во время выполнения не меняется; несовместимость типов обнаруживает компилятор. Ключевое слово `auto` этого не отменяет — тип просто выводится из инициализатора. Речь всюду идёт о *статическом* типе; у выражения, обозначающего объект полиморфного класса, есть ещё динамический тип, доступный через `typeid` и `dynamic_cast` ([[Динамический полиморфизм]]).
- **Классификация (`[basic.types]`):** **фундаментальные** типы ([[Встроенный тип]]) — арифметические (целочисленные: целые, а формально также символьные и [[Логический тип|bool]]; и [[Вещественный тип|с плавающей точкой]]), [[Тип void|void]] и `std::nullptr_t`; **составные** (*compound*) — [[Встроенный массив|массивы]], функции, [[Указатель|указатели]], ссылки, классы ([[Структура|struct]], [[Класс и экземпляр|class]], `union`), [[Перечисление|перечисления]], указатели на члены. Классы и перечисления создаёт сам программист — это пользовательские типы.
- **Объектные** типы — все, кроме ссылочных, функциональных и `void`: объект необъектного типа создать нельзя. По этой причине классическое определение «тип — множество значений и множество операций над ними» годится лишь для объектных типов: у `void` множество значений пусто, а у функциональных и ссылочных типов объектов-значений нет вовсе.
- **Неполный тип** — тип, размер которого компилятору неизвестен: `void`, объявленный но не определённый класс, массив неизвестной границы. Объект неполного типа создать и применить к нему `sizeof` нельзя, но объявить указатель или ссылку на него можно.
- **Размеры определяются реализацией** (*implementation-defined*), стандарт задаёт только минимумы: `sizeof(char) == 1` всегда, `int` — не менее 16 бит, `long` — не менее 32, `long long` — не менее 64; гарантирована и цепочка `sizeof(char) <= sizeof(short) <= sizeof(int) <= sizeof(long) <= sizeof(long long)`. С C++20 знаковые целые обязаны использовать дополнительный код, поэтому N-битный знаковый тип хранит ровно диапазон от минус двух в степени N−1 до двух в степени N−1 минус один; для типичного 32-битного `int`:

$$
-2^{31} \le x \le 2^{31} - 1
$$

- Подробнее о границах и переполнении — [[Диапазоны арифметических типов]]; расположение объекта в памяти дополнительно ограничено [[Выравнивание|выравниванием]] его типа.
- **cv-квалификация порождает разные типы:** `int`, `const int`, `volatile int` и `const volatile int` — четыре различных типа ([[Константность]] является частью типа). Точно так же `char`, `signed char` и `unsigned char` — три разных типа, и знаковость простого `char` определяется реализацией.
- [[Псевдоним типа|Псевдоним]] (`typedef`, `using`) нового типа не создаёт — это второе имя существующего. Напротив, каждое определение класса или перечисления создаёт новый тип, отличный от всех прочих, даже при полностью совпадающем содержимом.
- Тип выражения никогда не бывает ссылочным: если выражение имеет тип «ссылка на `T`», его тип корректируется до `T` (`[expr.type]`). Для `int& r = x;` тип *переменной* `r` — `int&`, а тип *выражения* `r` — `int`.
- Операнды разных типов приводятся к общему по правилам [[Неявные преобразования типов|неявных преобразований]]; для пользовательских типов смысл операций задаётся [[Перегрузка операторов|перегрузкой операторов]]. В C++23 добавлены необязательные расширенные типы с плавающей точкой (`std::float16_t`, `std::bfloat16_t` и др., заголовок `<stdfloat>`).
- **На практике:** неудачно выбранный тип — главный источник переполнений и потери точности ([[Выбор типа данных]]). При этом тип — основной инструмент проверки программы компилятором: введение отдельных типов (`enum class`, классы-обёртки вместо «голых» `int`) переводит логические ошибки в ошибки компиляции.

## Пример

```cpp
#include <iostream>
#include <type_traits>

using Integer = int;              // псевдоним: новый тип НЕ создаётся
enum class Color { red, green };  // новый тип, отличный от int

int main() {
    int a = 7, b = 2;
    double x = 7.0, y = 2.0;
    std::cout << a / b << ' ' << x / y << '\n';   // выведет: 3 3.5

    char c = 65;                  // те же биты — другая интерпретация
    std::cout << c << ' ' << static_cast<int>(c) << '\n';   // выведет: A 65

    std::cout << sizeof(char) << ' ' << sizeof(int) << ' ' << sizeof(double) << '\n';
    // выведет (типично для x86-64): 1 4 8; стандартом гарантирован только sizeof(char) == 1

    auto z = a / 2.0;             // тип выводится при компиляции: double
    std::cout << z << '\n';       // выведет: 3.5
    static_assert(std::is_same_v<Integer, int>);      // псевдоним — тот же тип
    static_assert(!std::is_same_v<const int, int>);   // cv-квалифицированный — другой тип
    static_assert(!std::is_same_v<Color, int>);       // перечисление — новый тип
    // Color col = 1;             // ошибка: нет неявного преобразования int -> Color
    // a = "seven";               // ошибка: тип int не принимает строку
}
```

`static_assert` проверяет утверждения о типах на этапе компиляции: программа собирается только если все они истинны.

## Ловушки на экзамене

- **Сколько байт занимает `int`?** — Определяется реализацией: стандарт гарантирует лишь ширину не менее 16 бит. Точно зафиксирован только `sizeof(char) == 1`. Ответ «всегда 4 байта» — ошибка: это свойство распространённых платформ, а не языка.
- **Почему `7 / 2` равно 3, а не 3.5?** — Смысл оператора определяется типами операндов: оба `int`, значит деление целочисленное и дробная часть отбрасывается. Достаточно сделать вещественным один операнд (`7 / 2.0`) — второй неявно преобразуется к `double`.
- **Делает ли `auto` язык динамически типизированным?** — Нет. `auto x = 5;` — это ровно `int x = 5;`: тип выводится при компиляции и дальше не меняется.
- **`int` и `const int` — один и тот же тип?** — Нет, разные: cv-квалификация входит в тип. Однако верхний `const` параметра не входит в тип функции, поэтому `void f(int)` и `void f(const int)` объявляют одну и ту же функцию.
- **Создаёт ли `using Integer = int;` новый тип?** — Нет, только второе имя существующего; поэтому [[Перегрузка функций|перегрузки]] по `int` и по `Integer` конфликтуют как повторное объявление.
- **`void` — это тип? Можно ли объявить `void v;`?** — Тип да, но неполный и с пустым множеством значений, поэтому объект типа `void` создать нельзя. Используется как тип возврата функции, ничего не возвращающей, и в составе `void*`.
- **`char` знаковый или беззнаковый?** — Определяется реализацией: на x86 обычно знаковый, на ARM часто беззнаковый. Для работы с «сырыми» байтами надёжнее `unsigned char` или `std::byte`.

## Протокол спора

> [!quote]- Как рождалось определение
> **Версия A (Формалист):** «Тип данных (*type*) — известное на этапе компиляции свойство объекта, ссылки, функции или выражения, определяющее, какие операции к ним применимы и каков смысл этих операций. Для объектного типа тип, кроме того, задаёт множество допустимых значений, их представление в памяти, размер и выравнивание объекта.»
>
> **Версия Б (Педагог-практик):** «Тип данных (*data type*) — характеристика каждого объекта, ссылки, функции и выражения программы, которая определяет множество допустимых значений, их представление в памяти (размер и способ интерпретации битов) и набор допустимых операций.»
>
> **Спорные пункты:**
> 1. Английский термин: `type` (A) против `data type` (Б). → **Решение:** `type`, как в стандарте; замечание A о том, что «тип данных» — общепрограммистское словосочетание, перенесено в примечания.
> 2. Структура определения. У A «множество значений и представление» отнесено во второе предложение только к объектным типам; у Б всё в одном предложении, но тогда утверждение «множество значений» ложно для `void` и ссылочных типов. → **Решение:** взята компактная схема Б (три вещи в одном предложении), а ограничение A сохранено отдельным примечанием про объектные типы — так определение остаётся пригодным для устного ответа и не становится ложным.
> 3. «Известное на этапе компиляции» против динамического типа. Б указал на противоречие между определением A и его же примечанием о полиморфных классах. → **Решение:** возражение принято: в примечании прямо сказано, что всюду речь о *статическом* типе, а динамический вводится отдельно.
> 4. Числовые гарантии. A: «стандарт гарантирует лишь ширину не менее 16 бит и `sizeof(int) >= 1`». Б: нужны минимумы для `long` и `long long` и формула диапазона. → **Решение:** взята версия Б и дополнена арбитром цепочкой `sizeof(char) <= sizeof(short) <= …`, которой не было ни у кого: слово «лишь» у A вводило в заблуждение.
> 5. Полнота классического определения «множество значений + операции». A опровергает его, Б опасается, что студент останется без короткого ответа. → **Решение:** компромисс: формулировка названа годной для объектных типов с указанием, почему она не покрывает `void`, ссылки и функции.
> 6. Наполнение примера. Б: у A четыре `static_assert` и ни одного наблюдаемого размера или интерпретации битов. → **Решение:** за основу взят пример Б (деление, `'A'`/65, `sizeof`), к нему добавлены три `static_assert` из версии A — они показывают различие «псевдоним / новый тип / cv-тип», которое иначе не продемонстрировать.
>
> **Итог:** определение — синтез: род и перечень трёх функций типа от Б, уточнение про компиляцию и объектные типы от A. От A взяты: оговорка про термин «тип», классификация по `[basic.types]`, объектные и неполные типы, «псевдоним не создаёт тип — определение класса создаёт», тип выражения никогда не ссылочный, C++23 и `<stdfloat>`, ловушки про `const int` и `using`. От Б: три вопроса, на которые отвечает тип, интерпретация одних и тех же битов, `auto` и статическая типизация, числовые минимумы и формула диапазона, знаковость `char`, ловушки про размер `int`, `7 / 2`, `auto` и `void`. Арбитр удалил из версии A биты заполнения, `std::is_object_v` и разбор `decltype`, из версии Б — утверждение «неполный тип — это `void` или класс без определения» как неполное (добавлен массив неизвестной границы) и аналогию с «инструкцией по обращению», дублирующую пункт о трёх вопросах.
