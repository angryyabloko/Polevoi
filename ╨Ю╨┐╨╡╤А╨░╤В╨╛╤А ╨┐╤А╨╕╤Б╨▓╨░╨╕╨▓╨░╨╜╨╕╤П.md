# Оператор присваивания

> [!abstract] Определение
> **Оператор присваивания** (*assignment operator*) — бинарный [[Оператор|оператор]] `=`, который заменяет значение [[Объект|объекта]], обозначенного левым операндом, значением правого операнда, преобразованным к [[Тип данных|типу]] левого операнда, и даёт результатом левый операнд как [[lvalue и rvalue|lvalue]]. Левым операндом может быть только модифицируемое lvalue. К операторам присваивания относятся также составные формы `E1 op= E2`.

## Примечания и тонкости

- **Составные операторы присваивания** — их десять: `+=`, `-=`, `*=`, `/=`, `%=`, `<<=`, `>>=`, `&=`, `^=`, `|=`. Запись `E1 op= E2` равносильна `E1 = E1 op E2` с единственным отличием: `E1` вычисляется ровно один раз. Поэтому в `v[f(i)] += 1` функция `f` вызывается однократно, а в `v[f(i)] = v[f(i)] + 1` — дважды.
- **Присваивание ≠ инициализация.** В `int x = 5;` знак `=` — часть синтаксиса инициализатора в [[Объявление|объявлении]], а не оператор: объект получает значение в момент создания, и оператор присваивания не применяется ([[Инициализация]]). Для классов разница наблюдаема: `T a = b;` вызывает [[Конструктор копирования|конструктор копирования]], а `a = b;` для уже существующего `a` — копирующий оператор присваивания. Для [[Константность|константного]] объекта и для ссылки возможна только инициализация.
- **Присваивание — выражение, а не инструкция.** `x = 5;` — это инструкция-выражение, но сам оператор применим везде, где допустимо [[Выражение|выражение]]: `f(x = 5)`, `while ((c = next()) != 0)`, `a = b = c`.
- **Требование к левому операнду — модифицируемое lvalue.** Не подходят: prvalue (`5 = x`, `a + b = c`), объект с квалификатором `const`, [[Встроенный массив|массив]] целиком (`u = v` — ошибка `invalid array assignment`; массив можно инициализировать, но не присвоить).
- **Преобразование правого операнда.** Значение правого операнда [[Неявные преобразования типов|неявно преобразуется]] к cv-неквалифицированному типу левого. При `int i; i = 3.9;` дробная часть отбрасывается (`i == 3`); если вещественное значение не помещается в [[Диапазоны арифметических типов|диапазон]] целевого целого типа — UB. При присваивании целого значения более узкому целому типу с C++20 результат определён (значение, сравнимое с исходным по модулю `2^N`, где `N` — число бит); до C++20 для знаковых типов он был implementation-defined.
- **Фигурные скобки справа.** Для скалярного `x` типа `T` запись `x = {v}` означает `x = T{v}`, поэтому сужающее преобразование здесь — ошибка компиляции (`narrowing conversion`), а не молчаливое отбрасывание; `x = {}` означает `x = T{}`, то есть присваивание нуля.
- **Результат — lvalue** (в языке C результат присваивания — значение, не lvalue). Поэтому в C++ корректны `(a = b) = c`, `++(a = b)` и `int& r = (a = 1);`. Это свойство встроенного оператора; результат перегруженного `operator=` — то, что он возвращает (по соглашению `T&`).
- **Ассоциативность и приоритет.** `a = b = c` ≡ `a = (b = c)`. [[Приоритеты операторов|Приоритет]] присваивания — на одном уровне с `?:` и `throw`; ниже только оператор [[Оператор «запятая»|«запятая»]]. Поэтому `x = a + b` и `x = a < b` не требуют скобок, а `x = 1, 2` означает `(x = 1), 2`.
- **Порядок вычисления (с C++17).** Правый операнд со всеми побочными эффектами упорядочен до левого, а запись значения — после вычисления значений обоих операндов. Поэтому `a[i] = i++` с C++17 определено (запись идёт в элемент с уже увеличенным индексом), и `i = i++` тоже определено (`i` не меняется); до C++17 оба выражения были UB ([[Порядок вычисления выражений]]). Выражение `i++ + i++` остаётся UB и в C++20: операнды `+` ничем не упорядочены.
- **Предупреждение остаётся.** g++ 13 на `i = i++` и `a[i] = i++` по-прежнему выдаёт `-Wsequence-point` («operation on `i` may be undefined»), хотя с C++17 поведение определено: проверка консервативна и рассчитана на старые стандарты ([[Предупреждения компилятора]]). Писать так всё равно не следует.
- **Для классов** `a = b` — вызов [[Метод|функции-члена]] `operator=`: копирующего или [[Перемещающий оператор присваивания|перемещающего оператора присваивания]] (их может неявно сгенерировать компилятор — почленное [[Копирование объектов|копирование]] или перемещение) либо другой перегрузки ([[Перегрузка операторов]]). `operator=` может быть только нестатической функцией-членом. Самописный оператор должен корректно работать при присваивании объекта самому себе. Составные операторы для класса — отдельные функции: из наличия `+` и `=` не следует наличие `+=`.
- **Двусмысленность термина.** «Оператор присваивания» означает и знак `=` в выражении, и специальную функцию-член `operator=` (*copy assignment operator*); из контекста экзаменационного вопроса нужно понять, о чём речь.
- **На практике:** присваивание в условии (`if ((n = read()) > 0)`) — законная идиома, но источник опечаток: `=` вместо `==` — одна из самых частых ошибок новичка, и ловит её только предупреждение компилятора. Современный стиль предпочитает инструкцию инициализации: `if (int n = read(); n > 0)`.

## Пример

```cpp
#include <iostream>

int main() {
    int a = 0, b = 0, c = 0;           // это инициализация, а не присваивание

    a = b = c = 7;                     // правая ассоциативность: a = (b = (c = 7))
    std::cout << a << b << c << '\n';   // выведет: 777

    int& r = (a = 1);                  // результат присваивания — lvalue, обозначающее a
    r = 2;
    std::cout << a << '\n';            // выведет: 2

    int x = 10;
    x += 5;                            // как x = x + 5, но x вычисляется один раз
    std::cout << x << '\n';            // выведет: 15
    x = 3.9;                           // double -> int: дробная часть отбрасывается
    std::cout << x << '\n';            // выведет: 3

    // x = {3.9};                      // ошибка: сужающее преобразование в списке
    // const int k = 1; k = 2;         // ошибка: k — не модифицируемое lvalue
    // int u[2]{}, v[2]{}; u = v;      // ошибка: invalid array assignment
    // 5 = x;                          // ошибка: левый операнд — prvalue
    // if (x = 0) { }                  // компилируется, но это не сравнение (-Wparentheses)
}
```

Строка `int& r = (a = 1);` показывает главное свойство встроенного присваивания: его результат — сам левый операнд, а не копия значения.

## Ловушки на экзамене

- **`int x = 5;` — это присваивание?** — Нет, инициализация: `=` здесь часть синтаксиса объявления, объект создаётся сразу со значением, прежнего значения у него не было. Присваивание возможно только для уже существующего объекта.
- **Чему равны `a`, `b`, `c` после `a = b = c = 7;`?** — Все трое равны 7: оператор правоассоциативен, сначала выполняется `c = 7`, его результат (lvalue `c`) даёт значение для `b`, и так далее.
- **Скомпилируется ли `if (x = 0)`?** — Да: присваивание — выражение, его значение (0) контекстно преобразуется к `false`, ветвь не выполняется, а `x` обнуляется. Ошибка логическая, а не синтаксическая; g++ с `-Wall` выдаёт `-Wparentheses`, и если присваивание в [[Инструкции выбора|условии]] намеренное, его заключают в дополнительные скобки.
- **Что даёт `a = b` — значение или lvalue?** — lvalue, обозначающее `a`. Поэтому законны `int& r = (a = b);` и `(a = b) = c`, а перегруженный `operator=` традиционно возвращает `T&`. В C результат присваивания — значение, и `(a = b) = c` там не компилируется.
- **Можно ли присвоить один массив другому (`int u[3], v[3]; u = v;`)?** — Нет: массив не является модифицируемым lvalue, присваивания для встроенных массивов не существует. Копируют поэлементно либо берут `std::array`/`std::vector`.
- **`x += y` всегда то же, что `x = x + y`?** — Для встроенных типов результат тот же, но `x` вычисляется один раз — это важно при побочных эффектах в `x`. Для классов это разные функции, которые могут быть реализованы по-разному (часто `+=` эффективнее, без временного объекта) или вовсе отсутствовать.
- **Чему равно `i` после `i = i++;`?** — С C++17 поведение определено: правый операнд (значение — старое `i`, побочный эффект инкремента) упорядочен до записи, поэтому `i` не меняется. До C++17 — UB. g++ всё равно предупреждает, и писать так не следует.

## Связанные термины

- [[Инициализация]] — задаёт первое значение при создании объекта; присваивание заменяет уже имеющееся.
- [[lvalue и rvalue]] — объясняет требование к левому операнду и то, почему результат — lvalue.
- [[Операторы сравнения]] — `==` проверяет равенство, `=` изменяет объект; путают их чаще всего.
- [[Приоритеты операторов]] — у присваивания один из самых низких приоритетов и правая ассоциативность.
- [[Порядок вычисления выражений]] — с C++17 правый операнд присваивания упорядочен до левого.
- [[Неявные преобразования типов]] — правый операнд приводится к типу левого.
- [[Перегрузка операторов]] — для классов `=` и `op=` — вызовы `operator=`, `operator+=` и т. д.
- [[Перемещающий оператор присваивания]] — форма присваивания, забирающая ресурсы у временного объекта.

## Протокол спора

> [!quote]- Как рождалось определение
> **Версия A (Формалист):** «Оператор присваивания (*assignment operator*) — бинарный оператор `=`, который заменяет значение объекта, обозначенного левым операндом (модифицируемым lvalue), значением правого операнда, предварительно преобразованным к типу левого операнда; результатом выражения присваивания является lvalue, обозначающее левый операнд. Вместе с десятью составными операторами присваивания (`+=`, `-=`, `*=`, `/=`, `%=`, `<<=`, `>>=`, `&=`, `^=`, `|=`) он образует группу операторов присваивания с правой ассоциативностью.»
>
> **Версия Б (Педагог-практик):** «Оператор присваивания (*assignment operator*) — бинарный оператор `=`, который записывает значение правого операнда в объект, обозначенный левым операндом, и даёт результатом сам левый операнд как lvalue. Левый операнд обязан быть модифицируемым lvalue. К операторам присваивания относятся также составные формы `+=`, `-=`, `*=`, `/=`, `%=`, `&=`, `|=`, `^=`, `<<=`, `>>=`.»
>
> **Спорные пункты:**
> 1. Преобразование правого операнда в определении. A его называет, Б — нет («записывает значение правого операнда»). → **Решение:** взято у A: без этой оговорки определение неверно для `int i; i = 3.9;`, где записывается не значение правого операнда, а результат его преобразования. Это видовое отличие, а не пример.
> 2. Перечень составных операторов и ассоциативность внутри определения. A выносит их во второе предложение определения, Б — в третье. → **Решение:** перечень из десяти знаков и правая ассоциативность убраны в «Примечания»: регламент запрещает перечни-иллюстрации в определении, а для устного ответа достаточно назвать группу формой `E1 op= E2`. Структура определения взята у Б (требование к левому операнду — отдельным предложением, а не вставкой в скобках).
> 3. «Присваивание — только отдельная инструкция вида `x = 5;`» (Б). → **Решение:** утверждение Б ошибочно и удалено. Присваивание — выражение; оно законно внутри другого выражения (`f(x = 5)`, `while ((c = next()) != 0)`), и именно поэтому компилируется `if (x = 0)` — ловушка, которую сам Б и приводит. Добавлено отдельное примечание.
> 4. Статус `i = i++` и `a[i] = i++` в C++20. A: определено с C++17, до C++17 UB. Б: то же, плюс «g++ по-прежнему выдаёт `-Wsequence-point`». → **Решение:** правы оба, взяты оба утверждения. Проверено компиляцией g++ 13.3 с `-std=c++20 -Wall -Wextra -pedantic`: `i = i++` оставляет `i` равным 0, `a[j] = j++ + 42` пишет 42 в `a[1]`, то есть поведение определено и соответствует правилу «правый операнд упорядочен до левого»; при этом на оба выражения выдаётся `warning: operation on 'i' may be undefined [-Wsequence-point]`. Добавлено пояснение, что предупреждение консервативно, — иначе студент решит, что компилятор сообщает об UB.
> 5. Правило для `x = {v}`. Есть только у A. → **Решение:** принято и проверено: `int x; x = {3.9};` даёт `error: narrowing conversion of '3.8999999999999999e+0' from 'double' to 'int'`.
> 6. Наполнение примера. A показывает `(a = 1) = 2`, Б — `int& r = (a = 1);`. → **Решение:** взята запись Б: она демонстрирует то же свойство (результат — lvalue), но понятнее, потому что связывание ссылки встречается в реальном коде, а двойное присваивание выглядит как трюк. Закомментированные ошибочные строки взяты у A (их четыре против одной у Б), сообщения компилятора сверены.
>
> **Итог:** определение — гибрид: род и формулировка «даёт результатом левый операнд как lvalue» от Б, преобразование к типу левого операнда от A, перечень составных форм вынесен арбитром в примечания. От A взяты: разграничение присваивания и инициализации (включая `T a = b;` против `a = b;`), требования к левому операнду с перечнем непригодных случаев, правило преобразования с отличием C++20 от предыдущих стандартов, правило для фигурных скобок справа, отличие результата от языка C, приоритет и ассоциативность, ограничение «`operator=` — только нестатическая функция-член», двусмысленность термина, идиома `if (int n = read(); n > 0)`. От Б взяты: структура определения, пример со ссылкой на результат присваивания, требование корректного самоприсваивания, акцент на `-Wparentheses` и на путанице `=` с `==`, ловушка про цепочку `a = b = c = 7`. Арбитр добавил примечание «присваивание — выражение, а не инструкция» (исправление ошибки Б), пояснение про консервативность `-Wsequence-point` и уточнение, что `i++ + i++` остаётся UB и в C++20.
