# Битовые операторы

> [!abstract] Определение
> **Битовые (побитовые) операторы** (*bitwise operators*) — группа [[Оператор|операторов]], которые рассматривают целочисленный операнд как последовательность двоичных разрядов (битов) его представления и вычисляют результат поразрядно либо сдвигом разрядов: `~` инвертирует каждый бит, `&`, `|` и `^` выполняют И, ИЛИ и исключающее ИЛИ над каждой парой соответствующих битов двух операндов, а `<<` и `>>` сдвигают биты влево и вправо на заданное число позиций.

## Примечания и тонкости

- **Правила для одного бита:** `&` даёт 1, только если оба бита равны 1; `|` — если хотя бы один равен 1; `^` — если биты различны; `~` меняет 0 на 1 и наоборот. Над числом эти правила выполняются для всех разрядов одновременно: `0b1100 & 0b1010` равно `0b1000`.
- **Операнды — только целые:** [[Целый тип|целые типы]] (включая `char` и `bool`) и [[Перечисление|перечисления]] без `class`; для [[Вещественный тип|вещественных]] это ошибка компиляции.
- **Продвижения меняют тип операнда.** К операндам `&`, `|`, `^` применяются целочисленные продвижения и затем обычные арифметические преобразования ([[Неявные преобразования типов|неявные преобразования]]), а к операндам сдвигов — **только продвижения, к каждому операнду отдельно**. Отсюда два следствия. Первое: тип результата сдвига определяется исключительно левым операндом, поэтому `1u << 3` имеет тип `unsigned`, а `1 << 3` — `int`. Второе: «маленькие» типы расширяются до `int`, поэтому `~` от `unsigned char` со значением `0x0F` даёт `int` со значением `-16`, а не `0xF0`; результат приходится явно сужать обратно ([[Приведение типа static_cast|static_cast]]).
- **Сдвиги и степени двойки.** Для неотрицательных значений `x << n` — умножение на `2^n`, `x >> n` — деление на `2^n` с округлением вниз. Если правый операнд отрицателен или не меньше ширины продвинутого типа левого операнда — **UB**: `1 << 32` для 32-битного `int` не обязан давать нуль.
- **Что изменилось в C++20.** Знаковые целые обязаны храниться в дополнительном коде ([basic.fundamental]), поэтому результаты `~`, `&`, `|`, `^` над отрицательными значениями переносимы между реализациями. Значение `a << b` определено как единственное значение, конгруэнтное

$$
a \cdot 2^{b} \pmod{2^{N}}
$$

  где `N` — ширина типа результата; благодаря этому сдвиг влево отрицательного значения перестал быть UB (до C++20 был UB). Значение `a >> b` — частное `a / 2^b`, округлённое **к минус бесконечности**, то есть для знаковых типов это арифметический сдвиг с сохранением знака (`-8 >> 1` равно `-4`); до C++20 правый сдвиг отрицательных значений был implementation-defined. Совет при этом не изменился: для работы с битами брать **беззнаковые** типы фиксированной ширины.
- **Маска** — число, в котором единицами отмечены интересующие биты: `&` пропускает только отмеченные биты, `|` устанавливает их в единицу, `^` переворачивает. Четыре стандартных действия с битом `k` числа `x`: установить — `x |= 1u << k`; сбросить — `x &= ~(1u << k)`; переключить — `x ^= 1u << k`; проверить — `(x >> k) & 1u`.
- **Составные формы** `&=`, `|=`, `^=`, `<<=`, `>>=` — это [[Оператор присваивания|присваивания]]: они, в отличие от самих битовых операторов, изменяют левый операнд.
- **Неожиданно низкий приоритет.** `&`, `^`, `|` слабее сравнений: `x & 1 == 0` — это `x & (1 == 0)`, то есть всегда `0` (g++ с `-Wall` предупреждает). Сдвиги слабее `+` и `-`: `1 << n + 1` — это `1 << (n + 1)`. Практическое правило: вокруг битовых операций ставить скобки. См. [[Приоритеты операторов]].
- **`<<` и `>>` у потоков** — те же лексемы, [[Перегрузка операторов|перегруженные]] для [[Операторы ввода и вывода|ввода и вывода]]; приоритет при перегрузке не меняется и остаётся «сдвиговым» — выше сравнений, ниже [[Арифметические операторы|арифметики]]. Поэтому `std::cout << a & b;` разбирается как `(std::cout << a) & b` и обычно просто не компилируется; нужно `std::cout << (a & b);`.
- **Не путать с [[Логические операторы|логическими]]** `&&`, `||`, `!`: те работают с истинностью целиком и вычисляются по сокращённой схеме, битовые — поразрядно и вычисляют оба операнда.
- Битовые операторы работают со **значением**, а не с байтами в памяти, поэтому `x & 0xFF` даёт младший байт числа при любом [[Порядок байтов|порядке байтов]].
- **Альтернативные лексемы:** `compl` (`~`), `bitand` (`&`), `bitor` (`|`), `xor` (`^`), а также `and_eq`, `or_eq`, `xor_eq`. Готовые инструменты: [[std-bitset|std::bitset]] — набор битов фиксированной длины с выводом нулями и единицами; заголовочный файл `<bit>` (C++20) — `std::popcount`, `std::has_single_bit`, `std::rotl`, `std::countl_zero`, `std::bit_width`; [[Битовые поля]] — поля структуры заданной ширины в битах.
- **На практике:** флаги и права доступа (одно число — набор «галочек»), упаковка значений в одно слово (цвет RGB), сетевые протоколы и форматы файлов, хеш-функции, быстрая проверка чётности `x & 1`. Работать следует над беззнаковыми типами фиксированной ширины (`std::uint32_t`): это снимает и вопрос знакового расширения при продвижениях, и вопрос сдвига отрицательных значений.

## Пример

```cpp
#include <bit>
#include <bitset>
#include <iostream>

int main() {
    constexpr unsigned READ = 1u << 0, WRITE = 1u << 1, EXEC = 1u << 2;  // флаги — отдельные биты
    unsigned flags = 0;
    flags |= READ | EXEC;                       // установить биты:  101
    flags &= ~EXEC;                             // сбросить бит:     001
    flags ^= WRITE;                             // переключить бит:  011
    std::cout << std::bitset<3>(flags) << ' ' << ((flags & WRITE) != 0) << '\n';  // выведет: 011 1

    std::cout << (0b1100u & 0b1010u) << ' ' << (0b1100u | 0b1010u) << ' '
              << (0b1100u ^ 0b1010u) << '\n';   // выведет: 8 14 6

    std::cout << (-7 >> 1) << ' ' << (-7 / 2) << '\n';   // выведет: -4 -3
    std::cout << (-1 << 1) << '\n';                      // выведет: -2 (в C++20 определено, раньше UB)

    unsigned char m = 0x0F;
    std::cout << ~m << ' ' << +static_cast<unsigned char>(~m) << '\n';   // выведет: -16 240
    std::cout << std::popcount(0b1011u) << '\n';         // выведет: 3 (C++20, <bit>)
    // std::cout << (1 << 32);   // UB: сдвиг на ширину типа или больше
}
```

Блок с `flags` — типичная работа с флагами: каждое право занимает свой бит одного числа, и скобки в `(flags & WRITE) != 0` обязательны. Строка с `-7` показывает, что сдвиг вправо и деление — разные операции: `-7 >> 1` равно `-4` (округление к минус бесконечности), а `-7 / 2` равно `-3` (округление к нулю). Унарный `+` перед `static_cast` нужен, чтобы однобайтовое значение печаталось числом, а не символом.

## Ловушки на экзамене

- **«Чему равно `2 ^ 3`?»** — `1`, а не `8`: `^` — исключающее ИЛИ (`10 ^ 11` даёт `01`). Возведения в степень среди операторов C++ нет; g++ 13 даже предупреждает об этой ошибке для литералов (`-Wxor-used-as-pow`).
- **«Почему `if (x & 1 == 0)` не срабатывает для чётных чисел?»** — из-за приоритета: `==` выполняется раньше `&`, получается `x & 0`, то есть всегда `0`. Правильно — `(x & 1) == 0`.
- **«Чему равно `1 << 32` для 32-битного `int`?»** — это UB, а не нуль: правый операнд обязан быть меньше ширины продвинутого типа левого. Компилятор вправе выдать что угодно, в том числе выбросить фрагмент кода; для сдвига на 32 и больше нужен более широкий тип — `1ull << 32`.
- **«Правда ли, что `x >> 1` — это деление на 2?»** — только для неотрицательных значений. Для отрицательных в C++20 сдвиг округляет к минус бесконечности, а деление — к нулю: `-7 >> 1` равно `-4`, `-7 / 2` равно `-3`.
- **«Что изменилось в битовых операциях в C++20?»** — сдвиг влево отрицательного значения перестал быть UB (определён через арифметику по модулю), правый сдвиг знакового определён как арифметический (раньше implementation-defined), а представление знаковых типов зафиксировано как дополнительный код.
- **«Чему равно `~0u` и `~static_cast<unsigned char>(0)`?»** — `UINT_MAX` типа `unsigned` и `-1` типа `int`: во втором случае срабатывает продвижение до `int`, и результат становится знаковым.
- **«Чем `~` отличается от `!`?»** — `~5` инвертирует все биты и даёт `-6`; `!5` — логическое отрицание и даёт `false`.
- **«Как битовыми операторами проверить чётность и «степень двойки»?»** — `x & 1` равно `1` у нечётных; для беззнакового `x` условие `x != 0 && (x & (x - 1)) == 0` истинно ровно для степеней двойки (`x & (x - 1)` сбрасывает младший единичный бит).
- **«Почему `std::cout << a & b` работает не так, как ожидается?»** — приоритет `<<` выше приоритета `&`, поэтому выражение разбирается как `(std::cout << a) & b`. Нужны скобки.

## Связанные термины

- [[Оператор]] — общее понятие, группой которого являются битовые операторы.
- [[Целый тип]] — единственно допустимый (вместе с неограниченным перечислением) тип операнда.
- [[Логические операторы]] — `&&`, `||`, `!`, которые путают с `&`, `|`, `~`.
- [[Неявные преобразования типов]] — продвижения, из-за которых `~` над `unsigned char` даёт `int`.
- [[Приоритеты операторов]] — объясняет обязательные скобки вокруг битовых выражений.
- [[Операторы ввода и вывода]] — те же лексемы `<<` и `>>` с совершенно иной семантикой.
- [[std-bitset]] — типобезопасная альтернатива ручным маскам.
- [[Битовые поля]] — хранение нескольких малых значений в одном объекте средствами языка.

## Протокол спора

> [!quote]- Как рождалось определение
> **Версия A (Формалист):** «Битовые операторы (*bitwise operators*) — группа операторов, которые рассматривают целочисленный операнд как последовательность бит его двоичного представления и вычисляют результат поразрядно либо сдвигом разрядов: унарное дополнение `~`, бинарные `&` (И), `|` (ИЛИ), `^` (исключающее ИЛИ) и сдвиги `<<`, `>>`. Операнды должны иметь целочисленный тип или тип неограниченного перечисления; результат — prvalue.»
>
> **Версия Б (Педагог-практик):** «Битовые (побитовые) операторы (*bitwise operators*) — операторы, обрабатывающие целочисленные операнды как последовательности двоичных разрядов (битов): `~` инвертирует каждый бит, `&`, `|` и `^` выполняют И, ИЛИ и исключающее ИЛИ над каждой парой соответствующих битов двух операндов, а `<<` и `>>` сдвигают биты влево и вправо на заданное число позиций.»
>
> **Спорные пункты:**
> 1. Что писать в определении — перечень знаков с названиями операций (A) или перечень с действиями каждого оператора (Б). → **Решение:** взято определение Б: из него сразу понятно, что делает каждый оператор, и это именно то, что требуется произнести на экзамене. Из A сохранены род «группа операторов», слова «его представления» и «поразрядно либо сдвигом разрядов», а требование к типу операнда и «prvalue» убраны из определения в примечания (регламент запрещает оговорки внутри определения).
> 2. Преобразования операндов. A: к `&`, `|`, `^` — продвижения и обычные арифметические преобразования, к сдвигам — только продвижения, к каждому операнду отдельно, поэтому тип результата сдвига задаёт левый операнд. Б: просто «работает повышение маленьких типов до `int`». → **Решение:** принято A: это точнее и объясняет, почему `1u << 3` и `1 << 3` имеют разные типы. Пример Б с `~` от `unsigned char` оставлен как иллюстрация.
> 3. Что именно изменилось в C++20. Б: «знаковые обязаны храниться в дополнительном коде, и сдвиги для них определены». A: то же плюс точная формулировка `a << b` через конгруэнтность по модулю `2^N` и `a >> b` как округление к минус бесконечности. → **Решение:** взята версия A с формулой; добавлено уточнение, что до C++20 правый сдвиг отрицательных был implementation-defined, а левый — UB (у Б это сказано верно, у A — только про левый). Совет «работать с беззнаковыми» сохранён от обеих сторон.
> 4. Формулировка «сдвиги — это умножение и деление на степень двойки» (Б) как общее правило. → **Решение:** сужена арбитром: для знаковых с переполнением `<<` — не умножение, а арифметика по модулю `2^N`, поэтому в итоге сказано «для неотрицательных значений». Возражение A здесь справедливо.
> 5. «На x86 `1 << 32` часто даёт 1, потому что процессор берёт сдвиг по модулю 32» (Б). → **Решение:** из итога убрано. Утверждение про конкретную архитектуру верно лишь для сдвига на переменную величину во время выполнения; в статье про UB полезнее правило «результат может быть любым», и оно оставлено вместе с советом Б про `1ull << 32`.
> 6. Приоритет сдвигов относительно `+` и `-` (`1 << n + 1`) и рецепты работы с битом `k`, аналогия «маска-трафарет» — только у Б; `<bit>`, альтернативные лексемы, `std::uint32_t` — только у A. → **Решение:** объединено: рецепты и приоритет от Б, список функций `<bit>` и альтернативные лексемы от A. Аналогия с трафаретом убрана как не соответствующая справочному стилю.
>
> **Итог:** определение — Б, с родом и уточнениями A. От A взяты: раздельные правила преобразований для сдвигов и для `&`/`|`/`^`, формула сдвига влево в C++20, округление `>>` к минус бесконечности, `[basic.fundamental]` про дополнительный код, `<bit>` и альтернативные лексемы, ловушки `~0u`, `1 << 32`, `x >> 1` против `x / 2`. От Б: само определение, правила для одного бита, четыре рецепта работы с битом, составные формы как присваивания, приоритет сдвигов ниже `+`, независимость от порядка байтов, пример с правами доступа и `std::bitset`, ловушки `x & 1 == 0`, `~` против `!`, проверка степени двойки, предупреждение `-Wxor-used-as-pow`. Арбитр проверил компилятором: `-Wxor-used-as-pow` в g++ 13 действительно существует и срабатывает на `2 ^ 3`; итоговый пример выводит `011 1`, `8 14 6`, `-4 -3`, `-2`, `-16 240`, `3` без предупреждений с `-std=c++20 -Wall -Wextra -pedantic` (в частности, `-1 << 1` в режиме C++20 уже не диагностируется). Утверждение Б про поведение x86 при `1 << 32` и слишком широкая формулировка «сдвиг — это умножение» исправлены арбитром.
