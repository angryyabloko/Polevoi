# Определение

> [!abstract] Определение
> **Определение** (*definition*) — [[Объявление|объявление]], которое вдобавок полностью задаёт обозначаемую им сущность: для [[Переменная|переменной]] создаёт [[Объект|объект]] и выделяет под него память, для [[Функция|функции]] задаёт её тело, для [[Класс и экземпляр|класса]] или [[Перечисление|перечисления]] — состав его членов. Всякое определение является объявлением, но не всякое объявление — определением.

## Примечания и тонкости

- Формальный критерий задан «от противного» ([basic.def]): объявление **является** определением, если только оно не одно из перечисленных исключений — объявление функции без тела (`int f(int);`); объявление со спецификатором `extern` без инициализатора (`extern int n;`); объявление класса без тела (`class Widget;`); непрозрачное объявление перечисления (`enum class E : int;`); объявление статического члена данных внутри класса **без `inline` и без `constexpr`**; `typedef` и alias-declaration ([[Псевдоним типа|псевдонимы типов]]); using-declaration и using-directive; объявление параметра функции; параметр шаблона; `static_assert`; объявление-атрибут; пустое объявление `;`; guide-объявление для вывода аргументов шаблона. Перечень важно знать целиком: определение «от противного» без него не является определением.
- Правило одного определения (*one definition rule*, ODR, [basic.def.odr]): в одной единице трансляции не может быть более одного определения любой переменной, функции, класса, перечисления или шаблона; во всей программе должно быть **ровно одно** определение каждой не-`inline` функции и переменной, которая фактически используется (*odr-used*).
- Классы, `inline`-функции и переменные, шаблоны и перечисления допускают по одному определению в **каждой** единице трансляции, но все эти определения обязаны быть лексически идентичными и означать одно и то же. Нарушение — *ill-formed, no diagnostic required*: ни компилятор, ни компоновщик не обязаны его замечать, и программа может собраться, а затем вести себя непредсказуемо. Это не UB и не «ошибка компиляции», а отдельная категория, и называть её следует именно так.
- Память выделяет только определение объекта. Определение класса задаёт тип — «чертёж», и памяти под него не выделяется, пока не создан объект этого класса. Нестатический член данных в определении класса — **не** определение переменной: в `struct S { int x, y; };` определений переменных ноль, память под `x` и `y` появляется при создании объекта.
- [[Статический член класса|Статическому члену данных]] требуется отдельное определение вне класса (`int S::count = 0;`), кроме членов, объявленных `inline` или `constexpr`: с C++17 `constexpr` подразумевает `inline`, и объявление в классе само является определением. Проверено: `struct S { static constexpr int limit = 100; };` с обращением по ссылке линкуется при `-std=c++20`, но даёт `undefined reference` при `-std=c++14`.
- Определение — это не [[Инициализация|инициализация]]: `int x;` внутри функции есть полноценное определение (память выделена), но значение переменной неопределённое. В области видимости пространства имён такой объект размещается в [[Статическая память|статической памяти]] и получает значение 0. UB даёт преобразование неопределённого значения в значение (lvalue→rvalue), из чего есть узкое исключение для `unsigned char` и `std::byte`; в C++26 этот случай переведён в категорию «ошибочного поведения» (*erroneous behavior*).
- `extern int n = 5;` — определение, а не объявление: наличие инициализатора перекрывает `extern`.
- Для функций определением является не только тело `{…}`, но и `= default`, и `= delete`. Метод, определённый прямо в теле класса, неявно `inline`, поэтому его можно держать в [[Заголовочный файл|заголовочном файле]].
- Определение обязательно там, где требуется полный тип или код сущности: создание объекта, `sizeof`, доступ к члену, наследование, фактический вызов функции. Для всего остального хватает объявления. Отсюда распределение: в заголовке — объявления функций и переменных, определения классов, `inline`-функций и шаблонов; в `.cpp` — определения обычных функций и переменных уровня пространства имён.
- **На практике:** по тексту сообщения видно, чего не хватает. `was not declared in this scope` (компилятор) — нет объявления; `redefinition of` (компилятор) — два определения в одной единице трансляции; `undefined reference to` (компоновщик) — объявление есть, определения нет ни в одной единице трансляции; `multiple definition of` (компоновщик) — определений больше одного. Последние два выдаёт компоновщик, а не компилятор, и искать их причину в синтаксисе бессмысленно — см. [[Раздельная компиляция]] и [[Связывание]].

## Пример

```cpp
#include <iostream>

struct Counter {                        // определение класса: тип задан, память не выделена
    static int total;                   // объявление статического члена, НЕ определение
    static constexpr int limit = 100;   // constexpr ⇒ неявно inline: это уже определение
    int v;                              // член данных объявлен, но это не определение переменной
    int get() const;                    // объявление метода
};

int Counter::total = 0;                 // определение статического члена
int Counter::get() const { return v; }  // определение метода

void log_message();                     // объявление; определения нигде нет

int main() {
    Counter c{5};            // определение переменной: объект создан
    Counter::total += c.get();
    int x;                   // определение без инициализации: значение неопределённое
    x = Counter::total;
    // log_message();        // ошибка компоновщика: undefined reference to `log_message()'
    std::cout << x << ' ' << Counter::limit << '\n';   // выведет: 5 100
}
```

Строка `static int total;` внутри класса — объявление: без `int Counter::total = 0;` вне класса программа не скомпонуется, а `static constexpr int limit = 100;` в отдельном определении не нуждается. Объявление `log_message` без определения безвредно, пока функцию не вызывают: ошибку выдаст только компоновщик и только при использовании.

## Ловушки на экзамене

- **«Является ли `int x;` объявлением?»** — да. Это определение, а любое определение есть объявление; ответ «нет, это определение» — ошибка логики, а не терминологии.
- **«`extern int x = 1;` — объявление или определение?»** — определение: наличие инициализатора делает объявление определением, несмотря на `extern`. GCC при этом предупреждает `'x' initialized and declared 'extern'`.
- **«Выделяет ли память `struct Point { int x, y; };`?»** — нет, это определение **типа**; память появится только при определении объекта `Point p;`. Определений переменных в этой строке ноль.
- **«`typedef int Id;` — это определение типа?»** — нет, несмотря на название (*type definition*): это объявление синонима существующего типа, новый тип не создаётся, и определением такое объявление не является.
- **«Класс с `static int count;` компилируется, но компоновщик пишет `undefined reference to S::count`. Почему?»** — внутри класса это лишь объявление. Нужно определение вне класса (`int S::count = 0;`) или, начиная с C++17, `inline static int count = 0;`; `static constexpr` член в отдельном определении не нуждается.
- **«Почему определение класса в заголовочном файле не вызывает `multiple definition`, а определение функции — вызывает?»** — ODR разрешает определять класс в каждой единице трансляции (при идентичности определений), а не-`inline` функцию — нет. Лечится словом `inline` или выносом определения в `.cpp`.
- **«Сколько определений переменной допустимо в программе?»** — для используемой не-`inline` переменной ровно одно во всей программе и не более одного в каждой единице трансляции. Для `inline`-переменной — по одному в каждой единице трансляции, и все они должны быть идентичны.

## Связанные термины

- [[Объявление]] — род, к которому определение относится: определение есть объявление с дополнительным свойством.
- [[Инициализация]] — задание начального значения; определение переменной его не гарантирует.
- [[Переменная]] — сущность, для которой определение создаёт объект и выделяет память.
- [[Функция]] — её определение содержит тело.
- [[Класс и экземпляр]] — определение класса задаёт тип, но не создаёт объектов.
- [[Статический член класса]] — классический случай, когда объявление и определение разнесены.
- [[Раздельная компиляция]] — контекст, в котором ODR вообще имеет смысл.
- [[Заголовочный файл]] — место, где неосторожное определение чаще всего нарушает ODR.

## Протокол спора

> [!quote]- Как рождалось определение
> **Версия A (Формалист):** «Определение (*definition*) — объявление, которое полностью задаёт объявляемую сущность: для переменной выделяет под неё память, для функции задаёт тело, для класса или перечисления — состав его членов. Каждое определение является объявлением, но не каждое объявление — определением.»
>
> **Версия Б (Педагог-практик):** «Определение (*definition*) — объявление, которое не только вводит имя, но и полностью задаёт обозначаемую им сущность: для переменной — создаёт объект (выделяет под него память), для функции — задаёт её тело, для класса — перечисляет его члены. Всякое определение является объявлением, но не наоборот.»
>
> **Спорные пункты:**
> 1. Условие для статического члена данных. A: оговорка «без `inline`» неполна — с C++17 `static constexpr` член неявно `inline`, и его объявление в классе уже является определением, поэтому правильно «без `inline` и без `constexpr`». Б: «объявление статического члена данных внутри класса (без `inline`)». → **Решение:** прав A. Проверено: `struct S { static constexpr int limit = 100; }; const int& r = S::limit;` линкуется при `-std=c++20` и даёт `undefined reference to 'S::limit'` при `-std=c++14`. В учебном коде `static constexpr` встречается чаще всего, так что пропуск существенный.
> 2. Полнота перечня исключений из [basic.def]. A: перечень должен быть полным, у Б он назван «главные из них» и пропускает непрозрачное объявление перечисления, параметр шаблона, объявление-атрибут, пустое объявление и guide-объявление. → **Решение:** прав A: для понятия, определяемого «от противного», неполный перечень означает неполное определение. Взят полный список.
> 3. Название категории ODR-нарушения. A: это *ill-formed, no diagnostic required*, и категорию надо назвать. Б: описывает её верно («компилятор не обязан это диагностировать»), но без названия, а в статье «Идентификатор» для похожего случая употребляет «UB». → **Решение:** прав A; единая терминология по регламенту обязательна, категория названа явно, а слово UB из этого пункта убрано.
> 4. Нестатический член данных. A: это не определение переменной, память появляется при создании объекта; прямой вопрос — «сколько определений переменных в `struct S { int x, y; };`» (ответ: ноль). Б: говорит только «определение класса задаёт тип — чертёж». → **Решение:** взято у A, граница проведена отдельным пунктом и продублирована в ловушке.
> 5. «Чтение неопределённого значения — UB» (так у Б). → **Решение:** уточнено: UB даёт преобразование lvalue→rvalue над неопределённым значением, и для `unsigned char` и `std::byte` есть узкое исключение. Слово «чтение» для первого курса приемлемо, но в примечании формулировка дана точно.
> 6. Определение ≠ инициализация. A: это отдельный тезис: `int x;` внутри функции — полноценное определение, но значения нет. Б: тезис спрятан внутрь пункта про `int x;`. → **Решение:** выделено отдельным пунктом со ссылкой на термин «Инициализация».
> 7. Лишнее. A: ловушка «Чем объявление отличается от определения?» — не ловушка, а пересказ обоих определений, и она полностью дублирует статью «Объявление»; упоминание C++26 — шум; «GCC при этом предупреждает» про `extern int n = 5;` — деталь реализации внутри пункта о стандарте. → **Решение:** ловушка-пересказ убрана; предупреждение GCC перенесено в соответствующую ловушку (проверено, оно выдаётся даже без `-Wall`); упоминание C++26 («ошибочное поведение») оставлено одной оговоркой — оно фактически верно и объясняет, куда движется стандарт, но вынесено в конец пункта.
>
> **Итог:** определение — в редакции Б (она явно называет создание объекта и «вводит имя», что точнее формулировки A), с терминологией A. От Б взяты целиком: пункт «На практике» с разбором четырёх сообщений об ошибках — самый полезный фрагмент обеих версий партии, ловушка про `typedef int Id;`, уточнение «`= default` и `= delete` — это определения», распределение «где что размещать» и структура примера (класс, статический член, объявление функции без определения, ошибка только у компоновщика). От A взяты: полный перечень исключений из [basic.def] с верной оговоркой «без `inline` и без `constexpr`», название категории IFNDR, термин *odr-use*, тезисы «нестатический член данных — не определение переменной» и «определение ≠ инициализация», ловушка «является ли `int x;` объявлением». Арбитр соединил примеры обеих сторон в один (в нём теперь показаны и `static int total;`, и `static constexpr int limit`, чего не хватало обоим) и уточнил формулировку про чтение неопределённого значения.
