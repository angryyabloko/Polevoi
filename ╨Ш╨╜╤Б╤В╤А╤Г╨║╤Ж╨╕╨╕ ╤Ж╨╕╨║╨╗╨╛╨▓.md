# Инструкции циклов

> [!abstract] Определение
> **Инструкции циклов** (*iteration statements*) — категория [[Инструкции управления|инструкций управления]], которые многократно выполняют подчинённую им инструкцию — тело цикла — пока истинно условие продолжения. В C++20 их ровно четыре формы: `while`, `do`-`while`, `for` и `for` по диапазону (*range-based for*).

## Примечания и тонкости

- **Четыре формы и момент проверки условия:**
    - `while (условие) тело` — цикл с **предусловием**: условие проверяется *перед* каждой итерацией, поэтому тело может не выполниться ни разу;
    - `do тело while (условие);` — цикл с **постусловием**: условие проверяется *после* итерации, поэтому тело выполняется хотя бы один раз; точка с запятой после `)` обязательна, так как это инструкция-выражение в составе `do`-`while`;
    - `for (инициализация; условие; приращение) тело` — тот же цикл с предусловием, но всё управление счётчиком собрано в заголовке;
    - `for (объявление : диапазон) тело` — `for` по диапазону (C++11): перебирает элементы [[Встроенный массив|встроенного массива]], контейнера, списка в фигурных скобках.
- **Итерация** — одно выполнение тела. Тело — ровно **одна** инструкция; чтобы выполнять несколько действий, её заменяют составной инструкцией в фигурных скобках.
- **Условие** — [[Выражение|выражение]], значение которого преобразуется к [[Логический тип|bool]] (ненулевое число и ненулевой указатель — истина). В `while` и `for` условием может быть также объявление с инициализатором: `while (int c = next())` — проверяется значение введённой переменной. У `do`-`while` условие — только выражение, и переменные, объявленные в теле, в нём уже не видны.
- **Пустая инструкция как тело** — классическая опечатка: в `while (i < n);` телом стала `;`, а следующая строка в цикл не попала. Важное практическое различие: g++ 13.3 с `-Wall` выдаёт на `for (i = 0; i < 3; ++i); { … }` предупреждение `this 'for' clause does not guard... [-Wmisleading-indentation]`, а на `while (i < n);` не выдаёт **ничего** ([[Предупреждения компилятора]]) — эту ошибку приходится искать глазами.
- **Опущенные части `for`.** Любую из трёх частей заголовка можно опустить (обе `;` остаются); пропущенное условие считается равным `true`, поэтому `for (;;)` — [[Бесконечный цикл|бесконечный цикл]].
- **`for` сводится к `while`:** `for (init; cond; step) body` работает как `{ init; while (cond) { body; step; } }`. Отличий два: `continue` в `for` переходит к выражению приращения (в таком `while` он бы его перепрыгнул), и имя из инициализирующей части видно только внутри инструкции `for`.
- **[[Область видимости|Области видимости]] в `for`.** Инициализирующая часть и условие принадлежат области видимости, объемлющей тело; само тело — вложенная область, поэтому объявленное в теле имя затеняет одноимённое из заголовка (компилятор сообщит об этом только с `-Wshadow`). После цикла имя из заголовка недоступно.
- **Развёртывание `for` по диапазону.** Компилятор превращает его в обычный цикл: `auto&& __range = выражение-диапазон;`, затем `__begin` и `__end` из `begin`/`end` (члены диапазона либо функции, найденные поиском, зависящим от аргументов), затем `for (; __begin != __end; ++__begin)`. Отсюда два следствия: диапазону достаточно пары [[Итератор|итераторов]] — контейнером быть не обязательно, а конец диапазона вычисляется **один раз**, до первой итерации.
- **Переменная цикла в `for` по диапазону — копия элемента:** `for (auto x : v)` изменяет копию. Чтобы менять элементы, нужна ссылка `auto&`, чтобы не копировать крупные объекты — `const auto&`.
- **Изменения по версиям.** В C++20 у `for` по диапазону появилась инициализирующая часть: `for (auto n = v.size(); int x : v)`. До C++23 продлевался срок жизни только самого результата выражения-диапазона, а временные объекты внутри него разрушались до начала цикла, из-за чего `for (int x : make().items())` работал с уже уничтоженным объектом; в C++23 (P2718R0) продление распространено на все временные объекты выражения-диапазона.
- **Инструкции перехода в цикле.** `break` покидает ближайшую охватывающую инструкцию цикла или `switch` ([[Инструкции выбора|инструкцию выбора]]); `continue` переходит к следующей итерации — в `for` при этом вычисляется выражение приращения, в `while` и `do`-`while` управление идёт сразу к проверке условия. Из двух вложенных циклов `break` выводит только из внутреннего.
- **Терминологическая ловушка.** В старой русской литературе *statement* переводили словом «оператор», отсюда «оператор цикла», «оператор `for`». В справочнике [[Оператор|оператор]] — это только *operator* (`+`, `<`, `=`), а `for` и `while` — инструкции.
- **На практике:** обход контейнера — `for (const auto& x : c)`; индексный `for` — когда нужен сам номер элемента; `while` — когда число итераций заранее неизвестно (чтение до конца ввода, итерационный метод до точности ε); `do`-`while` — когда тело обязано выполниться хотя бы раз («запрашивать ввод, пока он некорректен»). Многие ручные циклы (поиск, подсчёт, сортировка) заменяются [[Алгоритмы стандартной библиотеки|алгоритмами стандартной библиотеки]].

## Пример

```cpp
#include <iostream>
#include <vector>

int main() {
    // while — проверка условия ДО тела: тело может не выполниться ни разу
    int number = 2026, digits = 0;
    while (number != 0) {
        number /= 10;
        ++digits;
    }
    std::cout << "digits = " << digits << '\n';        // выведет: digits = 4

    // do-while — проверка ПОСЛЕ тела: тело выполняется хотя бы один раз
    int k = 0;
    do {
        std::cout << "do: " << k << '\n';              // выведет: do: 0
    } while (k > 0);

    // for — то же предусловие, но управление счётчиком собрано в заголовке
    int sum = 0;
    for (int i = 1; i <= 10; ++i) {
        if (i % 2 == 0) continue;   // к выражению-приращению ++i, затем к условию
        if (i > 7) break;           // выход из цикла
        sum += i;                   // 1 + 3 + 5 + 7
    }
    std::cout << "sum = " << sum << '\n';              // выведет: sum = 16
    // std::cout << i;              // ошибка: i видна только внутри инструкции for

    // for по диапазону: переменная цикла — копия элемента, если не взять ссылку
    std::vector<int> v{1, 2, 3};
    for (int& x : v) x *= 10;                          // меняются сами элементы
    for (int x : v) std::cout << x << ' ';             // выведет: 10 20 30
    std::cout << '\n';
}
```

Тело `do`-`while` выполнилось, хотя условие `k > 0` ложно с самого начала: `while` с тем же условием не выполнил бы тело ни разу. В последней паре циклов разница только в `&`: без ссылки вектор остался бы прежним.

## Ловушки на экзамене

- **Сколько видов инструкций циклов в C++?** — Ровно четыре: `while`, `do`-`while`, `for`, `for` по диапазону. Повторение через `goto` или [[Рекурсия|рекурсию]] даёт тот же эффект, но инструкцией цикла не является.
- **Чем `while` отличается от `do`-`while`?** — Моментом проверки условия: `while` проверяет его до тела, поэтому тело может не выполниться ни разу; `do`-`while` — после, поэтому тело выполняется минимум один раз. Ответ «это одно и то же, просто разная запись» — ошибка.
- **Является ли `for` оператором?** — Нет: `for` — инструкция (*statement*). Оператор (*operator*) — знак операции, у него есть операнды и значение; у `for` нет ни того, ни другого.
- **`int i; for (i = 0; i < 3; ++i); { std::cout << i; }` — что выведется?** — `3`, один раз. Точка с запятой после `)` — пустая инструкция, она и есть тело цикла; блок в фигурных скобках — отдельная инструкция, выполняемая один раз после цикла.
- **`for (auto x : v) x = 0;` обнулит вектор?** — Нет: `x` — копия элемента, обнуляется копия. Нужно `for (auto& x : v) x = 0;`.
- **Какова область видимости `i` в `for (int i = 0; i < n; ++i)`?** — От объявления до конца всей инструкции `for`; после цикла имя недоступно. Внутри тела можно объявить своё `i` — оно затенит внешнее.
- **Можно ли внутри `for` по диапазону делать `v.push_back(...)`?** — Нет: при перевыделении памяти итераторы, по которым идёт развёрнутый цикл, становятся недействительными, дальнейшая работа с ними — неопределённое поведение. Это ошибка времени выполнения, а не компиляции (см. [[Валидность итераторов]]).
- **Куда переходит `continue` в `for`, а куда в `while`?** — В `for` — к выражению приращения, затем к условию; в `while` — сразу к условию. Поэтому `while` с `++i` в конце тела и `continue` в середине зацикливается, а аналогичный `for` — нет.
- **`i++` или `++i` в заголовке `for` — есть разница?** — Для `int` результат одинаков: значение выражения приращения отбрасывается, важен только побочный эффект. Для итераторов и других классов префиксная форма может быть дешевле — постфиксной нужно вернуть копию старого значения (см. [[Инкремент и декремент]]).

## Связанные термины

- [[Инструкции управления]] — родовое понятие: циклы — одна из трёх категорий управляющих инструкций.
- [[Инструкции выбора]] — соседняя категория; разделяет с циклами правило «условие может быть объявлением», и в ней тоже работает `break`.
- [[Бесконечный цикл]] — предельный случай: условие продолжения никогда не становится ложным.
- [[Итератор]] — то, через что определён `for` по диапазону.
- [[Валидность итераторов]] — почему изменение контейнера внутри цикла по диапазону опасно.
- [[Область видимости]] — где видны переменные заголовка и тела цикла.
- [[Инкремент и декремент]] — типичное выражение приращения цикла `for`.
- [[Алгоритмы стандартной библиотеки]] — готовые замены типовых ручных циклов.

## Протокол спора

> [!quote]- Как рождалось определение
> **Версия A (Формалист):** «Инструкции циклов (*iteration statements*) — разновидность инструкций управления, которая задаёт многократное выполнение подчинённой инструкции — тела цикла — в зависимости от условия продолжения. В C++20 их четыре вида: `while`, `do`-`while`, `for` и `for` по диапазону (*range-based for*).»
>
> **Версия Б (Педагог-практик):** «Инструкции циклов (*iteration statements*) — инструкции управления, которые многократно выполняют вложенную инструкцию — тело цикла — пока истинно условие продолжения (`while`, `do`-`while`, `for`) либо по одному разу для каждого элемента диапазона (диапазонный `for`).»
>
> **Спорные пункты:**
> 1. Нужно ли в определении выделять `for` по диапазону как форму «без условия». Б разделяет: «пока истинно условие» для трёх форм и «по одному разу для каждого элемента» для диапазонного. A подводит все четыре под одно условие продолжения. → **Решение:** принята формулировка A. `for` по диапазону определён стандартом через развёртывание в обычный `for` с условием `__begin != __end`, то есть условие продолжения у него есть; разделение Б создаёт ложное впечатление, будто это конструкция другого рода. Механика развёртывания вынесена в примечания.
> 2. Название четвёртой формы. A: «`for` по диапазону». Б: «диапазонный `for`». → **Решение:** «`for` по диапазону» — калька ближе к *range-based for* и не выглядит как самостоятельный вид инструкции; английский термин дан в скобках.
> 3. Предупреждение на пустую инструкцию как тело. A утверждает только, что это «классическая ошибка». Б утверждает, что g++ с `-Wall` предупреждает (`-Wmisleading-indentation`). → **Решение:** прав Б, и проверка уточнила границу: g++ 13.3 выдаёт `-Wmisleading-indentation` на `for (i = 0; i < 3; ++i); { … }`, но на `while (i < n);` не выдаёт **ничего**. Оба факта внесены в примечания: практически важно именно то, что для `while` предупреждения нет.
> 4. Как объяснять `for` через `while`. Только у Б: `for (init; cond; step) body` ≡ `{ init; while (cond) { body; step; } }`, отличие — поведение `continue`. → **Решение:** принято: это самый короткий способ объяснить, почему `continue` в `for` не пропускает приращение. Добавлено второе отличие, которого у Б нет, — область видимости имени из заголовка.
> 5. Области видимости внутри `for`. A точнее: инициализирующая часть и условие — в области, объемлющей тело; тело — вложенная область, поэтому имя можно затенить. Б говорит лишь «переменная существует только внутри цикла». → **Решение:** взята формулировка A, к ней добавлено замечание Б про невидимость переменных тела в условии `do`-`while`.
> 6. Копия или ссылка в `for` по диапазону. Только у Б: `auto x` — копия, `auto&` — для изменения, `const auto&` — чтобы не копировать. У A этого нет вовсе, хотя это самая частая практическая ошибка студентов. → **Решение:** принято и вынесено отдельным пунктом, в пример добавлена демонстрация `for (int& x : v) x *= 10;`.
> 7. Изменения в C++23. A: продление срока жизни распространено на все временные объекты выражения-диапазона (P2718R0). Б описывает то же без номера предложения. → **Решение:** взята версия A с номером предложения и с указанием, что именно продлевалось раньше.
> 8. Наполнение примера. A даёт четыре формы, дающие один и тот же обход вектора. Б даёт четыре содержательно разные задачи (подсчёт цифр, `do`-`while` с ложным условием, `continue`/`break`, изменение через ссылку). → **Решение:** взят пример Б: одинаковый обход у A не показывает, зачем нужны разные формы, тогда как у Б каждая форма стоит на своём месте. Комментарии уточнены, вывод проверен запуском (`digits = 4`, `do: 0`, `sum = 16`, `10 20 30`).
>
> **Итог:** определение — A (с правкой названия формы). От A взяты: развёртывание `for` по диапазону и два следствия из него (достаточно пары итераторов, `end` вычисляется однократно), точное описание областей видимости, P2718R0, инициализирующая часть `for` по диапазону из C++20, ловушки про «оператор цикла» и про область видимости `i`. От Б взяты: разбор четырёх форм по моменту проверки условия, понятие итерации, «копия против ссылки», сведение `for` к `while`, практические рекомендации по выбору формы, пример и ловушки про `while`/`do`-`while`, про `x = 0` в цикле по диапазону и про `continue`. Арбитр проверил компилятором утверждение о предупреждениях на пустое тело (предупреждение есть для `for`, нет для `while`) и запустил итоговый пример.
