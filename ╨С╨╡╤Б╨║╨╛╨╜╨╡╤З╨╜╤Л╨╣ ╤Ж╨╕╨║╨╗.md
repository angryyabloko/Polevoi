# Бесконечный цикл

> [!abstract] Определение
> **Бесконечный цикл** (*infinite loop*) — [[Инструкции циклов|инструкция цикла]], условие продолжения которой никогда не становится ложным, так что управление покидает её только изнутри тела — инструкцией перехода (`break`, `return`, `goto`) или выбрасыванием исключения, — либо не покидает вовсе.

## Примечания и тонкости

- **Канонические записи:** `for (;;)`, `while (true)`, `do … while (true);`. Они равносильны: у `for` пропущенное условие считается равным `true`, поэтому `for (;;)` — единственная форма, не содержащая условия вообще. А `while ()` с пустыми скобками — синтаксическая ошибка: в `while` условие обязательно.
- **Преднамеренный и случайный.** Преднамеренный бесконечный цикл — законный и распространённый приём, когда условие выхода удобнее проверять в середине тела: цикл обработки событий в играх и графическом интерфейсе, сервер в ожидании запросов, меню «пока не выбран выход», главный цикл прошивки микроконтроллера (обычно прямо в [[Функция main|функции main]]). Ошибкой является только «зависание» — случай, когда условие **должно было** стать ложным, но не становится.
- **Типичные причины случайного бесконечного цикла:**
    - забыто изменение переменной условия (`while (i < n) { … }` без `++i`) или изменяется не та переменная (`++j` вместо `++i`);
    - условие не может стать ложным по свойствам типа: `unsigned i` и условие `i >= 0`; знаковый `char c` и условие `c < 200` при максимуме `127` (см. [[Диапазоны арифметических типов]]);
    - счётчик [[Вещественный тип|вещественного типа]] сравнивается на точное равенство: `for (double x = 0.0; x != 1.0; x += 0.1)` — значение `0.1` не представимо точно в двоичной арифметике, накопленная сумма «проскакивает» `1.0`; спасает сравнение `<` ([[Операторы сравнения]]) или счёт в целых числах;
    - точка с запятой после заголовка: `while (i < n); { ++i; }` — тело пустое, `i` не меняется;
    - присваивание вместо сравнения: `while (x = 1)` истинно всегда (см. [[Оператор присваивания]]);
    - «обёртывание» беззнакового счётчика за границу диапазона, из-за которого условие с `!=` перескакивается;
    - `continue`, проскакивающий приращение в `while`.
- **Гарантия прогресса** (*forward progress*) — формальная тонкость, о которой стоит знать. Раздел `[intro.progress]` C++20 разрешает реализации предполагать, что каждый поток в конце концов сделает одно из четырёх: завершится, вызовет функцию ввода-вывода стандартной библиотеки, обратится к объекту через `volatile`-glvalue или выполнит синхронизирующую либо атомарную операцию. Цикл, который ничего из этого не делает и не завершается, по букве C++20 — **неопределённое поведение** (UB), и оптимизатор вправе его удалить или «выполнить» код после него. Поэтому `while (true) { std::cout << '.'; }` безопасен при любом прочтении стандарта; для пустого тела это правило позже отменили задним числом — см. следующий пункт.
- **Послабление уже действует задним числом.** Предложение P2809R3 («тривиальные бесконечные циклы не являются неопределённым поведением»), принятое в **C++26**, оформлено как **дефект-репорт и применено к C++11** и всем последующим редакциям, включая C++20. *Тривиальным* считается цикл, условие которого есть константное выражение, равное `true` (или опущено), а тело — пустая инструкция `;` либо пустой блок `{ }`; его тело считается заменённым на вызов `std::this_thread::yield`. Так что `for (;;);` и `while (true) {}` корректны, а `for (;;) { int x; }` — нет: объявление делает тело нетривиальным. Практический вывод для первокурсника: **пустой вечный цикл «ни о чём» писать не надо**, но и бояться его не стоит — ни GCC, ни Clang, ни MSVC такой цикл не выбрасывают.
- **Цикл с нетривиальным условием под послабление не попадает.** Например, `for (unsigned i = 1; i != 10; i += 2) { }` вечен (счётчик всегда нечётен), но его условие — не константное выражение `true`, так что поведение остаётся неопределённым. Именно поэтому осознанный вечный цикл пишут как `for (;;)` или `while (true)`, а не маскируют под обычный счётный цикл.
- **Выход из цикла.** `break` завершает только ближайшую охватывающую инструкцию цикла или `switch`; `return` завершает всю функцию, включая все объемлющие циклы; `throw` передаёт управление обработчику ([[Обработка исключений]]); `goto` переводит управление на метку в той же функции — все это [[Инструкции управления|инструкции управления]] и выражения, а не средства самого цикла. Возврат из цикла в `main` через `break`/`return` штатно завершает программу, а `std::exit` и особенно `std::abort` — нет: `abort` не уничтожает объекты со статическим временем жизни и не сбрасывает буферы потоков.
- **Как остановить зависшую программу.** В терминале — Ctrl+C, в среде разработки — кнопка Stop. Продуктивнее прервать её под [[Отладчик|отладчиком]] (в GDB тоже Ctrl+C) и посмотреть стек вызовов: сразу видно, в каком именно цикле программа «застряла».
- **На практике:** `while (std::cin >> x)` — не бесконечный цикл, а цикл с условием, которое становится ложным при ошибке или конце ввода. Осознанный бесконечный цикл пишут как `for (;;)` с явным `break`, чтобы условие выхода было видно в теле; у такого цикла должен быть либо легко находимый выход, либо осознанное решение «работать, пока процесс не остановят извне».

## Пример

```cpp
#include <iostream>

int main() {
    // Гипотеза Коллатца: число шагов до 1 заранее неизвестно, поэтому
    // условие выхода удобнее проверять в середине тела.
    long long n = 27;
    int steps = 0;
    for (;;) {                       // условие опущено — считается равным true
        if (n == 1) break;           // единственный выход из цикла
        n = (n % 2 == 0) ? n / 2 : 3 * n + 1;
        ++steps;
    }
    std::cout << "steps = " << steps << '\n';   // выведет: steps = 111

    // Непреднамеренные бесконечные циклы (раскомментировать нельзя — зациклятся):
    // for (unsigned i = 5; i >= 0; --i) { }    // i >= 0 всегда истинно для unsigned
    // for (double x = 0.0; x != 1.0; x += 0.1) { }  // 0.1 не представимо точно
    // int i = 0; while (i < 3); { ++i; }       // тело цикла — пустая инструкция ';'
}
```

Первый цикл — преднамеренный бесконечный: условия в заголовке нет, выход один и явно выделен `break`; выполнится он всего 111 раз. Первую из закомментированных строк g++ с `-Wextra` диагностирует: `comparison of unsigned expression in '>= 0' is always true [-Wtype-limits]`; про две остальные компилятор молчит.

## Ловушки на экзамене

- **Бесконечный цикл — это всегда ошибка?** — Нет. «Бесконечность» относится к условию в заголовке, а не к реальному времени работы: `for (;;)` с `break` внутри может выполнить три итерации. Ошибка — только цикл, который не должен был стать бесконечным.
- **Чем `for (;;)` отличается от `while (true)`?** — Семантически ничем: в обоих случаях условие равно `true`. Разница историческая — некоторые компиляторы выдавали предупреждение о константном условии на `while (true)`, но не на `for (;;)`.
- **Можно ли написать `while () { … }` по аналогии с `for (;;)`?** — Нет, ошибка компиляции: опускать условие разрешено только в `for`; в `while` пишут `while (true)`.
- **Сколько раз выполнится `for (unsigned i = 5; i >= 0; --i)`?** — Бесконечно: беззнаковое значение всегда `>= 0`, а декремент нуля даёт максимум типа (беззнаковая арифметика идёт по модулю `2^N`). g++ ловит это предупреждением `-Wtype-limits` из набора `-Wextra` ([[Предупреждения компилятора]]).
- **`for (int i = 0; i < 10; i--)` — бесконечный цикл?** — Формально нет: `i` убывает до минимума `int`, и следующий декремент — переполнение знакового целого, то есть UB. Программа может зациклиться, завершиться или повести себя как угодно иначе — предсказуемого ответа нет.
- **Верно ли, что `while (true) { }` — неопределённое поведение, а `while (true) { std::cout << '.'; }` — нет?** — Так было по букве C++20, и рассуждение здесь такое: вызов функции ввода-вывода стандартной библиотеки входит в список действий из `[intro.progress]`, при наличии которых реализация не вправе предполагать завершение потока; пустое тело такого действия не содержит. Уточнение для строгого ответа: предложение P2809R3 применено как дефект-репорт к C++11 и далее, поэтому *тривиальные* вечные циклы (`for (;;);`, `while (true) {}`) сегодня считаются корректными — а вот `for (unsigned i = 1; i != 10; i += 2) {}` остаётся UB, так как его условие не константа `true`.
- **`break` внутри двух вложенных циклов — откуда он выйдет?** — Только из ближайшей охватывающей инструкции цикла или `switch`. Для выхода сразу из нескольких уровней нужен флаг, `goto` на метку после циклов или вынесение циклов в функцию и `return`.
- **Чем `break` отличается от `return` при выходе из бесконечного цикла?** — `break` завершает только цикл, и функция продолжает работу после него; `return` завершает функцию целиком, а из `main` — и всю программу.

## Связанные термины

- [[Инструкции циклов]] — родовое понятие; бесконечным может стать любая из четырёх форм.
- [[Инструкции управления]] — `break`, `return`, `goto` как способы покинуть цикл.
- [[Диапазоны арифметических типов]] — «обёртывание» беззнакового счётчика как причина незавершения.
- [[Вещественный тип]] — почему сравнение дробного счётчика на равенство делает цикл вечным.
- [[Предупреждения компилятора]] — ловят часть случайных бесконечных циклов (`-Wtype-limits`).
- [[Отладчик]] — позволяет найти, где именно зависла программа.
- [[Функция main]] — штатное место главного бесконечного цикла программы.
- [[Обработка исключений]] — `throw` как ещё один способ прервать бесконечный цикл.

## Протокол спора

> [!quote]- Как рождалось определение
> **Версия A (Формалист):** «Бесконечный цикл (*infinite loop*) — инструкция цикла, условие продолжения которой никогда не становится ложным, так что управление покидает её только инструкцией передачи управления изнутри тела (`break`, `return`, `goto`), выбрасыванием исключения или завершением программы, а иначе не покидает вовсе.»
>
> **Версия Б (Педагог-практик):** «Бесконечный цикл (*infinite loop*) — цикл, условие продолжения которого никогда не становится ложным, поэтому он завершается только досрочным выходом из тела (`break`, `return`, выброс исключения, завершение программы) либо не завершается вообще.»
>
> **Спорные пункты:**
> 1. Род в определении. Б: «цикл». A: «инструкция цикла». → **Решение:** взято A: «цикл» — разговорное слово, а термин реестра — «инструкции циклов»; видовое отличие при этом у обеих сторон одинаково.
> 2. Включать ли «завершение программы» в список способов выхода. Оба включают. → **Решение:** убрано из определения. `std::exit` или `std::abort` не «покидают цикл», а уничтожают весь контекст выполнения; упоминание этого в определении смешивает уровни. Разница между `return` и `abort` вынесена в примечания.
> 3. **Формальный статус `while (true) { }` в C++20 — главное разногласие.** A: это UB по `[intro.progress]`, причём «P2809R3 — не дефект-репорт, в C++20 и C++23 поведение остаётся неопределённым». Б: UB в C++20, «в C++26 перестали быть UB». → **Решение:** **A ошибся в проверяемом факте.** По таблице дефект-репортов cppreference P2809R3 применён к **C++11** и всем последующим редакциям — то есть задним числом и к C++20 тоже. Б ближе к истине по существу, но его «в C++26» тоже неточно. В статье даны оба слоя: буква C++20 (UB, с перечислением четырёх действий из `[intro.progress]`) и действующее задним числом послабление. Заодно исправлено описание самого послабления: A писал, что тело не должно содержать вызовов функций, `volatile`-доступов и синхронизации, тогда как в действительности тело должно быть *пустым* (пустая инструкция или блок из пустых инструкций) — пример `for (;;) { int x; }` уже не тривиален и остаётся UB. Описание «тело заменяется вызовом `std::this_thread::yield`» у A верно и сохранено.
> 4. Как подать этот сюжет первокурснику. A излагает его как полноценную тонкость стандарта с номерами предложений. Б — одной фразой «может повести себя странно». → **Решение:** компромисс. Пункт примечаний оставлен подробным (сильный студент должен уметь ответить), но завершается практическим выводом: пустой вечный цикл писать не надо, однако бояться его не стоит — ни один из трёх основных компиляторов его не выбрасывает. В ловушке на экзамене дан короткий ответ с уточнением «для строгого ответа», чтобы вопрос не превращался в запугивание.
> 5. Нетривиальный вечный цикл. Только у A: `for (unsigned i = 1; i != 10; i += 2)` остаётся UB, так как условие не является константным выражением `true`. → **Решение:** принято — это и есть содержательная граница послабления, и именно она объясняет, зачем писать `for (;;)` явно. Проверено: на этот цикл g++ 13.3 с `-Wall -Wextra -pedantic` никаких предупреждений не выдаёт.
> 6. Перечень причин случайного зацикливания. У Б он лучше структурирован (забытый шаг, свойства типа, вещественный счётчик, лишняя `;`, `=` вместо `==`), у A добавлены две причины: обёртывание беззнакового счётчика мимо условия `!=` и `continue`, проскакивающий приращение. → **Решение:** взят список Б, дополненный двумя пунктами A.
> 7. Пример. A: чтение чисел с `break` по концу ввода. Б: гипотеза Коллатца с `break` по достижении цели. → **Решение:** взят пример Б — он детерминирован, не требует ввода и даёт проверяемый вывод (`steps = 111`, проверено запуском). Закомментированные «вечные» циклы взяты от обоих авторов; указано, что предупреждение выдаётся только на беззнаковый счётчик.
> 8. Утверждение Б про `-Wtype-limits`. → **Решение:** проверено компилятором и подтверждено: g++ 13.3 на `for (unsigned i = 5; i >= 0; --i)` печатает `comparison of unsigned expression in '>= 0' is always true [-Wtype-limits]`. Б процитировал ключ верно.
>
> **Итог:** определение — A, с удалением «завершения программы» из перечня. От A взяты: перечень четырёх действий из `[intro.progress]`, нетривиальный вечный цикл как не попадающий под послабление, замена тела на `std::this_thread::yield`, разница `return`/`std::abort`, замечание про `while (std::cin >> x)`, ловушки про `for (;;)` против `while (true)` и про `break` в двух циклах. От Б взяты: деление на преднамеренный и случайный, структурированный перечень причин, `while ()` как синтаксическая ошибка, остановка зависшей программы (Ctrl+C, Stop, пауза в отладчике), пример, ловушки про `unsigned i >= 0`, про `i--` и про `break` против `return`. Арбитр исправил фактическую ошибку A о статусе P2809R3 (это дефект-репорт, применённый к C++11 и далее) и его же неточное описание того, какое тело делает цикл тривиальным.
