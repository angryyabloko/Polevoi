# Инструкции выбора

> [!abstract] Определение
> **Инструкции выбора** (*selection statements*) — [[Инструкции управления|инструкции управления]], которые в зависимости от значения условия выполняют одну из своих подынструкций либо не выполняют ни одной. В C++ их два вида: инструкция `if` — по результату контекстного преобразования условия к `bool`, и инструкция `switch` — по совпадению значения условия целочисленного или перечислимого типа с константой одной из меток `case`.

## Примечания и тонкости

- **Формы (C++20):** `if (условие) S1`, `if (условие) S1 else S2`, `if constexpr (условие) …` (C++17), `switch (условие) S`. С C++17 `if` и `switch` допускают инструкцию инициализации: `if (init; условие)`, `switch (init; условие)`. В C++23 добавлена форма `if consteval`.
- **Условие** — это [[Выражение|выражение]] или объявление одной [[Переменная|переменной]] с инициализатором (`if (int* p = find())`). Имя, введённое в условии или в инструкции инициализации, видно в обеих ветвях, включая `else`, не попадает в объемлющую [[Область видимости|область видимости]] и уничтожается в конце всей инструкции. Это удобно для результата функции, нужного только внутри ветвления.
- **Контекстное преобразование к `bool`** допускает и `explicit operator bool` ([[Оператор приведения к типу]]): `if (n)` для целого `n` означает `n != 0`, `if (p)` для указателя — `p != nullptr` ([[Логический тип]]).
- **Подынструкция — ровно одна инструкция,** поэтому на практике почти всегда ставят блок `{…}`. Без скобок подынструкция всё равно образует собственную область видимости: в `if (c) int x = 1;` переменная `x` не видна после инструкции `if`.
- **Висячий `else`** (*dangling else*): `else` относится к ближайшему предшествующему `if`, у которого ещё нет своего `else`, независимо от отступов. Фигурные скобки снимают двусмысленность, а g++ предупреждает о вводящем в заблуждение отступе (`-Wmisleading-indentation`).
- **Условие `switch`** должно иметь целочисленный или перечислимый тип либо тип класса с однозначным [[Неявные преобразования типов|неявным преобразованием]] к такому типу; к нему применяются целочисленные продвижения. Метки `case` — константные выражения, преобразуемые к типу условия, и все различные; метка `default` — не более одной и в любом месте тела, но обязательной она не является. Вещественные типы ([[Вещественный тип]]) и строки ([[std-string|std::string]], C-строки) в качестве условия недопустимы: g++ сообщает `switch quantity not an integer`. Для строк используют каскад `if` или словарь.
- **Метки — только точки входа, а не границы ветвей.** После перехода на метку выполнение продолжается последовательно через следующие метки («проваливание», *fallthrough*) до `break` или конца тела. Намеренное проваливание с C++17 помечают атрибутом `[[fallthrough]];`, непомеченное g++ отмечает предупреждением `-Wimplicit-fallthrough` (входит в `-Wextra`, см. [[Предупреждения компилятора]]).
- **Тело `switch` — произвольная инструкция;** метки `case` могут находиться внутри вложенных блоков и даже циклов (приём «устройство Даффа»). Если ни одна метка не совпала и `default` отсутствует, не выполняется ничего.
- **Объявления внутри `switch`.** Переход к метке `case`, минующий объявление переменной с инициализацией в той же области видимости, — ошибка компиляции `jump to case label`; ветвь с объявлением заключают в `{…}`.
- **`if constexpr`**: условие — константное выражение типа `bool`, выбор происходит во время компиляции. В [[Шаблон функции|шаблоне]] отброшенная ветвь не инстанцируется, поэтому в ней допустим код, некорректный для данного типа; вне шаблона она всё равно должна быть корректной ([[constexpr]]). Этим `if constexpr` и отличается от обычного `if` с константным условием, который проверяет оба варианта и лишь затем, возможно, оптимизирует один.
- **Атрибуты `[[likely]]` и `[[unlikely]]`** (C++20) сообщают компилятору ожидаемую ветвь; на семантику программы не влияют.
- **Условный оператор `?:` — не инструкция выбора,** а [[Оператор|оператор]]: он образует выражение, имеющее значение и общий тип ветвей, и его ветви — выражения, а не инструкции. Поэтому `int x = c ? 1 : 2;` корректно, а `int x = if (c) 1; else 2;` не существует.
- **На практике:** `switch` по `enum class` без метки `default` в сочетании с `-Wswitch` (входит в `-Wall`) заставляет компилятор сообщать о каждом необработанном перечислителе после расширения [[Перечисление|перечисления]] — дешёвый способ не забыть ветвь.

## Пример

```cpp
#include <iostream>

void describe(int code) {
    if (int sq = code * code; sq > 10)   // C++17: инструкция инициализации в if
        std::cout << "big ";
    else if (sq == 0)                    // sq видна и в ветви else
        std::cout << "zero ";
    else
        std::cout << "small ";

    switch (code) {
    case 0: {                            // объявлению в ветви нужен свой блок {…}
        const char* msg = "none";
        std::cout << msg << '\n';
        break;                           // без break выполнение пошло бы дальше
    }
    case 1:
    case 2:                              // две метки — одна точка входа
        std::cout << "few ";
        [[fallthrough]];                 // намеренное «проваливание» (C++17)
    default:
        std::cout << "(end)\n";
    }
    // case 3: int t = 1; break;         // ошибка: jump to case label
}

int main() {
    describe(0);  // выведет: zero none
    describe(2);  // выведет: small few (end)
    describe(5);  // выведет: big (end)
}
```

Переменная `sq` объявлена в самой инструкции `if`, видна в обеих ветвях и после ветвления уже не существует. В `switch` метки `case 1` и `case 2` ведут к одному коду, а `[[fallthrough]]` показывает, что переход к `default` сделан намеренно.

## Ловушки на экзамене

- **Что делает `if (x = 5)`?** — Присваивает `x` значение 5 и всегда выполняет ветвь (5 преобразуется в `true`). Это не ошибка компиляции; g++ с `-Wall` предупреждает о присваивании в условии ([[Оператор присваивания]]).
- **Проверяет ли `if (0 < x < 10)` попадание в интервал?** — Нет: это `(0 < x) < 10`, и условие всегда истинно; нужно `0 < x && x < 10` ([[Логические операторы]]).
- **Почему блок после `if (x > 0);` выполняется всегда?** — Точка с запятой — пустая инструкция, она и есть подынструкция `if`; следующий блок — самостоятельная инструкция. g++ предупреждает `-Wempty-body`.
- **К какому `if` относится `else` в `if (a) if (b) f(); else g();`?** — К внутреннему `if (b)`: `else` связывается с ближайшим `if` без `else`, отступы на разбор не влияют. Чтобы отнести его к внешнему, внутренний `if` заключают в `{}`.
- **Зачем в `switch` нужен `break`?** — Метки `case` не ограничивают ветвь, а задают только точку входа: без `break` выполняется код этой и всех следующих меток до конца `switch`. Каскад `if … else if` так себя не ведёт.
- **Можно ли написать `switch` по `std::string` или `double`?** — Нет: условие должно быть целочисленного или перечислимого типа (или приводиться к нему), а метки — константными выражениями этого типа.
- **Почему не компилируется `case 1: int t = 1; break; case 2: …`?** — Переход к `case 2` минует инициализацию `t`, которая остаётся в области видимости; ветвь нужно заключить в `{}`.
- **`?:` — это инструкция выбора?** — Нет, это оператор: у него есть значение, и его можно поставить туда, где нужно значение, например в инициализатор. У `if` значения нет.

## Связанные термины

- [[Инструкции управления]] — родовое понятие: инструкции выбора — одна из трёх категорий.
- [[Инструкции циклов]] — другая категория; `break` действует и в циклах, и в `switch`.
- [[Логический тип]] — к нему контекстно преобразуется условие `if`.
- [[Перечисление]] — естественный тип условия `switch`.
- [[Логические операторы]] — из них строятся составные условия.
- [[Оператор присваивания]] — `if (x = 0)` вместо `if (x == 0)` — самая частая ошибка в условии.
- [[constexpr]] — основа `if constexpr` и требований к меткам `case`.
- [[Предупреждения компилятора]] — `-Wimplicit-fallthrough`, `-Wswitch`, `-Wparentheses`, `-Wempty-body`, `-Wmisleading-indentation`.

## Протокол спора

> [!quote]- Как рождалось определение
> **Версия A (Формалист):** «Инструкции выбора (*selection statements*) — инструкции управления, которые в зависимости от значения условия выполняют одну из своих подынструкций или ни одной: инструкция `if` — по результату контекстного преобразования условия к `bool`, инструкция `switch` — по совпадению значения условия целочисленного или перечислимого типа с константой одной из меток `case`.»
>
> **Версия Б (Педагог-практик):** «Инструкции выбора (*selection statements*) — инструкции управления, которые в зависимости от значения управляющего выражения выполняют одну из взаимоисключающих ветвей либо не выполняют ни одной. В C++ их две: `if` (в формах `if`, `if … else` и `if constexpr`) и `switch`.»
>
> **Спорные пункты:**
> 1. «Одну из взаимоисключающих ветвей» (Б) против «одну из своих подынструкций» (A). → **Решение:** формулировка A. Слово «ветвь» для `switch` неверно: метки `case` не ограничивают ветвей, и после выполнения кода одной метки управление идёт к следующей — это и есть проваливание, о котором сам Б пишет ниже. «Подынструкция» — точный термин и не создаёт ложного образа.
> 2. Называть ли в определении критерий выбора. A называет (преобразование к `bool` для `if`, совпадение с меткой для `switch`), Б — только перечисляет два вида. → **Решение:** взято у A: без критерия определение не отличает инструкции выбора от инструкций циклов, которые тоже «в зависимости от условия выполняют подынструкцию». Перечень форм `if` у Б перенесён в примечания как перечень-иллюстрация.
> 3. Допустимо ли объявление как подынструкция без скобок. A утверждает, что в `if (c) int x = 1;` переменная не видна после `if`, то есть запись законна. → **Решение:** A прав, проверено компиляцией g++ 13.3 с `-std=c++20 -Wall -Wextra -pedantic`: код принимается, выдаётся только `-Wunused-variable`. Примечание сохранено, к нему добавлено наблюдение Б о том, что подынструкция — ровно одна инструкция.
> 4. Полнота сведений о `switch`. У A есть целочисленные продвижения, ограничение «не более одной метки `default`», произвольная инструкция в качестве тела и «устройство Даффа»; у Б — указание, что `default` не обязателен, и практический совет для строк. → **Решение:** объединено. Сообщение компилятора на `switch (d)` для `double` сверено: `error: switch quantity not an integer`; ошибка на переход через инициализацию — `error: jump to case label`.
> 5. `if constexpr`. A: в шаблоне отброшенная ветвь не инстанцируется, вне шаблона всё равно должна быть корректной. Б: то же плюс сравнение с обычным `if` с константным условием. → **Решение:** взяты оба утверждения; важное уточнение A («вне шаблона ветвь должна быть корректной») сохранено, иначе из формулировки Б можно заключить, что `if constexpr` разрешает любой некорректный код.
> 6. C++23. Только у A: форма `if consteval`. → **Решение:** принято — регламент требует отмечать отличия C++23.
> 7. Наполнение примера. A показывает инструкцию инициализации, две метки с общей точкой входа и `[[fallthrough]]`; Б — блок `{…}` для объявления внутри `case` и `?:` внутри ветви. → **Решение:** взят пример A, в него добавлен блок с объявлением внутри `case 0` от Б и закомментированная строка `case 3: int t = 1;` с сообщением компилятора. Запись `[[fallthrough]]` перед `default` проверена компиляцией.
>
> **Итог:** определение — A целиком; перечень форм `if` вынесен в примечания. От A взяты: формы инструкций вместе с `if consteval` из C++23, правила для условия-объявления, контекстное преобразование к `bool` с `explicit operator bool`, область видимости подынструкции, полные требования к условию и меткам `switch`, «метки — точки входа, а не границы ветвей», произвольное тело `switch`, ошибка `jump to case label`, атрибуты `[[likely]]`/`[[unlikely]]`, совет про `-Wswitch` и `enum class`, ловушки про `if (x = 5)`, `if (x > 0);`, висячий `else`, `break` в `switch` и `case 1: int t = 1;`. От Б взяты: «подынструкция — ровно одна инструкция, поэтому ставят блок», `-Wmisleading-indentation`, практическая польза инструкции инициализации, необязательность `default`, сравнение `if constexpr` с обычным `if`, замена `switch` по строкам на каскад `if` или словарь, ловушки «`?:` — это инструкция выбора?» и «что выведет `switch`, если забыть `break`». Арбитр уточнил формулировку про подынструкции вместо «взаимоисключающих ветвей» и сверил с компилятором три спорных места: законность `if (c) int x = 1;`, сообщение для `switch` по `double` и допустимость `[[fallthrough]]` перед `default`.
