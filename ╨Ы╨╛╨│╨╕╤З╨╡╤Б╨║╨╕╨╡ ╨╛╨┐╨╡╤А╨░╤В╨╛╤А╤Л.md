# Логические операторы

> [!abstract] Определение
> **Логические операторы** (*logical operators*) — группа [[Оператор|операторов]] булевой алгебры над условиями: унарное отрицание `!` (НЕ) и бинарные `&&` (И, конъюнкция) и `||` (ИЛИ, дизъюнкция). Операнды приводятся к [[Логический тип|логическому типу]] `bool`, результат тоже имеет тип `bool`. Бинарные логические операторы вычисляются по сокращённой схеме: правый операнд вычисляется только в том случае, если значение левого не определяет результат целиком.

## Примечания и тонкости

- **Таблица истинности в одну строку:** `a && b` истинно, только когда истинны оба операнда; `a || b` ложно, только когда ложны оба; `!a` меняет истину на ложь и наоборот.
- **Что считается истиной.** Операнд *контекстно преобразуется* к `bool`, поэтому им может быть не только `bool`, но и число (ноль — ложь), [[Указатель|указатель]] ([[nullptr, NULL и 0|нулевой указатель]] — ложь) и объект класса с `explicit operator bool`. Поэтому `if (p)` и `if (p != nullptr)` эквивалентны, а `if (n)` читается «если `n` не ноль».
- **Сокращённое вычисление** (*short-circuit evaluation*) — не оптимизация, а **гарантия стандарта**: у `&&` при ложном левом операнде правый не вычисляется вовсе, у `||` — при истинном. Левый операнд вычисляется полностью, со всеми побочными эффектами, и секвенирован **перед** правым — это один из немногих гарантированных случаев [[Порядок вычисления выражений|порядка вычисления]] в C++.
- **Защитные условия.** На этой гарантии держатся идиомы `p != nullptr && p->value > 0`, `i < n && a[i] != 0`, `it != v.end() && *it == x`: вторая проверка выполняется лишь тогда, когда первая гарантирует её безопасность. Поменять операнды местами — значит получить разыменование нулевого указателя или выход за границы массива, то есть UB.
- **Приоритет.** `!` — унарный и связывает очень сильно, в частности сильнее сравнений: `!x == 5` — это `(!x) == 5`, то есть сравнение `0` или `1` с пятёркой. `&&` сильнее `||`: `a || b && c` — это `a || (b && c)` (g++ с `-Wall` советует поставить скобки). Оба слабее [[Операторы сравнения|сравнений]], поэтому `x > 0 && x < 10` пишется без скобок. См. [[Приоритеты операторов]].
- **Словесные формы.** `and`, `or`, `not` (а также `not_eq` для `!=`) — полноценные альтернативные лексемы языка, полностью эквивалентные `&&`, `||`, `!`; это не макросы, заголовочный файл не нужен.
- **Логического «исключающего ИЛИ» в языке нет.** Для операндов типа `bool` его роль играет `!=`: `a != b` истинно, когда истинно ровно одно из двух. Для произвольных значений — `!a != !b`.
- **Не путать с [[Битовые операторы|битовыми]] `&`, `|`, `~`.** Битовые работают поразрядно, дают число и **всегда вычисляют оба операнда**: `1 && 2` истинно, а `1 & 2` равно `0`; `!1` — это `false`, а `~1` — это `-2` (что в условии означает истину). Для операндов типа `bool` значения `&` и `&&` совпадают, а побочные эффекты — нет: `if (p && p->ok())` корректно, `if (p & p->ok())` — разыменование нулевого указателя.
- **Перегрузка ломает сокращённое вычисление.** `&&` и `||` можно [[Перегрузка операторов|перегрузить]], но у перегруженных версий вычисляются оба операнда: они становятся аргументами вызова функции. Сохраняется лишь порядок «левый перед правым» — с C++17 перегруженный оператор в операторной форме наследует правила секвенирования встроенного. Именно поэтому перегружать `&&` и `||` не рекомендуется: семантика выражения меняется незаметно для читателя.
- В C++20 `&&` и `||` внутри ограничений и *requires*-выражений образуют **конъюнкцию и дизъюнкцию ограничений** — это конструкции системы концептов, а не вызовы оператора, и правила их проверки иные.
- **На практике:** логические операторы — «клей» условий в [[Инструкции выбора|`if`]] и циклах. Проверки упорядочивают от безопасных и дешёвых к опасным и дорогим; замена `&&` на `&` в защитном условии превращает рабочий код в обращение по невалидному адресу.

## Пример

```cpp
#include <iostream>

bool trace(const char* name, bool value) {
    std::cout << '[' << name << "] ";          // видно, что функция действительно вызвана
    return value;
}

int main() {
    std::cout << std::boolalpha;
    std::cout << (trace("A", false) && trace("B", true)) << '\n';  // выведет: [A] false — B не вызывалась
    std::cout << (trace("C", true) || trace("D", false)) << '\n';  // выведет: [C] true  — D не вызывалась

    const int* p = nullptr;
    if (p != nullptr && *p > 0)                // правый операнд не вычисляется
        std::cout << "positive\n";
    // if (*p > 0 && p != nullptr) {}          // UB: сначала разыменовали нулевой указатель

    int x = 7;
    std::cout << (x > 0 && x < 10) << ' ' << !(x == 7) << ' ' << (not false) << '\n';
    // выведет: true false true
    std::cout << (1 && 2) << ' ' << (1 & 2) << '\n';  // выведет: true 0 — логическая операция против поразрядной
}
```

Функция `trace` печатает своё имя в момент вызова, поэтому по выводу видно, что `B` и `D` не вызывались: это и есть сокращённое вычисление. В последней строке `1 && 2` — значение типа `bool` (печатается как `true` из-за `std::boolalpha`), а `1 & 2` — число `0`.

## Ловушки на экзамене

- **«Будет ли вызвана `f()` в выражениях `false && f()` и `true || f()`?»** — нет, ни в одном: результат известен по левому операнду, и это гарантировано стандартом, а не зависит от оптимизации. Следствие: побочные эффекты в правом операнде (`if (ok && ++count > 3)`) происходят не всегда.
- **«Чем `&&` отличается от `&`?»** — `&&` логический: операнды приводятся к `bool`, результат `bool`, правый операнд может не вычисляться. `&` битовый: поразрядный, результат — целое, вычисляются оба операнда. Пример: `2 && 1` — `true`, а `2 & 1` — `0`.
- **«Когда истинно `if (x == 1 || 2)`?»** — всегда: это `(x == 1) || 2`, а число `2` превращается в `true`. Правильно — `x == 1 || x == 2`.
- **«Правда ли, что `!x == 5` — то же, что `x != 5`?»** — нет: `!` выполняется первым, и `(!x) == 5` сравнивает `0` или `1` с пятёркой, то есть всегда ложно.
- **«Сохранится ли сокращённое вычисление у перегруженного `operator&&`?»** — нет: операнды становятся аргументами функции и вычисляются оба. Гарантирован только порядок «левый перед правым».
- **«Какого типа результат `!x`?»** — всегда `bool`, независимо от типа операнда: `!5` равно `false`, а не `-6` (последнее — это `~5`).
- **«Как записать «истинно ровно одно из условий `a` и `b`»?»** — `a != b` для `bool`: отдельного оператора логического XOR в C++ нет.

## Связанные термины

- [[Оператор]] — общее понятие; логические операторы — его группа.
- [[Логический тип]] — тип результата и целевой тип контекстного преобразования операндов.
- [[Операторы сравнения]] — обычно поставляют операнды для `&&` и `||`.
- [[Битовые операторы]] — похожие по виду `&`, `|`, `~` с другим смыслом и без сокращённого вычисления.
- [[Порядок вычисления выражений]] — гарантия «левый перед правым» и пропуск правого операнда.
- [[Приоритеты операторов]] — `!` сильнее сравнений, `&&` сильнее `||`.
- [[Инструкции выбора]] — основной контекст составных условий.

## Протокол спора

> [!quote]- Как рождалось определение
> **Версия A (Формалист):** «Логические операторы (*logical operators*) — группа операторов, которые трактуют операнды как истину или ложь и дают prvalue типа `bool`: бинарные `&&` (конъюнкция) и `||` (дизъюнкция) и унарный `!` (отрицание). Операнды контекстно преобразуются к `bool`, а встроенные `&&` и `||` вычисляют правый операнд только в том случае, если значение левого не определяет результат целиком (короткое замыкание).»
>
> **Версия Б (Педагог-практик):** «Логические операторы (*logical operators*) — операторы булевой алгебры над условиями: унарное отрицание `!` (НЕ) и бинарные конъюнкция `&&` (И) и дизъюнкция `||` (ИЛИ); их операнды приводятся к типу `bool`, и результат тоже имеет тип `bool`. Бинарные логические операторы вычисляются по сокращённой схеме: сначала вычисляется левый операнд, а правый — только если результат ещё не определён левым.»
>
> **Спорные пункты:**
> 1. Разногласий по существу в этом термине почти нет: оба определения совпадают по роду, перечню и ключевому свойству. Расхождение только в терминах — «контекстное преобразование к `bool`» и «prvalue» у A против «приводятся к типу `bool`» у Б. → **Решение:** в определение взята формулировка Б как пригодная для устного ответа, а точный термин «контекстно преобразуется» вынесен в примечание, где он и раскрывается (число, указатель, `explicit operator bool`). «Prvalue» в этой статье ничего не добавляет.
> 2. Название свойства: «короткое замыкание» (A) против «сокращённое вычисление» (Б). → **Решение:** основным выбран перевод Б, английский термин *short-circuit evaluation* приведён рядом: на экзамене звучат оба.
> 3. Аналогии Б (охранник, который не спрашивает билет) и требование безличного стиля. → **Решение:** аналогия убрана, смысловая часть («левый операнд вычисляется полностью, со всеми побочными эффектами, раньше правого») сохранена: регламент требует справочного стиля без воды.
> 4. Приоритет `!` относительно сравнений (`!x == 5`). Есть только у Б. A ограничился тем, что унарные операторы старше бинарных. → **Решение:** принято у Б, это реальная ловушка; добавлено к пункту о приоритете.
> 5. Конъюнкция и дизъюнкция ограничений в C++20. Есть только у A. Б (за понятность) возразил бы, что первокурснику это лишнее. → **Решение:** оставлено одним коротким пунктом в конце: `&&` в `requires` действительно не является вызовом оператора, и знать, что это другая конструкция, полезно; разбор концептов отнесён к своему блоку.
> 6. Наследование правил секвенирования перегруженными операторами с C++17. Есть только у A. → **Решение:** принято: утверждение верно и важно именно в паре с потерей сокращённого вычисления — порядок сохраняется, пропуск операнда нет.
>
> **Итог:** определение — Б, с родом «группа операторов» от A и переносом «контекстного преобразования» в примечания. От A взяты: контекстное преобразование с перечнем допустимых операндов, статус гарантии стандарта (а не оптимизации), сохранение порядка «левый перед правым» у перегруженных операторов с C++17, конъюнкция ограничений в C++20, ловушка про тип результата `!x`. От Б: таблица истинности одной строкой, приоритет `!` против сравнений, `!a != !b` как общий XOR, противопоставление `~1` и `!1`, ловушки `if (x == 1 || 2)` и `!x == 5`, практический порядок проверок «от дешёвых к дорогим». Пример построен на функции-индикаторе A (она показывает невычисление правого операнда) с добавленной от Б последней строкой `1 && 2` против `1 & 2`; проверено компилятором: выводится `[A] false`, `[C] true`, `true false true`, `true 0`. Фактических ошибок ни у одной стороны нет.
