# Оператор «запятая»

> [!abstract] Определение
> **Оператор «запятая»** (*comma operator*) — бинарный [[Оператор|оператор]] `,`, который вычисляет левый операнд как выражение с отбрасываемым значением (*discarded-value expression*), а затем правый; тип, значение и категория значения всего [[Выражение|выражения]] совпадают с типом, значением и категорией значения правого операнда. Левый операнд со всеми своими побочными эффектами упорядочен до правого.

## Примечания и тонкости

- **Смысл оператора** — упорядоченно выполнить два действия там, где синтаксис допускает ровно одно выражение.
- **Наименьший приоритет из всех операторов**, ассоциативность слева направо: `a, b, c` ≡ `(a, b), c`, результат — `c`. Ниже присваивания, поэтому `x = 1, 2;` ≡ `(x = 1), 2;` ([[Приоритеты операторов]], [[Оператор присваивания]]).
- **Одна лексема — две роли.** На лексическом уровне `,` — знак пунктуации; оператором она является только там, где грамматика ожидает выражение. В списке аргументов вызова и параметров [[Функция|функции]], в списке инициализаторов `{1, 2, 3}`, в списке аргументов шаблона, между несколькими деклараторами одного [[Объявление|объявления]] (`int a = 1, b = 2;`), в списке захвата лямбды и в списке инициализации членов конструктора запятая — разделитель. Чтобы использовать там оператор, нужны скобки: `f((a, b))` передаёт **один** аргумент.
- **Гарантия порядка.** Встроенная запятая — один из немногих операторов, упорядочивающих левый операнд целиком до правого, поэтому `(i++, i)` корректно ([[Порядок вычисления выражений]]). Для запятой-разделителя такой гарантии нет: порядок вычисления аргументов вызова не уточнён.
- **Категория значения результата** совпадает с категорией правого операнда: если правый операнд — [[lvalue и rvalue|lvalue]], то `(a, b)` — тоже lvalue, и `(a, b) = 5` присваивает 5 переменной `b` (в языке C результат запятой — не lvalue).
- **Любой операнд может иметь тип `void`**: запись `(void)f(), x` корректна.
- **Перегрузка.** Запятую можно [[Перегрузка операторов|перегрузить]], но значение левого операнда тогда не отбрасывается, а передаётся аргументом функции. Порядок вычисления операндов с C++17 остаётся тем же, что у встроенного оператора (до C++17 перегруженная запятая была обычным вызовом функции без гарантии порядка). Перегружают её крайне редко; в обобщённом коде левый операнд приводят к `void` — `(void)a, b`, — чтобы гарантированно применялась встроенная запятая.
- **Запятая внутри `[]`.** `a[i, j]` — не двумерная индексация, а `a[j]` после вычисления `i`. С C++20 такая запись без скобок устарела (*deprecated*; g++ выдаёт `-Wcomma-subscript`), а в C++23 запятая в `[]` стала разделителем аргументов многомерного `operator[]` — для встроенного [[Встроенный массив|массива]] `a[i, j]` там уже ошибка. Запись `a[(i, j)]` остаётся допустимой всегда.
- **Отбрасываемое значение.** Если левый операнд не имеет побочных эффектов, его вычисление бессмысленно: g++ предупреждает `left operand of comma operator has no effect` (`-Wunused-value`, входит в `-Wall`) — например, на `int y = (1, 2);` ([[Предупреждения компилятора]]).
- **На практике:** оправданные применения — выражение приращения [[Инструкции циклов|цикла]] `for` с несколькими счётчиками (`++i, --j`) и свёртка пакета параметров шаблона `(f(args), ...)` (C++17). Гораздо чаще запятая-оператор встречается как ошибка: лишняя запятая вместо точки с запятой, десятичная запятая «по-русски» или попытка «вернуть два значения» через `return a, b;`.

## Пример

```cpp
#include <iostream>

int shout(int v) {
    std::cout << "eval" << v << ' ';
    return v;
}

int main() {
    int k = (shout(1), shout(2), 3);     // левые операнды вычисляются, значения отброшены
    std::cout << "k=" << k << '\n';      // выведет: eval1 eval2 k=3

    int a = 1, b = 2;                    // здесь запятая — разделитель деклараторов
    (++a, b) = 7;                        // результат — lvalue b, присваивается b
    std::cout << a << ' ' << b << '\n';  // выведет: 2 7

    for (int i = 0, j = 4; i < j; ++i, --j)  // «int i = 0, j = 4» — разделитель,
        std::cout << i << j << ' ';          // «++i, --j» — оператор «запятая»
    std::cout << '\n';                       // выведет: 04 13

    // int y = (1, 2);   // даёт 2, но левый операнд без эффекта: -Wunused-value
    // a = 1, 2;         // это (a = 1), 2;  a станет 1
    // double d = 3,14;  // ошибка: в объявлении запятая — разделитель деклараторов
}
```

Вызовы `shout(1)` и `shout(2)` происходят именно в этом порядке — левый операнд упорядочен до правого, — но их значения нигде не используются: значением всего выражения становится 3.

## Ловушки на экзамене

- **Чему равно `x` после `x = 1, 2;`?** — 1: присваивание связывается сильнее запятой, выражение равно `(x = 1), 2`, а значение 2 отбрасывается.
- **Чему равно `int y = (1, 2, 3);`?** — 3: каждый левый операнд вычисляется и отбрасывается, результат — самый правый операнд. Скобки обязательны, иначе запятая была бы разделителем деклараторов.
- **Сколько аргументов получит функция в `f(a, b)` и в `f((a, b))`?** — Два и один: в первом случае запятая — разделитель, во втором — оператор, и передаётся значение `b`. Если `f` принимает два параметра, второй вызов не скомпилируется.
- **Что вернёт `return a, b;`?** — Значение `b`. Вернуть два значения через запятую нельзя; нужны структура, `std::pair` или выходные параметры.
- **Что будет, если записать `double d = 3,14;`?** — Ошибка компиляции: в объявлении запятая разделяет деклараторы, а `14` не может быть именем переменной. Зато присваивание `d = 3,14;` скомпилируется и даст `d == 3` — ошибка останется незамеченной, если не смотреть на предупреждения.
- **Сколько раз оператор «запятая» встречается в `for (int i = 0, j = 5; i < j; ++i, --j)`?** — Один раз, в выражении приращения. В части инициализации это разделитель деклараторов одного объявления, и подменить его оператором нельзя.
- **Что означает `m[1, 2]` для `int m[3][4]`?** — Не элемент `m[1][2]`, а строку `m[2]`: сработал оператор «запятая». С C++20 такая запись устарела, а в C++23 для встроенного массива это ошибка.
- **Что проверяет `if (x > 0, y > 0)`?** — Только `y > 0`: значение левого операнда отбрасывается. Для конъюнкции нужен `&&` ([[Логические операторы]]).

## Связанные термины

- [[Оператор]] — родовое понятие; «запятая» как оператор, а не только знак пунктуации.
- [[Приоритеты операторов]] — у запятой наименьший приоритет, ниже присваивания; отсюда необходимость скобок.
- [[Порядок вычисления выражений]] — встроенная запятая гарантирует вычисление слева направо.
- [[Оператор присваивания]] — типичная путаница `x = 1, 2`.
- [[Инструкции циклов]] — основное практическое применение: несколько счётчиков в заголовке `for`.
- [[Перегрузка операторов]] — запятую можно перегрузить, но значение левого операнда тогда не отбрасывается.
- [[Предупреждения компилятора]] — `-Wunused-value`, `-Wcomma-subscript`.

## Протокол спора

> [!quote]- Как рождалось определение
> **Версия A (Формалист):** «Оператор «запятая» (*comma operator*) — бинарный оператор `,` с наименьшим приоритетом, который вычисляет сначала левый операнд как выражение с отбрасываемым значением (*discarded-value expression*), затем правый; результат имеет тип, значение и категорию значения правого операнда. Все вычисления значений и побочные эффекты левого операнда упорядочены до вычислений правого.»
>
> **Версия Б (Педагог-практик):** «Оператор «запятая» (*comma operator*) — бинарный оператор `,`, который вычисляет левый операнд, отбрасывает его результат, а затем вычисляет правый операнд; тип, значение и категория значения всего выражения совпадают с типом, значением и категорией значения правого операнда. Левый операнд вычисляется полностью, со всеми побочными эффектами, до начала вычисления правого.»
>
> **Спорные пункты:**
> 1. Расхождений в сути определения почти нет: обе версии называют одно и то же родовое понятие, один и тот же порядок и одно и то же правило о типе, значении и категории результата. → **Решение:** за основу взята редакция Б (она читается легче), но с термином A «выражение с отбрасываемым значением»: у Б «отбрасывает его результат» звучит как действие во время выполнения, тогда как речь о синтаксическом контексте, в котором значение не используется. Упоминание наименьшего приоритета убрано из определения в примечания как отдельное свойство.
> 2. Порядок вычисления операндов у перегруженной запятой. A: до C++17 гарантии не было, с C++17 порядок тот же, что у встроенного оператора. Б: «привычной семантики у перегруженной версии нет, это вызов функции, и оба операнда вычисляются всегда». → **Решение:** прав A. С C++17 перегруженный оператор в операторной записи наследует упорядочение встроенного (это то же правило, благодаря которому `std::cout << f() << g()` вызывает `f` первой, — и сам Б пишет о нём в статье «Порядок вычисления выражений»). Утверждение Б исправлено: у перегруженной запятой теряется не порядок, а отбрасывание значения левого операнда — оно передаётся аргументом.
> 3. Полнота перечня мест, где запятая — разделитель. У A шесть контекстов (включая список захвата лямбды и список инициализации членов конструктора), у Б — пять. → **Решение:** перечень A.
> 4. Судьба `a[i, j]` в C++23. A: запятая стала разделителем аргументов многомерного `operator[]`. Б: для встроенного массива это уже ошибка. → **Решение:** верны оба утверждения, они дополняют друг друга и объединены в одном пункте. Устаревание в C++20 подтверждено компиляцией: g++ 13.3 на `m[1, 2]` выдаёт `warning: top-level comma expression in array subscript is deprecated [-Wcomma-subscript]`.
> 5. Наполнение примера. A показывает `(++a, b) = 7` (категория значения результата) и `for` с двумя счётчиками; Б — цепочку с печатающей функцией, по которой видно фактический порядок вычислений. → **Решение:** взяты обе части. Пример Б `int y = (1, 2);` перенесён в комментарий: он вызывает `-Wunused-value` (проверено), а регламент допускает предупреждения в примере только тогда, когда пример посвящён именно им; сам факт предупреждения вынесен в примечание.
>
> **Итог:** определение — Б с терминологической правкой от A. От A взяты: полный перечень контекстов, где запятая — разделитель, возможность операнда типа `void`, правило для перегруженной запятой с C++17 (исправление ошибки Б), приём `(void)a, b` в обобщённом коде, сравнение с языком C по категории значения результата, упоминание свёртки пакета параметров, пример с `(++a, b) = 7` и ловушки про `x = 1, 2`, `double d = 3,14;` и `if (x > 0, y > 0)`. От Б взяты: формулировка определения, объяснение смысла оператора («выполнить два действия там, где допустимо одно выражение»), ловушки про `return a, b;`, про число аргументов в `f((a, b))` и про количество операторов-запятых в заголовке `for`, пример с печатающей функцией. Арбитр перенёс предупреждающую строку из кода в комментарий и свёл оба утверждения про C++23 в одно.
