# Константность

> [!abstract] Определение
> **Константность** (*constness*) — свойство [[Тип данных|типа]], задаваемое квалификатором `const` и означающее, что [[Объект|объект]] через имя, [[Левая ссылка|ссылку]] или [[Указатель|указатель]] такого типа можно только читать: любая попытка изменить его по такому пути доступа — ошибка компиляции.

## Примечания и тонкости

- **`const` — часть типа, а не свойство [[Переменная|переменной]] или значения.** `const int` и `int` — разные типы; `const int` и `int const` — один и тот же тип. Проверка выполняется компилятором и во время выполнения не стоит ничего. Второй cv-квалификатор — `volatile`.
- **Правило чтения:** `const` относится к тому, что стоит слева от него, а если слева ничего нет — к тому, что справа:
  - `const int* p` (то же, что `int const* p`) — указатель на константу: `*p` менять нельзя, сам `p` — можно;
  - `int* const p` — константный указатель: `p` менять нельзя, `*p` — можно;
  - `const int* const p` — нельзя ни то, ни другое.
  
  В литературе те же два случая называют константностью верхнего (*top-level*, константен сам объект) и нижнего (*low-level*, константен объект, к которому ведёт путь доступа) уровня; в стандарте этих терминов нет.
- **Константность пути доступа — не неизменность объекта.** `const int& r = x;` при неконстантном `x` запрещает менять `x` *через `r`*, но сам `x` может измениться, и `r` покажет новое значение (в примере `r` выводит 7).
- **Если const-квалифицирован тип самого объекта** (const-объект), то изменение его в течение времени жизни — неопределённое поведение (UB), даже если система типов обойдена. Стандарт определяет const-объект как объект типа `const T` или не-[[Ключевое слово mutable|mutable]]-подобъект const-объекта; поля, объявленные `mutable`, const-объектами не являются и изменяются даже у константного объекта.
- **Добавить `const` можно, убрать — нет.** `int*` неявно преобразуется в `const int*`, обратное преобразование компилятор запрещает: иначе через неконстантный указатель можно было бы испортить константу. Снять `const` явно позволяет [[Приведение типа const_cast|const_cast]], но запись через него корректна лишь тогда, когда сам объект константным не является.
- **Константа обязана быть [[Инициализация|инициализирована]]** — это единственный момент, когда ей можно дать значение. Исключение — класс, у которого инициализация по умолчанию действительно что-то инициализирует (есть пользовательский конструктор по умолчанию или инициализаторы полей).
- **`const` не означает «известно при компиляции».** `const int n = readNumber();` корректно: значение вычислится во время работы программы, но потом не изменится. Гарантию вычисления при компиляции даёт [[constexpr]]. Путаница возникает из-за того, что `const`-переменная целого типа или перечисления с константным инициализатором тоже годится там, где нужно константное выражение, — например как размер [[Встроенный массив|массива]].
- **Константные [[Метод|методы]]:** в `int get() const;` [[Ключевое слово this|this]] имеет тип `const T*`, поэтому у const-объекта можно вызвать только const-методы. В C++23 то же можно выразить явным объектным параметром: `void f(this const S& self);`.
- Верхний `const` параметра не входит в тип [[Функция|функции]]: `void f(int)` и `void f(const int)` объявляют одну и ту же функцию, [[Перегрузка функций|перегрузка]] по нему невозможна. Различие `T&` и `const T&` (как и `int*` и `const int*`) перегрузку различает.
- `auto` отбрасывает верхний `const`: при `const int c = 1;` объявление `auto a = c;` даёт `a` типа `int`.
- **`const` вместо `#define`:** в отличие от [[Макрос|макроса]], константа имеет тип, подчиняется [[Область видимости|областям видимости]] и видна в [[Отладчик|отладчике]].
- Константная переменная в области пространства имён по умолчанию имеет внутреннее [[Связывание|связывание]] (в языке C — внешнее), если не объявлена `extern` или `inline`; поэтому её можно определить в [[Заголовочный файл|заголовочном файле]] без ошибки повторного определения — в каждой единице трансляции ([[Раздельная компиляция]]) появится свой объект.
- Слово «константа» в русской литературе многозначно: const-объект, константное [[Выражение|выражение]] и литерал («целая константа `42`»). В стандарте это три разных понятия. Строковый литерал, кстати, имеет тип `const char[N]` ([[C-строки и строковые литералы]]), и попытка его изменить — UB.
- **На практике:** const-корректность (*const-correctness*) — дисциплина, при которой всё, что не должно меняться, помечается `const`: параметры «только для чтения» передают как `const T&` ([[Передача параметров и возврат значения]]), методы-наблюдатели помечают `const`. Сигнатура `void greet(const std::string&)` сразу сообщает, что функция аргумент не испортит, и компилятор это проверит.

## Пример

```cpp
#include <iostream>
#include <string>

struct Counter {
    int value = 0;
    int get() const { return value; }   // const-метод: this имеет тип const Counter*
    void inc() { ++value; }
};

void greet(const std::string& name) {   // обещание: функция не изменит name
    std::cout << "Hi, " << name << '\n';
    // name += "!";                     // ошибка: доступ только для чтения
}

int main() {
    const int maxScore = 100;
    // maxScore = 200;                  // ошибка: присваивание const-объекту
    int x = 1, y = 2;
    const int* p1 = &x;                 // указатель на const int
    // *p1 = 5;                         // ошибка
    p1 = &y;                            // сам указатель перенаправить можно
    int* const p2 = &x;                 // const-указатель
    *p2 = 5;                            // объект через него менять можно
    // p2 = &y;                         // ошибка
    // int* q = &maxScore;              // ошибка: const int* -> int* отбрасывает const
    const int& r = x;                   // путь доступа «только для чтения»
    x = 7;                              // сам x не const: меняется, и r это видит
    const Counter cnt{};
    // cnt.inc();                       // ошибка: неконстантный метод у const-объекта
    std::cout << maxScore << ' ' << *p1 << ' ' << r << ' ' << cnt.get() << '\n';
    // выведет: 100 2 7 0
    greet("Ann");                       // выведет: Hi, Ann
}
```

## Ловушки на экзамене

- **Чем отличаются `const int* p`, `int const* p` и `int* const p`?** — Первые два одинаковы: указатель на константный `int` (нельзя `*p = …`, можно `p = …`). Третий — константный указатель на изменяемый `int` (можно `*p = …`, нельзя `p = …`). Правило: `const` относится к тому, что слева от него.
- **Если есть `const int& r = x;`, может ли значение `r` измениться?** — Да, если `x` изменили напрямую: `const` у ссылки запрещает изменение только через `r`, но сам объект неизменным не делает.
- **Константа — это всегда значение, известное при компиляции?** — Нет: `const` означает «не изменяется после инициализации», а само значение может вычисляться во время работы программы. Константа времени компиляции — `constexpr`.
- **Что будет, если снять `const` через `const_cast` и изменить объект?** — Код скомпилируется. Если объект изначально объявлен `const` — это UB: компилятор вправе подставить значение константы по месту или разместить её в памяти только для чтения. Если же `const` была только у ссылки или указателя на неконстантный объект — изменение корректно.
- **Можно ли написать `int* q = &c;` при `const int c = 1;`?** — Нет: преобразование `const int*` в `int*` отбрасывает `const`, это ошибка компиляции. Обратное направление разрешено и неявно.
- **Почему у const-объекта нельзя вызвать неконстантный метод?** — В неконстантном методе `this` имеет тип `T*`, а для const-объекта `&obj` имеет тип `const T*`; неявного преобразования `const T*` в `T*` не существует.
- **Можно ли перегрузить `void f(int)` и `void f(const int)`?** — Нет: верхний `const` параметра не входит в тип функции, это одна и та же функция. А `f(int&)` и `f(const int&)` перегрузить можно.

## Связанные термины

- [[Тип данных]] — `const` является квалификатором в составе типа
- [[Инициализация]] — единственный момент, когда константе задают значение
- [[Указатель]] — указатель на константу и константный указатель
- [[Левая ссылка]] — `const T&` как путь доступа только для чтения
- [[constexpr]] — константы времени компиляции, в отличие от просто `const`
- [[Приведение типа const_cast]] — снятие константности и связанный с ним риск UB
- [[Метод]] — константные методы и тип `this` в них
- [[Ключевое слово mutable]] — исключение из константности для отдельного поля

## Протокол спора

> [!quote]- Как рождалось определение
> **Версия A (Формалист):** «Константность (*constness*) — свойство типа, задаваемое cv-квалификатором `const` и запрещающее модификацию объекта через выражение этого типа: такая попытка — ошибка компиляции. Если const-квалифицирован тип самого объекта (const-объект), любая попытка изменить его в течение времени жизни, в том числе в обход системы типов, — неопределённое поведение.»
>
> **Версия Б (Педагог-практик):** «Константность (*constness*) — свойство типа, задаваемое квалификатором `const` и означающее, что объект через имя, ссылку или указатель такого типа можно только читать, но не изменять; нарушение этого запрета обнаруживает компилятор.»
>
> **Спорные пункты:**
> 1. Второе предложение A целиком про UB. → **Решение:** убрано из определения в примечания. Регламент запрещает оговорки внутри определения, а устный ответ «константность — это свойство типа, и ещё бывает UB» создаёт впечатление, будто UB входит в понятие. Само утверждение верно и сохранено отдельным пунктом.
> 2. «Модификация через выражение этого типа» (A) против «через имя, ссылку или указатель» (Б). → **Решение:** формулировка Б: она точна и называет путь доступа теми словами, которые студент может повторить; термин «путь доступа» введён в этом же определении.
> 3. «Верхний / нижний уровень» (A) против правила «`const` относится к тому, что слева» (Б). → **Решение:** основой взято правило Б с тремя разобранными случаями, термины A сохранены как пара названий в том же пункте: они встречаются в учебниках, но в стандарте их нет, и сами по себе ничего не объясняют.
> 4. Внутреннее связывание const-переменной: A добавляет исключение для `inline`, у Б его нет. → **Решение:** прав A, и это проверено: объект, определённый как `const int vc = 1;` в заголовке, включённом в две единицы трансляции, в каждой из них свой (адреса различаются), а `inline const int vi = 2;` даёт один общий объект. Исключение для `inline` внесено в итог.
> 5. «Добавить `const` можно, убрать — нет» и сравнение `const` с `#define` — пункты Б, у A отсутствуют. → **Решение:** приняты оба: первый отвечает на частый вопрос про `int* q = &c;`, второй — на вопрос «почему `const` лучше макроса».
> 6. `const_cast` в примере. Б: пример A учит обходить `const` раньше, чем студент понял, зачем `const` нужен. → **Решение:** из примера `const_cast` убран (ловушка про него сохранена), вместо него добавлены самое частое применение `const` — параметр `const std::string&` — и запрещённое преобразование `const int*` в `int*`.
>
> **Итог:** определение — Б. От A взяты: стандартное определение const-объекта через не-`mutable`-подобъект, UB при изменении const-объекта, исключение для `inline` в правиле внутреннего связывания, `auto` отбрасывает верхний `const`, многозначность слова «константа» в русской литературе, тип строкового литерала, верхний `const` параметра и невозможность перегрузки по нему, C++23 (*deducing this*), ловушки про `this` у const-метода и про перегрузку. От Б: правило чтения `const` с тремя случаями, «проверяется компилятором и ничего не стоит при выполнении», «добавить можно — убрать нет», `const` против `#define`, параметр `const T&` в примере, ловушка `int* q = &c;`. Арбитр убрал `volatile` как самостоятельную тему (оставив одно упоминание), `consteval` и пункт про модули, а также удалил из версии Б утверждение «константа обязана быть инициализирована — это единственный момент», дополнив его случаем класса с конструктором по умолчанию.
