# Инициализация

> [!abstract] Определение
> **Инициализация** (*initialization*) — задание начального значения [[Объект|объекту]] (или привязка [[Левая ссылка|ссылки]] к объекту) в момент его создания, в отличие от [[Оператор присваивания|присваивания]], которое заменяет значение уже существующего объекта. Как именно инициализируется объект, определяет форма инициализатора, а при отсутствии инициализатора — правила инициализации по умолчанию.

## Примечания и тонкости

- **Знак `=` в объявлении — не [[Оператор|оператор]] присваивания**, а часть синтаксиса инициализатора. Для `int` разница незаметна, для классов принципиальна: при инициализации вызывается [[Конструктор|конструктор]], при присваивании — `operator=`. [[Константность|Константу]] и ссылку можно только инициализировать: присвоить им значение позже нельзя в принципе.
- **Формы инициализации** (для `int` все они, кроме последней, дают одно и то же; различаются правила):
  - `int a = 5;` — копирующая (*copy-initialization*): `explicit`-конструкторы не рассматриваются;
  - `int a(5);` — прямая (*direct-initialization*);
  - `int a{5};` и `int a = {5};` — списковая (*list-initialization*, C++11): запрещает сужающие преобразования и при наличии конструктора от `std::initializer_list` отдаёт предпочтение ему;
  - `int a{};` — инициализация значением (*value-initialization*): для встроенных типов даёт 0;
  - `int a;` — по умолчанию (*default-initialization*): для класса вызывается конструктор по умолчанию, а для скаляра с автоматической или динамической продолжительностью хранения не выполняется ничего.
- **Объект без инициализатора.** Локальная `int x;` в [[Стековая память|автоматической памяти]] содержит неопределённое (*indeterminate*) значение — «мусор»; его чтение — неопределённое поведение (UB). Глобальные и `static`-[[Переменная|переменные]] в [[Статическая память|статической памяти]] до всякой другой инициализации обнуляются (*zero-initialization*), поэтому `int g;` в примере равна 0.
- **Фигурные скобки защищают от сужения.** `int h = 3.7;` молча отбрасывает дробную часть ([[Неявные преобразования типов|неявное преобразование]]), а `int f{3.7};` — ошибка компиляции. Оговорка: сужение в списковой инициализации делает программу некорректной (*ill-formed*), но стандарт требует лишь диагностики, поэтому для неконстантного источника (`double d = 2.5; int n{d};`) g++ выдаёт только предупреждение `-Wnarrowing` — корректной программа от этого не становится.
- Правила инициализации (`[dcl.init]`) едины для всех контекстов: инициализация происходит не только в [[Объявление|объявлениях]], но и при передаче аргумента в параметр, и при возврате значения из функции ([[Передача параметров и возврат значения]]) — поэтому говорят, что параметр «инициализируется» аргументом.
- **Обязательная инициализация:** `const`-объект скалярного типа и ссылка без инициализатора не компилируются. Для класса `const`-объект без инициализатора допустим, только если инициализация по умолчанию действительно что-то инициализирует (есть пользовательский конструктор по умолчанию или инициализаторы полей).
- Для переменных статической продолжительности хранения различают статическую инициализацию (нулевую и константную — выполняется без исполнения кода программы) и динамическую (во время выполнения). Локальная [[Статическая переменная|статическая переменная]] инициализируется один раз — при первом прохождении управления через её объявление, потокобезопасно; при следующих вызовах объявление пропускается.
- **Составные объекты** инициализируют списком: [[Встроенный массив|массив]] — `int arr[3]{1, 2, 3};`, [[Структура|структуру]] — агрегатной инициализацией `Point p{1, 2};`; в C++20 добавлены назначенные инициализаторы `Point p{.x = 1, .y = 2};` (строго в порядке объявления полей) и агрегатная инициализация круглыми скобками `Point p(1, 2);` (в этой форме сужение допускается).
- `T x();` — объявление функции, а не инициализация объекта значением (самый досадный разбор, *most vexing parse*); инициализацию значением записывают как `T x{};`.
- **Сюрприз с `auto`:** `auto x{5};` — это `int` (с C++17), а `auto x = {5};` — `std::initializer_list<int>`.
- **На практике:** правило «каждую переменную инициализировать в точке объявления» и привычка к `{}` снимают целый класс ошибок; забытую инициализацию помогают найти [[Предупреждения компилятора]] (`-Wuninitialized`, `-Wmaybe-uninitialized` из набора `-Wall`). Осознанное откладывание создания дорогого объекта — отдельный приём, [[Ленивая инициализация]].

## Пример

```cpp
#include <iostream>

int g;                          // статическая память: нулевая инициализация, g == 0

struct Point { int x; int y; };

int main() {
    int a = 5;                  // копирующая инициализация
    int b(5);                   // прямая
    int c{5};                   // списковая
    int d{};                    // значением: 0
    int e;                      // по умолчанию: значение неопределённо
    // std::cout << e;          // UB: чтение неопределённого значения
    e = 7;                      // присваивание, а не инициализация
    int h = 3.7;                // сужение при '=' допустимо: h == 3
    // int f{3.7};              // ошибка: сужающее преобразование в списковой инициализации
    // int k();                 // объявление функции k, а не переменной
    const int limit = 10;       // const обязан быть инициализирован
    int& r = a;                 // ссылка обязана быть инициализирована
    Point p{.x = 1, .y = 2};    // C++20: назначенные инициализаторы

    std::cout << "g=" << g << " a=" << a << " b=" << b << " c=" << c << '\n';
    // выведет: g=0 a=5 b=5 c=5
    std::cout << "d=" << d << " e=" << e << " h=" << h << '\n';
    // выведет: d=0 e=7 h=3
    std::cout << "limit=" << limit << " r=" << r << " p=" << p.x << p.y << '\n';
    // выведет: limit=10 r=5 p=12
}
```

Строки `const int m;` и `int& q;` добавить нельзя: константа и ссылка без инициализатора — ошибка компиляции.

## Ловушки на экзамене

- **В `int x = 5;` используется оператор присваивания?** — Нет, это копирующая инициализация: объект создаётся сразу со значением 5, `operator=` не вызывается. Поэтому `const int c = 5;` компилируется, а `c = 5;` — нет.
- **Что содержит `int x;`, объявленная внутри функции?** — Неопределённое значение, и его чтение — UB, а не «0» и не «случайное, но безопасное число». Нулём гарантированно инициализируются только объекты статической памяти (глобальные и `static`).
- **Что объявляет `int k();`?** — Функцию `k` без параметров, возвращающую `int`, а не переменную (самый досадный разбор). Чтобы получить переменную, равную нулю, пишут `int k{};` или `int k = 0;`.
- **Чем `int a = 2.5;` отличается от `int a{2.5};`?** — Первое компилируется (`a == 2`, дробь отброшена), второе — ошибка: списковая инициализация запрещает сужающее преобразование `double` в `int`.
- **Сколько раз выполнится инициализация `static int calls = 0;` в функции, вызванной 100 раз?** — Один раз, при первом проходе через объявление; дальше переменная сохраняет значение между вызовами, и строка объявления её не сбрасывает.
- **Чем `std::vector<int> v(3, 1);` отличается от `std::vector<int> v{3, 1};`?** — Первое — три элемента со значением 1, второе — два элемента 3 и 1: списковая инициализация предпочитает конструктор от `std::initializer_list`.

## Связанные термины

- [[Переменная]] — сущность, которую инициализируют при объявлении
- [[Определение]] — объявление, создающее объект и содержащее его инициализатор
- [[Оператор присваивания]] — изменение значения уже существующего объекта
- [[Константность]] — `const`-объекты обязаны инициализироваться
- [[Конструктор]] — инициализация объектов классов
- [[Неявные преобразования типов]] — допускаются при `=` и ограничены при `{}`
- [[Статическая переменная]] — однократная инициализация при первом проходе
- [[Ленивая инициализация]] — откладывание создания объекта до первого использования

## Протокол спора

> [!quote]- Как рождалось определение
> **Версия A (Формалист):** «Инициализация (*initialization*) — этап создания объекта или ссылки, на котором объекту задаётся начальное значение, а ссылка связывается с объектом или функцией; выполняется по инициализатору, а при его отсутствии — по правилам инициализации по умолчанию. Для каждого объекта инициализация выполняется однократно, и время жизни объекта начинается с её завершения.»
>
> **Версия Б (Педагог-практик):** «Инициализация (*initialization*) — задание начального значения объекту (или привязка ссылки к объекту) в момент его создания, в отличие от присваивания, которое заменяет значение уже существующего объекта.»
>
> **Спорные пункты:**
> 1. Противопоставление присваиванию: у Б внутри определения, у A — только в примечаниях. → **Решение:** взято определение Б. Это не оговорка, а видовое отличие: вся тема держится на различии «создаётся со значением» и «значение заменяется», и именно его ждёт экзаменатор.
> 2. «Для каждого объекта инициализация выполняется однократно» (A). → **Решение:** утверждение удалено. Б прав: оно противоречит собственному примечанию A о том, что для скаляра с автоматической продолжительностью хранения инициализация «не выполняется вовсе»; стандарт сам говорит осторожнее — «its initialization (*if any*) is complete».
> 3. Классификация видов инициализации: восемь видов у A против пяти форм для `int` у Б. → **Решение:** основа Б — пять форм с прямым указанием, что для `int` результат совпадает; из версии A в них внесены содержательные уточнения (про `explicit`, про `std::initializer_list`, про отсутствие инициализации у скаляра). Нулевая инициализация, агрегатная и инициализация ссылки вынесены в отдельные пункты, поскольку классифицируются по другому основанию.
> 4. Сужение в `{}`: «запрещено» (Б) против оговорки A про `-Wnarrowing` для неконстантного источника. → **Решение:** прав A, что подтверждено компиляцией: `int n1{2.5};` g++ отвергает как ошибку, а `double d = 2.5; int n{d};` пропускает с предупреждением. Оговорка внесена в итог, Б её признал.
> 5. Вывод примера. Б: у A `std::cout << g << d << v << n2` печатает слитное `0102`, цифру невозможно сопоставить с переменной. → **Решение:** возражение принято, в итоговом примере каждое значение подписано именем.
> 6. Ссылка на `std::vector` в статье блока 1. Б считает её преждевременной. → **Решение:** из примера `vector` убран, но ловушка про `v(3, 1)` и `v{3, 1}` сохранена: это один из самых частых вопросов, а в формулировке ловушки знание `vector` не требуется.
>
> **Итог:** определение — Б. От A взяты: единство правил `[dcl.init]` и инициализация параметра аргументом, различение статической и динамической инициализации, потокобезопасность локальной `static`, оговорка про `-Wnarrowing`, формулировка про `T x();` и `T x{};`, C++20-расширения агрегатной инициализации, уточнение про `const`-объект класса без инициализатора. От Б: пять форм с указанием на одинаковый результат для `int`, жёсткое «локальная — мусор, чтение UB; статическая — гарантированный нуль», вывод «поэтому `{}` — основная форма», связка с `-Wuninitialized`, ловушки про `int k();` и про `static int calls = 0;` при 100 вызовах. Арбитр убрал `constinit`, неупорядоченность динамической инициализации между единицами трансляции, продление времени жизни временных объектов и *erroneous behavior* C++26 как материал будущих блоков, а также привёл «самый досадный разбор» с русским названием перед английским, как требует регламент.
