Совместный репозиторий для ведения конспектов, изучения языка программирования C++ и систематизации учебных материалов.

## 🛠️ Инструменты для работы

* **Среда разработки/Текст:** [Obsidian](https://obsidian.md) (для удобных связей между лекциями).
* **Система контроля версий:** Git + GitHub.

---

## 🔀 Архитектура ведения репозитория (Git Workflow)

Мы используем модель **Feature Branch**. Главная ветка `main` всегда должна оставаться стабильной и чистой.

### Как выполнять любую задачу:
1. **Обновите проект** перед началом работы:
   ```bash
   git checkout main
   git pull origin main
   ```
2. **Создайте новую ветку** под свою задачу:
   ```bash
   git checkout -b feature/название-задачи
   ```
3. **Сделайте работу** (напишите текст/код) и зафиксируйте изменения коммитом.
4. **Отправьте ветку** на GitHub:
   ```bash
   git push -u origin feature/название-задачи
   ```
5. **Создайте Pull Request (PR)** на GitHub. Второй автор должен проверить изменения (Code Review) перед слиянием в `main`.

---

## 🧱 Правила оформления коммитов (Conventional Commits)

Каждое сообщение коммита должно начинаться с префикса, определяющего тип изменений:

* `feat: ...` — добавление новой лекции, темы, файла или конспекта (например: `feat: добавил алфавит языка`).
* `docs: ...` — редактирование существующего текста, исправление форматирования, дополнение таблиц (например: `docs: улучшил структуру темы Лексемы`).
* `fix: ...` — исправление фактических ошибок, опечаток или багов в коде (например: `fix: исправил опечатку в синтаксисе циклов`).
* `refactor: ...` — перенос файлов по папкам, переименование для порядка, изменение структуры без изменения сути.
* `chore: ...` — рутинные задачи, не связанные с конспектами напрямую (обновление `.gitignore`, настройка окружения).

---

## ⚠️ Важные правила совместной работы

1. **Запрещено пушить напрямую в `main`** — все изменения проходят через ветки и Pull Request.
2. **Не редактируйте один и тот же файл одновременно** в разных ветках, чтобы избежать конфликтов слияния (Merge Conflicts).
3. **Личные настройки скрыты:** папка `.obsidian/` и файлы конфигураций у каждого свои и находятся в `.gitignore`.
