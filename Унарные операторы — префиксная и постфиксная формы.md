> [!abstract] Определение
> **Унарный оператор** (*unary operator*) — [[Оператор|оператор]] с единственным операндом. Форма записи определяется положением знака операции относительно операнда: **префиксная** (*prefix*) — знак записывается перед операндом, **постфиксная** (*postfix*) — после него. Обе формы в C++ есть только у операторов `++` и `--`; все прочие унарные операторы языка — исключительно префиксные.

## Примечания и тонкости

- **Кто есть кто.** Префиксные унарные операторы: `+` и `-` ([[Арифметические операторы|арифметические]]), `!` ([[Логические операторы|логическое НЕ]]), `~` ([[Битовые операторы|битовое НЕ]]), `*` ([[Оператор разыменования|разыменование]]), `&` (взятие адреса), `++` и `--`, `sizeof`, `alignof`, `noexcept`, `typeid`, `new` и `delete` ([[Динамическое управление памятью]]), приведение в стиле C `(T)x`. Постфиксную форму имеют только `++` и `--`, и только у них две формы различаются смыслом (подробно — [[Инкремент и декремент]]).
- **«Дописывается справа» не значит «унарный».** В грамматике префиксные операторы и постфиксные конструкции описаны раздельно ([expr.unary] и [expr.post]), но конструкции `a[i]`, `f(x)`, `a.b`, `a->b` **не унарны**: у них больше одного операнда (или операнд и имя), хотя записываются справа от первого операнда.
- **Один знак — разные операторы.** `-` бывает унарным (смена знака) и бинарным (вычитание), `*` — разыменованием и умножением, `&` — взятием адреса и битовым И. Лексема одна и та же, а арность определяет синтаксическая позиция: если слева от знака нет операнда, оператор унарный. В [[Объявление|объявлении]] `int* p;` или `int& r = x;` знак вообще не оператор, а часть декларатора: объявление не является [[Выражение|выражением]] (см. [[Левая ссылка]]).
- **Формы различаются категорией значения.** `++x` и `*p` дают **lvalue** (обозначают сам объект и допускают присваивание), а `x++`, `&x`, `-x`, `!x`, `~x` дают **prvalue** — значение-копию. Поэтому `++x = 1;` компилируется, а `x++ = 1;` — ошибка. См. [[lvalue и rvalue]].
- **Приоритет.** Все постфиксные конструкции связываются с операндом раньше любых префиксных: `*p++` — это `*(p++)`, `-x++` — это `-(x++)`, `&a[0]` — это `&(a[0])`. Префиксные унарные, в свою очередь, сильнее всех бинарных: `-a * b` — это `(-a) * b`. Префиксные группируются **справа налево**: `!!x` — это `!(!x)` (приём «привести к `bool`»), `*&x` — это `*(&x)`, то есть сам `x`, `++*p` — это `++(*p)`. См. [[Приоритеты операторов]].
- **Жадный разбор лексем.** Компилятор берёт самую длинную возможную лексему, поэтому `--x` — это декремент, а два унарных минуса пишутся с пробелом: `- -x`. По той же причине `a+++b` читается как `a++ + b`, а `a+++++b` не компилируется (получается `a++ ++ + b`).
- **Унарный `+` не пустая операция:** он выполняет целочисленное продвижение, поэтому `+c` превращает `char` в `int` — обычный приём напечатать код [[Символьный тип|символа]] числом. Из всех арифметических операторов только он допускает ещё и операнд-указатель ([expr.unary.op]). Унарный `-` над беззнаковым операндом даёт беззнаковый результат по модулю `2^N`: `-1u` — это `UINT_MAX`.
- **`-5` — не литерал.** Отрицательных числовых литералов в C++ нет: `-5` — это унарный минус, применённый к литералу `5`. Пограничный эффект: `-2147483648` имеет тип `long` или `long long`, потому что само `2147483648` в `int` не помещается; поэтому `INT_MIN` в стандартных заголовочных файлах определяют как `(-INT_MAX - 1)`.
- **`sizeof` — оператор, а не функция.** Для операнда-выражения скобки не обязательны (`sizeof x`), для операнда-типа обязательны (`sizeof(int)`). Операнд-выражение находится в невычисляемом контексте и **не вычисляется**: `sizeof(i++)` не меняет `i`.
- **Перегрузка.** Для своих типов формы `++` и `--` различаются единственным способом — фиктивным параметром: префиксная объявляется как `T& operator++()`, постфиксная как `T operator++(int)`; значение фиктивного параметра никогда не используется. См. [[Перегрузка операторов]].
- **На практике:** `!`, `-`, `*`, `&`, `++` встречаются почти в каждой строке кода, а `*p++` — классическая идиома прохода по массиву в стиле C (`while ((*dst++ = *src++) != '\0') {}`). Для «тяжёлых» объектов предпочтительна префиксная форма: постфиксная обязана сохранить и вернуть копию состояния до изменения, и эта копия нужна только тогда, когда её действительно используют.

## Пример

```cpp
#include <iostream>

int main() {
    int x = 5;
    int& ref = ++x;                            // префиксная форма даёт lvalue — связывается со ссылкой
    ref = 10;
    std::cout << x << '\n';                    // выведет: 10
    // int& bad = x++;                         // ошибка: x++ — prvalue, ссылку привязать нельзя

    int y = x++;                               // постфиксная форма: значение старое, x уже 11
    std::cout << y << ' ' << x << '\n';        // выведет: 10 11

    int* p = &x;                               // унарный & — взятие адреса
    std::cout << *p << ' ' << -x << ' ' << ~x << ' ' << !x << '\n';   // выведет: 11 -11 -12 0
    std::cout << - -x << '\n';                 // выведет: 11 (два унарных минуса; --x был бы декрементом)

    char c = 'A';
    std::cout << c << ' ' << +c << '\n';       // выведет: A 65 (унарный + продвигает char до int)

    int i = 0;
    std::cout << sizeof(i++) << ' ' << i << '\n';   // выведет: 4 0 (типично) — операнд не вычисляется

    int arr[] = {10, 20, 30};
    int* q = arr;
    int first = *q++;                          // это *(q++): постфиксный ++ старше унарного *
    std::cout << first << ' ' << *q << '\n';   // выведет: 10 20
}
```

Привязка `int& ref = ++x;` компилируется именно потому, что результат префиксного `++` — lvalue; закомментированная строка с `x++` не компилируется по противоположной причине. Размер `int`, равный 4 байтам, типичен, но стандартом не гарантирован.

## Ловушки на экзамене

- **«Сколько операторов в C++ имеют и префиксную, и постфиксную форму?»** — два: `++` и `--`. Всё остальное, что «пишется справа» (`[]`, `()`, `.`, `->`), — не унарные операторы вообще.
- **«Почему `++x = 5;` компилируется, а `x++ = 5;` — нет?»** — префиксная форма возвращает lvalue (сам объект), постфиксная — prvalue (копию старого значения), а присваивать можно только модифицируемому lvalue.
- **«Сколько разных операторов в `a - -b`?»** — два: бинарное вычитание и унарный минус. Знак один и тот же, роль определяется позицией.
- **«Что увеличивает `*p++` — значение или указатель?»** — указатель: постфиксный `++` связывается раньше `*`, так что выражение даёт старый элемент и сдвигает `p`. Увеличить значение — `(*p)++` или `++*p`.
- **«Чем `*` в `int* p;` отличается от `*` в `*p = 1;`?»** — в первом случае это часть декларатора в объявлении, во втором — унарный оператор разыменования в выражении. Путаница лексического вида и синтаксической роли — типичная ошибка.
- **«`sizeof` — функция?»** — нет, оператор, вычисляемый во время компиляции; его операнд не вычисляется, поэтому после `sizeof(i++)` значение `i` не меняется.
- **«Является ли `-5` литералом?»** — нет, это унарный минус и литерал `5`. Именно поэтому `-2147483648` имеет тип не `int`, а `long`/`long long`.
- **«Чему равно `-1u`?»** — `UINT_MAX`: унарный минус над беззнаковым операндом даёт беззнаковый результат по модулю `2^N`. Отрицательных значений у типа `unsigned` не существует.
- **«Как объявить постфиксный `++` для своего класса?»** — `T operator++(int);` с неиспользуемым параметром-различителем; префиксный — `T& operator++();`.

## Связанные термины

- [[Оператор]] — родовое понятие; унарность — характеристика по числу операндов.
- [[Инкремент и декремент]] — единственные операторы с двумя формами, разобранные отдельно.
- [[lvalue и rvalue]] — ключ к различию `++x` и `x++`, `*p` и `&x`.
- [[Оператор разыменования]] — унарный `*`, самый частый пример префиксной формы.
- [[Приоритеты операторов]] — постфиксные сильнее префиксных, префиксные сильнее бинарных.
- [[Перегрузка операторов]] — механизм с фиктивным параметром `int` для постфиксной формы.
- [[Арифметические операторы]] — содержат унарные `+` и `-`, а также их бинарные омонимы.

## Протокол спора

> [!quote]- Как рождалось определение
> **Версия A (Формалист):** «Унарный оператор (*unary operator*) — оператор с единственным операндом. Форма записи определяется положением знака операции относительно операнда: префиксная — знак записывается перед операндом, постфиксная — после него. В C++ обе формы есть только у операторов `++` и `--`; все прочие унарные операторы языка (`*`, `&`, `+`, `-`, `!`, `~`, `sizeof`, `alignof`, `new`, `delete`, приведения типа) — исключительно префиксные.»
>
> **Версия Б (Педагог-практик):** «Унарный оператор (*unary operator*) — оператор, применяемый ровно к одному операнду. По положению относительно операнда различают префиксную форму (*prefix*), когда оператор записан перед операндом, и постфиксную форму (*postfix*), когда оператор записан после операнда.»
>
> **Спорные пункты:**
> 1. Должен ли факт «обе формы есть только у `++` и `--`» входить в определение. A: должен, иначе термин не очерчен и студент решит, что постфиксных операторов много. Б: определение должно отвечать только на вопрос «что это», перечень — в примечаниях. → **Решение:** принято A, но перечень знаков из определения убран (регламент запрещает примеры внутри определения): осталось «обе формы в C++ есть только у `++` и `--`; все прочие унарные операторы — исключительно префиксные». Так определение остаётся тремя фразами, пригодными для устного ответа, и при этом задаёт границу понятия.
> 2. Статус постфиксных конструкций `a[i]`, `f(x)`, `a.b`, `a->b`. A: это не унарные операторы, у них больше одного операнда. Б относит их к «постфиксным операциям», которые «связываются раньше префиксных». → **Решение:** прав A по существу: `a[i]` и `a.b` — бинарные конструкции, и называть их унарными нельзя. Формулировка Б про приоритет при этом верна и сохранена, но с оговоркой A, что «дописывается справа» и «унарный» — разные вещи. Это же стало первой экзаменационной ловушкой.
> 3. Нужна ли категория значения (lvalue/prvalue) в статье. A разбирает её как главное различие форм; у Б она упомянута только в статье про инкремент. → **Решение:** принято A: `++x = 1;` против `x++ = 1;` — самый наглядный способ показать, что формы различаются не только записью. Пример A со связыванием ссылки оставлен в итоге.
> 4. Жадный разбор лексем (`a+++b`, `- -x`) и «`-5` — не литерал» с типом `-2147483648`. Есть только у Б. A (за точность) мог бы возразить, что это вопрос лексического уровня, а не арности. → **Решение:** принято у Б: оба пункта относятся именно к форме записи унарного оператора и объясняют, почему `INT_MIN` определяют как `(-INT_MAX - 1)`. Утверждение про тип `-2147483648` арбитр проверил по правилам вывода типа целого литерала: `2147483648` в `int` не помещается, поэтому тип — `long`/`long long`.
> 5. Полнота перечня префиксных операторов. У A нет `noexcept` и `typeid` среди примеров, у Б — `alignof` присутствует, но нет `noexcept`, `typeid`, `co_await`. → **Решение:** перечень объединён; `co_await` как корутинная конструкция в статью первого блока не вошёл.
> 6. Ловушка Б «есть ли в C++ постфиксный факториал `n!`». → **Решение:** убрана: вопрос не проверяет понимания форм записи и на экзамене не встречается. Вместо неё оставлены ловушки про `a - -b` и `*p++` от Б.
>
> **Итог:** определение — A, очищенное от перечня знаков. От A взяты: раздельность [expr.unary] и [expr.post] с выводом «постфиксные конструкции не унарны», различие lvalue/prvalue и пример со связыванием ссылки, `+` как единственный арифметический оператор с операндом-указателем, невычисляемый операнд `sizeof`, фиктивный параметр при перегрузке, практический довод в пользу префиксной формы. От Б: перечень префиксных операторов, «один знак — разные операторы» и роль позиции, правая группировка префиксных с примерами `!!x` и `*&x`, жадный разбор лексем, «`-5` — не литерал», идиома `*p++` и `while ((*dst++ = *src++) != '\0')`, ловушки `a - -b` и `*p++`. Итоговый пример собран из обоих и проверен компилятором: выводит `10`, `10 11`, `11 -11 -12 0`, `11`, `A 65`, `4 0`, `10 20`. Фактических ошибок ни у одной стороны не обнаружено.
