# Инструкции управления

> [!abstract] Определение
> **Инструкции управления** (*control flow statements*) — инструкции (*statements*), изменяющие естественный порядок выполнения, при котором инструкции выполняются последовательно в порядке записи: они выбирают, повторяют или пропускают выполнение других инструкций либо передают управление в другую точку [[Функция|функции]]. К ним относятся три категории инструкций, выделяемые стандартом C++: инструкции выбора (*selection statements*), инструкции циклов (*iteration statements*) и инструкции перехода (*jump statements*).

## Примечания и тонкости

- **Инструкция** (*statement*) — элементарный шаг выполнения программы, синтаксическая единица, из последовательности которых состоит тело функции. В отличие от [[Выражение|выражения]] инструкция выполняется ради своего действия и не имеет значения. Стандарт C++20 различает: помеченную инструкцию (*labeled statement* — метка `goto` или метка `case`), инструкцию-выражение (`x = 1;`, в том числе пустую `;`), составную инструкцию (блок `{…}`), [[Инструкции выбора|инструкции выбора]], [[Инструкции циклов|инструкции циклов]], инструкции перехода, инструкцию-объявление (*declaration statement*) и try-блок. Инструкциями управления из них являются только три категории.
- **Состав категорий:**
    - выбора: `if`, `if … else`, `if constexpr` (C++17), `switch`;
    - циклов: `while`, `do … while`, `for`, диапазонный `for` (C++11);
    - перехода: `break` — выход из ближайшего объемлющего цикла или `switch`; `continue` — переход к концу тела ближайшего объемлющего цикла (далее выполняется выражение приращения, если это `for`, и проверка условия); `return` — выход из функции, возможно с возвратом значения ([[Передача параметров и возврат значения]]); `goto` — переход к помеченной инструкции той же функции; `co_return` — выход из сопрограммы (C++20).
- **Термин не является термином стандарта.** В стандарте нет общей категории «control flow statements»; это принятое на cppreference и в учебниках объединение трёх разделов — `[stmt.select]`, `[stmt.iter]`, `[stmt.jump]`.
- **Терминологическая ловушка.** В старой русской литературе *statement* переводили как «оператор» («условный оператор `if`», «оператор цикла»). В справочнике [[Оператор|оператор]] — это только *operator* (`+`, `=`, `<<`…), у него есть операнды и значение, а `if`, `for`, `return` — инструкции. На экзамене стоит говорить «инструкция» и при необходимости пояснить расхождение.
- **Составная инструкция `{…}` — это одна инструкция** и одновременно [[Область видимости|область видимости]]. Это ключ к пониманию ветвлений и циклов: они управляют ровно одной подынструкцией, и фигурные скобки нужны именно для того, чтобы подчинить им несколько. Даже без фигурных скобок подынструкция образует собственную область видимости.
- **Точка с запятой — не разделитель инструкций,** а часть инструкции-выражения и инструкции-объявления. Поэтому у составной инструкции точки с запятой нет и после `}` цикла или ветвления её не ставят, а одинокая `;` — полноценная пустая инструкция.
- **Пустая инструкция как тело** — известная ошибка: `while (i < n);` даёт [[Бесконечный цикл|бесконечный цикл]]. Для `if` и `do … while` g++ предупреждает (`-Wempty-body`), для `while` такого предупреждения нет — эту опечатку приходится искать глазами; частично выручает `-Wmisleading-indentation` ([[Предупреждения компилятора]]).
- **Что не относится к инструкциям управления, хотя меняет ход выполнения:** `throw` — это выражение, а `throw e;` — инструкция-выражение; try-блок — отдельный вид инструкции ([[Обработка исключений]]); вызов функции — выражение; `?:`, `&&`, `||` — операторы, управляющие вычислением операндов внутри выражения ([[Логические операторы]]). Составная инструкция лишь группирует инструкции и порядок выполнения не меняет.
- **Переходы и время жизни.** При выходе из блока инструкцией перехода автоматические объекты уничтожаются в порядке, обратном созданию (вызываются [[Деструктор|деструкторы]]). Переход (`goto`, переход к метке `case`) внутрь области видимости [[Переменная|переменной]] в обход её объявления с инициализацией — ошибка компиляции.
- **Условие** (*condition*) в `if`, `switch`, `while` и `for` может быть объявлением с инициализатором: `while (int n = next()) …`; введённое имя видно только внутри инструкции.
- **На практике:** читаемость страдает прежде всего от глубокой вложенности управляющих инструкций, поэтому предпочитают ранний `return` и `continue` вместо лестницы вложенных `if`, а крупные ветви выносят в функции. `goto` в прикладном коде почти не встречается (допустимое применение — выход сразу из нескольких вложенных циклов).

## Пример

```cpp
#include <iostream>

int main() {
    int sum = 0;
    for (int i = 1; ; ++i) {      // инструкция цикла (условие опущено)
        if (i % 2 == 0)           // инструкция выбора
            continue;             // инструкция перехода: к следующей итерации
        if (i > 9)
            break;                // инструкция перехода: выход из цикла
        sum += i;                 // инструкция-выражение — не инструкция управления
    }
    std::cout << sum << '\n';     // выведет: 25  (1 + 3 + 5 + 7 + 9)

    int n = 0;
    if (n > 0)                    // подчинена ровно одна инструкция
        std::cout << "положительное\n";
    std::cout << "конец\n";       // выполняется всегда, как бы ни стоял отступ

    // while (n < 3);             // пустая инструкция ';' как тело — бесконечный цикл
    return 0;                     // инструкция перехода: выход из функции
}
```

Цикл без условия был бы бесконечным, если бы не инструкция `break`. Вторая часть примера показывает, что отступ не влияет на то, какая инструкция подчинена `if`.

## Ловушки на экзамене

- **`if` — это оператор?** — В терминологии стандарта нет: `if` — инструкция (*statement*), у неё нет ни операндов, ни значения, а оператор (*operator*) — знак операции внутри выражения. Название «условный оператор» — наследие старых переводов.
- **Чем инструкция отличается от выражения?** — Выражение вычисляет значение, инструкция выполняет действие. Выражение становится инструкцией, когда к нему добавляют точку с запятой; обратное неверно — `if` в выражение не превратить, для этого есть оператор `?:`.
- **Сколько инструкций подчинено `if` в коде `if (x) a = 1; b = 2;`?** — Одна: `a = 1;`. Инструкция `b = 2;` выполняется всегда, как бы она ни была отформатирована.
- **Точка с запятой — это разделитель инструкций?** — Нет, она входит в состав самой инструкции. Поэтому `{…}` обходится без неё, а `;` сам по себе — пустая инструкция, и `while (i < n);` — бесконечный цикл.
- **Куда передаёт управление `break` внутри `switch`, который находится в цикле? А `continue`?** — `break` завершает только `switch` (ближайшую объемлющую конструкцию из «цикл или `switch`»), а `continue` относится к циклу, так как на `switch` не действует, — выполнение перейдёт к следующей итерации.
- **Выйдет ли `break` сразу из двух вложенных циклов?** — Нет, только из ближайшего. Нужны флаг, вынесение в отдельную функцию с `return` или (редко) `goto`.
- **Является ли `throw` инструкцией управления?** — Нет: `throw` — выражение (оно может стоять, например, в операнде `?:`), а `throw e;` — инструкция-выражение. Передачу управления при исключении описывает механизм обработки исключений, а не категория инструкций управления.
- **Можно ли с помощью `goto` перепрыгнуть вперёд через `int x = 5;`?** — Нет, если после метки `x` ещё в области видимости: переход в обход инициализации — ошибка компиляции. Выход из области видимости переходом назад или наружу допустим.

## Связанные термины

- [[Инструкции выбора]] — первая из трёх категорий: выбор одной из ветвей.
- [[Инструкции циклов]] — вторая категория: повторное выполнение подынструкции.
- [[Бесконечный цикл]] — частый результат ошибки в управляющей инструкции.
- [[Выражение]] — имеет значение, в отличие от инструкции; инструкция-выражение превращает выражение в инструкцию.
- [[Оператор]] — не путать: *operator*, а не *statement*.
- [[Функция]] — тело функции состоит из инструкций; `return` завершает функцию.
- [[Область видимости]] — составная инструкция, подынструкции и условия вводят собственные области видимости.
- [[Обработка исключений]] — альтернативный механизм передачи управления, не относящийся к инструкциям управления.

## Протокол спора

> [!quote]- Как рождалось определение
> **Версия A (Формалист):** «Инструкции управления (*control flow statements*) — инструкции (*statements*), изменяющие естественный порядок выполнения, при котором инструкции выполняются последовательно в порядке записи: они выбирают, повторяют или пропускают выполнение других инструкций либо передают управление в другое место функции. К ним относятся три категории инструкций, выделяемые стандартом C++: инструкции выбора (*selection statements*), инструкции циклов (*iteration statements*) и инструкции перехода (*jump statements*).»
>
> **Версия Б (Педагог-практик):** «Инструкции управления (*control flow statements*) — инструкции (*statements*), которые сами не вычисляют значение, а задают, какие другие инструкции программы будут выполнены и в каком порядке. К ним относятся инструкции выбора, инструкции циклов и инструкции перехода (`break`, `continue`, `return`, `goto`).»
>
> **Спорные пункты:**
> 1. Видовое отличие. Б: «сами не вычисляют значение». → **Решение:** формулировка Б отвергнута: значения не вычисляет **никакая** инструкция, так что этот признак не отделяет инструкции управления от инструкции-выражения или блока. Взято видовое отличие A — изменение естественного, последовательного порядка выполнения; при этом сам «естественный порядок» A тут же и определяет, что для первокурсника важно.
> 2. Перечень инструкций перехода внутри определения (Б). → **Решение:** перенесён в примечания: регламент запрещает перечни-иллюстрации в определении. Состав категорий дан отдельным пунктом, по версии A — он полнее (есть `co_return`, который в C++20 входит в грамматику jump-statement, и диапазонный `for`).
> 3. Статус термина. A отмечает, что «control flow statements» — не категория стандарта, а объединение трёх его разделов; у Б этого нет. → **Решение:** примечание A принято: иначе студент будет искать в стандарте несуществующий раздел.
> 4. Предупреждение на пустое тело цикла. Б: `-Wempty-body` выдаётся для `if`, но не для `while`. → **Решение:** Б прав, утверждение проверено компиляцией g++ 13.3: на `if (i < n);` выдаётся `warning: suggest braces around empty body in an 'if' statement [-Wempty-body]` и дополнительно `-Wmisleading-indentation`, на `do ; while (i < n);` — `-Wempty-body`, а на `while (i < n);` не выдаётся ничего. Это ценное практическое наблюдение, которого у A нет.
> 5. Что ещё не относится к инструкциям управления. Только у A: `throw` как выражение, try-блок как отдельный вид инструкции, `?:`, `&&`, `||` как операторы. → **Решение:** принято целиком: это и есть граница понятия, а без неё определение «меняет ход выполнения» слишком широко.
> 6. Роль точки с запятой и составной инструкции. Только у Б: «точка с запятой — не разделитель инструкций», «`{…}` — одна инструкция, и скобки нужны, чтобы подчинить ветвлению несколько действий». → **Решение:** принято: это прямо отвечает на две типовые экзаменационные ловушки и объясняет, почему после `}` не ставят `;`.
> 7. Наполнение примера. A: цикл без условия, в котором работают `continue`, `break` и `return`. Б: то же плюс демонстрация, что `if` без скобок подчиняет одну инструкцию. → **Решение:** взят пример A (он показывает все три инструкции перехода и опущенное условие цикла), к нему добавлена вторая часть Б про одну подчинённую инструкцию и закомментированная строка `while (n < 3);`.
>
> **Итог:** определение — A, с перечнем инструкций перехода, вынесенным в примечания. От A взяты: определение инструкции и полный перечень её видов по C++20, состав трёх категорий (включая `co_return`), замечание о неформальности самого термина, граница понятия (`throw`, try-блок, `?:`, `&&`, `||`), уничтожение автоматических объектов при переходе, запрет перехода в обход инициализации, условие-объявление, ловушки про `break` в `switch` внутри цикла, про `throw` и про `goto`. От Б взяты: «составная инструкция — одна инструкция и область видимости», роль точки с запятой, отсутствие `-Wempty-body` для `while`, ловушки «сколько инструкций подчинено `if`», «чем инструкция отличается от выражения» и «выйдет ли `break` из двух циклов», вторая часть примера.
