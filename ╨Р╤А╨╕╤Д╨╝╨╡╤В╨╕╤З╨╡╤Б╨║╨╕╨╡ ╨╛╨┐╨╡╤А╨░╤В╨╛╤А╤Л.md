# Арифметические операторы

> [!abstract] Определение
> **Арифметические операторы** (*arithmetic operators*) — группа встроенных [[Оператор|операторов]], которые по числовым операндам вычисляют числовое значение, не изменяя сами операнды: бинарные сложение `+`, вычитание `-`, умножение `*`, деление `/`, взятие остатка `%` и унарные плюс `+` и минус `-`. Перед вычислением операнды приводятся к общему типу; результат — значение этого общего типа.

## Примечания и тонкости

- **Допустимые операнды.** Значения [[Встроенный тип|встроенных]] арифметических типов — [[Целый тип|целых]] (включая `char` и `bool`, которые перед вычислением продвигаются до `int`) и [[Вещественный тип|вещественных]], а также [[Перечисление|перечислений]] без `class`. Остаток `%` требует именно **целых** операндов; для вещественных его роль играет `std::fmod` из `<cmath>`. Кроме чисел, операндом бинарных `+` и `-` может быть указатель, а операндом унарного `+` — указатель тоже: эти случаи относятся к [[Арифметика указателей|арифметике указателей]].
- **Приведение к общему типу** — это [[Неявные преобразования типов|неявные преобразования]] в два шага: сначала *целочисленные продвижения* (`bool`, `char`, `short` → `int`), затем *обычные арифметические преобразования* (`int` и `double` → `double`, `int` и `unsigned` → `unsigned`). Поэтому `'A' + 1` — это `int` со значением 66, а не символ `'B'`, а в `1 + 2u - 4` весь расчёт идёт в `unsigned` и даёт не `-1`, а огромное положительное число.
- **Целочисленное деление.** Если оба операнда целые, результат `/` тоже целый: дробная часть отбрасывается, округление — всегда **к нулю** (гарантировано с C++11; в C++03 направление было implementation-defined). Тип [[Переменная|переменной]], в которую записывается результат, на выбор операции не влияет — важны только типы операндов.
- **Остаток согласован с делением:** всегда выполняется тождество

$$
(a \mathbin{/} b) \cdot b + (a \bmod b) = a
$$

  Отсюда знак остатка совпадает со знаком делимого: `-7 % 2` равно `-1`, `7 % -2` равно `1`. Математический остаток из промежутка от `0` до `m - 1` получают выражением `(a % m + m) % m`.
- **Деление на нуль** — **UB** и для `/`, и для `%` ([expr.mul]). Формально стандарт объявляет неопределённым любое деление на нуль, включая вещественное; однако на реализациях с IEEE 754 (то есть практически всех, где `std::numeric_limits<double>::is_iec559` истинно) вещественное деление даёт `±inf` или `NaN` и не считается диагностируемой ошибкой.
- **Переполнение.** Выход результата `+`, `-`, `*` за границы знакового типа, а также `INT_MIN / -1` — **UB**: компилятор вправе считать, что такого не бывает. То, что с C++20 знаковые типы обязаны храниться в дополнительном коде, законным переполнение не сделало. Беззнаковые типы в этом смысле не переполняются: результат берётся по модулю `2^N`, где `N` — ширина типа, — это определённое поведение, поэтому `0u - 1` равно максимальному `unsigned`. Границы — в [[Диапазоны арифметических типов]].
- **Унарные формы.** Унарный минус над беззнаковым операндом даёт беззнаковый результат по модулю `2^N`: `-1u` — это `UINT_MAX`, а не «минус единица». Унарный плюс значение не меняет, но выполняет целочисленное продвижение, поэтому `+c` печатает код [[Символьный тип|символа]] числом. Общие правила записи — в статье [[Унарные операторы — префиксная и постфиксная формы]].
- **Приоритет и ассоциативность** — как в школьной арифметике: унарные `+` и `-` сильнее `*`, `/`, `%`, те сильнее бинарных `+` и `-`; операторы одного уровня выполняются слева направо, поэтому `8 / 4 / 2` равно `1`. Полная таблица — [[Приоритеты операторов]].
- **Отличие от «родственников».** Составные присваивания `+=`, `-=`, `*=`, `/=`, `%=` ([[Оператор присваивания]]) и [[Инкремент и декремент|инкремент с декрементом]] тоже считают, но **изменяют** операнд; арифметические операторы только вычисляют значение. Все они допускают [[Перегрузка операторов|перегрузку]] для пользовательских типов.
- **Оператора возведения в степень в языке нет.** Знак `^` — исключающее ИЛИ из [[Битовые операторы|битовых операторов]]; степень вычисляет `std::pow` из `<cmath>` (возвращает `double`) или умножение для малых целых показателей.
- **На практике:** большинство ошибок в арифметике на C++ — не ошибки формул, а ошибки типов: целочисленное деление там, где ожидался дробный результат (среднее, процент), и беззнаковый перенос в выражениях вида `v.size() - 1` для пустого контейнера.

## Пример

```cpp
#include <cmath>
#include <iostream>

int main() {
    int a = -7, b = 2;
    std::cout << a / b << ' ' << a % b << '\n';        // выведет: -3 -1
    std::cout << (a / b) * b + a % b << '\n';          // выведет: -7  (тождество деления)

    std::cout << 7 / 2 << ' ' << 7 / 2.0 << '\n';      // выведет: 3 3.5
    double avg = (7 + 2) / 2;                          // сначала int / int = 4, потом 4 -> 4.0
    std::cout << avg << '\n';                          // выведет: 4

    char c = 'A';
    std::cout << c + 1 << '\n';                        // выведет: 66 (char продвигается до int)

    unsigned u = 0;
    std::cout << u - 1 << '\n';                        // выведет: 4294967295 при 32-битном unsigned
    std::cout << std::fmod(7.5, 2.0) << '\n';          // выведет: 1.5 (остаток для вещественных)

    // std::cout << 7.5 % 2;     // ошибка: % требует целых операндов
    // std::cout << a / 0;       // UB: деление целого на нуль
    // int big = 2147483647 + 1; // UB: переполнение знакового типа
}
```

Строки с `7 / 2`, `7 / 2.0` и `avg` — главный урок: `/` для целых и `/` для вещественных — разные операции, и выбирают её типы операндов, а не ожидаемый или объявленный тип результата.

## Ловушки на экзамене

- **«Чему равно `x` после `double x = 1 / 2;`?»** — `0.0`. Сначала вычисляется `1 / 2` в типе `int` (получается `0`), и только потом нуль преобразуется в `double`. Тип переменной слева на деление не влияет.
- **«Чему равны `-7 / 2` и `-7 % 2`?»** — `-3` и `-1`. Деление округляется к нулю, поэтому остаток отрицателен; это не математический `a mod b`, который всегда неотрицателен.
- **«Почему `1 + 2u - 4` не равно `-1`?»** — из-за обычных арифметических преобразований весь расчёт идёт в `unsigned`: `3u - 4u` даёт значение по модулю `2^32`. Знакового промежуточного результата здесь нет вообще.
- **«Что будет при `INT_MAX + 1`?»** — UB, а не «гарантированно `INT_MIN`». Для беззнаковых результат гарантирован: `UINT_MAX + 1u` равно `0`.
- **«Является ли переполнение `int` ошибкой компиляции?»** — нет. В `constexpr`-вычислении компилятор обязан отвергнуть такое выражение (оно перестаёт быть константным), а в обычном коде это UB времени выполнения, которое компилятор вправе не обнаруживать.
- **«Как возвести в квадрат — `x ^ 2`?»** — нет, это XOR (`2 ^ 3` равно `1`, а не `8`). Правильно `x * x` или `std::pow(x, 2)`.
- **«Какой тип и значение у `'a' + 'b'`?»** — `int` со значением 195 (97 + 98), а не `char`: оба операнда продвигаются до `int`.
- **«Деление вещественного на нуль — это UB?»** — в ядре языка да, любое деление на нуль неопределено; но на IEEE-реализациях получается `inf`/`NaN`, и полагаться на это можно, лишь проверив `is_iec559`.

## Связанные термины

- [[Оператор]] — общее понятие; арифметические операторы — одна из его групп.
- [[Выражение]] — контекст, в котором операторы применяются и вычисляется значение.
- [[Неявные преобразования типов]] — определяют общий тип операндов и тип результата.
- [[Диапазоны арифметических типов]] — границы, за которыми начинается переполнение (UB для знаковых).
- [[Целый тип]] — целочисленное деление и единственно допустимые операнды `%`.
- [[Битовые операторы]] — другая группа над целыми; `^` не имеет отношения к возведению в степень.
- [[Приоритеты операторов]] — порядок разбора `a + b * c` без скобок.
- [[Инкремент и декремент]] — арифметика, которая изменяет операнд.

## Протокол спора

> [!quote]- Как рождалось определение
> **Версия A (Формалист):** «Арифметические операторы (*arithmetic operators*) — группа встроенных операторов, которые по числовым операндам вычисляют числовое значение: унарные `+` и `-`, бинарные `*`, `/`, `%`, `+`, `-`. Перед вычислением к операндам применяются целочисленные продвижения, а к операндам бинарных операторов — ещё и обычные арифметические преобразования; результатом является prvalue-значение полученного общего типа.»
>
> **Версия Б (Педагог-практик):** «Арифметические операторы (*arithmetic operators*) — операторы, выполняющие над числовыми операндами действия обычной арифметики: бинарные сложение `+`, вычитание `-`, умножение `*`, деление `/` и взятие остатка `%`, а также унарные плюс `+` и минус `-`. Арифметический оператор вычисляет новое значение и не изменяет свои операнды.»
>
> **Спорные пункты:**
> 1. Перечень операндов: A утверждает, что единственное исключение из «только числа» — унарный `+`, допускающий указатель. Б относит к исключениям и бинарные `+`/`-` для указателей. → **Решение:** прав Б. Стандарт разрешает указатель как операнд и унарного `+` ([expr.unary.op]), и бинарных `+`/`-` (`p + n`, `p - q`); утверждение A о «единственном исключении» противоречит его же примечанию про арифметику указателей. В итог вошла формулировка Б с сохранённой ссылкой A на [expr.unary.op]-случай.
> 2. Насыщенность определения. A вносит в определение продвижения, обычные арифметические преобразования и категорию значения prvalue. Б (за понятность) возражает: для устного ответа первокурсника три термина подряд неподъёмны, а «prvalue» в этой статье ничего не объясняет. → **Решение:** за основу взято определение Б, из A добавлено короткое «операнды приводятся к общему типу; результат — значение этого общего типа» — без названий обеих групп преобразований: они разобраны отдельным примечанием. Терминология prvalue оставлена статье [[lvalue и rvalue]].
> 3. Видовое отличие «не изменяет операнды» (Б) против простого «вычисляют значение» (A). → **Решение:** взято у Б: именно это отличает группу от `+=` и `++`, которые тоже «считают». A (за точность) мог бы возразить, что перегруженный `operator+` формально может изменить операнды, — но речь о встроенных операторах, и это оговорено словом «встроенных» из версии A.
> 4. Направление округления целого деления. Обе версии говорят «к нулю, гарантировано с C++11». → **Решение:** согласие; добавлено уточнение A, что до C++11 направление было implementation-defined.
> 5. Деление вещественного на нуль. A: формально UB, но на IEEE-реализациях `inf`/`NaN`, и опираться можно только при `is_iec559`. Б: «по стандарту тоже UB, но на практике `inf` или `NaN`». → **Решение:** взята более строгая версия A с критерием `is_iec559`; формулировка Б «на практике обычно аварийно завершается» для целых как неуточняемая деталь реализации из итога убрана.
> 6. Меташная реплика Б о том, что cppreference описывает битовые операторы на одной странице с арифметическими. → **Решение:** убрана: справочник не комментирует структуру сторонних сайтов, а границу группы задаёт статья «Битовые операторы».
>
> **Итог:** определение — Б, уточнённое словом «встроенных» и фразой про общий тип от A. От A взяты: тождество деления формулой, implementation-defined округление до C++11, критерий `is_iec559`, `INT_MIN / -1` как отдельный случай UB, ловушка про `constexpr`-переполнение и про `1 + 2u - 4`. От Б: исправленный перечень операндов с указателями, двухшаговое описание преобразований с примером `'A' + 1`, рецепт `(a % m + m) % m`, `7 % -2 == 1`, ловушки `double x = 1 / 2;` и `'a' + 'b'`, практический пункт про `v.size() - 1`. Арбитр проверил компилятором весь итоговый пример: выводы `-3 -1`, `-7`, `3 3.5`, `4`, `66`, `4294967295`, `1.5` подтверждены.
