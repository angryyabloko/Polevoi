# Объявление

> [!abstract] Определение
> **Объявление** (*declaration*) — конструкция языка, которая вводит в единицу трансляции одно или несколько имён (либо повторно сообщает об уже введённом имени) и задаёт их интерпретацию: вид обозначаемой сущности — [[Переменная|переменная]], [[Функция|функция]], [[Тип данных|тип]], [[Пространство имён|пространство имён]] — её тип и, где это применимо, [[Связывание|связывание]]. Объявление делает имя известным транслятору, но не обязано полностью задавать саму сущность: это дело [[Определение|определения]].

## Примечания и тонкости

- Каждое определение является объявлением, но не каждое объявление — определением. Одно и то же имя можно объявлять сколько угодно раз, если объявления согласованы (тот же тип, то же связывание); определением из них может быть не более одного.
- «Объявление» — понятие грамматики, и строго говоря не каждое объявление вводит имя: `static_assert(n > 0, "…");`, пустое объявление `;`, `using namespace std;` и объявление, состоящее только из атрибутов, грамматически являются declaration, но никаких имён не вводят. Рабочее описание «объявление вводит имя» верно для всех практически значимых случаев, и именно его следует давать на экзамене, но знать про исключения полезно.
- Устройство простого объявления: спецификаторы (тип, `const`, `static`, `extern`…), затем список объявителей через запятую, у каждого — свой необязательный [[Инициализация|инициализатор]]: `const int a = 1, *p = &a, arr[3]{};`. Знаки `*`, `&`, `[]` относятся к конкретному объявителю, а не к спецификатору типа, поэтому в `int* p, q;` указателем является только `p`.
- Объявление — не [[Выражение|выражение]]: `int x = 5;` — инструкция-объявление, и `=` в ней часть синтаксиса инициализации, а не [[Оператор присваивания|оператор присваивания]]. Разница видна на [[Константность|константах]]: `const int c = 5;` допустимо, а `c = 5;` — нет.
- Имя нужно объявить до использования: транслятор читает текст сверху вниз, поэтому функцию, записанную ниже `main`, предварительно объявляют прототипом — `int square(int);`. Исключение составляет контекст полного класса: в телах методов, аргументах по умолчанию, инициализаторах членов и `noexcept`-спецификациях видны все члены класса, в том числе объявленные ниже; отдельно отложен и поиск зависимых имён в шаблонах — он выполняется при инстанцировании.
- Точка объявления (*point of declaration*) — сразу после полного объявителя и **до** инициализатора. Поэтому `int x = x;` успешно компилируется: второе `x` — это уже объявляемая переменная, и чтение её неопределённого значения даёт UB, а не ошибку «имя не найдено» (GCC 13 выдаёт лишь `warning: 'x' is used uninitialized`).
- Объявления достаточно, пока не требуется полный тип. После `struct Point;` (неполный тип) можно объявить `Point*`, `Point&`, функцию с параметром или возвращаемым значением типа `Point`, но нельзя создать [[Объект|объект]], применить `sizeof` или обратиться к члену.
- Объявлениями, но **не** определениями являются, в частности: объявление функции без тела; объявление переменной с [[Ключевое слово extern|extern]] без инициализатора; объявление имени класса; непрозрачное объявление перечисления (`enum class E : int;`); `typedef` и alias-declaration ([[Псевдоним типа|псевдоним типа]]); using-declaration и using-directive; параметр шаблона; параметр функции в объявлении, не являющемся определением функции; `static_assert`. Нормативный перечень — в [basic.def].
- В C++, в отличие от C, нет «предварительных определений» (*tentative definitions*): `int n;` в области видимости пространства имён — сразу определение. Поэтому такая строка в [[Заголовочный файл|заголовочном файле]], включённом в две единицы трансляции, даёт два определения и ошибку компоновки.
- Неоднозначность «объявление или выражение» всегда разрешается в пользу объявления (*most vexing parse*): `S s();` — объявление функции без параметров, возвращающей `S`, а не создание объекта. GCC предупреждает об этом: `empty parentheses were disambiguated as a function declaration [-Wvexing-parse]`.
- **На практике:** объявления живут в заголовочных файлах, определения — в файлах реализации; это и позволяет компилировать файлы проекта по отдельности, не пересобирая всё при каждом изменении (см. [[Раздельная компиляция]]). Объявление вперёд (*forward declaration*) вместо `#include` сокращает время сборки и разрывает циклические зависимости между заголовочными файлами.

## Пример

```cpp
#include <iostream>

int  square(int);           // объявление функции (прототип): тела нет
extern int counter;         // объявление переменной: память не выделена
struct Point;               // объявление типа: Point пока неполный
using Length = double;      // объявление псевдонима типа

int main() {
    int* p, q;              // p — указатель на int, а q — просто int
    q = square(4);          // имя уже объявлено — вызывать можно
    p = &q;
    Point* pt = nullptr;    // указатель на неполный тип объявить можно
    // Point obj;           // ошибка: для создания объекта нужен полный тип
    // int w();             // это не переменная, а объявление функции w
    Length len = 2.5;
    std::cout << *p + counter << ' ' << len << ' ' << (pt == nullptr) << '\n';
    // выведет: 17 2.5 1
}

int counter = 1;                      // определение переменной
int square(int n) { return n * n; }   // определение функции
struct Point { int x, y; };           // определение типа
```

`main` пользуется `square` и `counter` раньше, чем они определены: для компиляции достаточно объявлений, а связать имя с определением — задача компоновщика. Если раскомментировать `int w();`, программа по-прежнему скомпилируется, но GCC выдаст предупреждение `-Wvexing-parse`: строка объявляет функцию, а не переменную.

## Ловушки на экзамене

- **«Чем `extern int n;` отличается от `int n;` в области видимости пространства имён?»** — первое только объявление: памяти нет, определение обязано найтись в какой-то единице трансляции, иначе компоновщик выдаст `undefined reference`. Второе — определение: память выделена, значение инициализировано нулём.
- **«Что объявляет `int w();` внутри функции?»** — функцию `w` без параметров, возвращающую `int`, с областью видимости блока, а не переменную и не вызов. Для переменной пишут `int w;` или `int w{};` (последнее даёт ноль).
- **«Почему компилятор пишет `'f' was not declared in this scope`, хотя функция `f` есть в файле?»** — она записана ниже места вызова. Нужно объявить её прототипом до использования или перенести определение выше.
- **«Сколько имён и каких типов вводит `int *p, q;`? А `int a, b;`?»** — в первом случае два имени: `p` типа `int*` и `q` типа `int`, потому что звёздочка относится к объявителю, а не к спецификатору типа. Во втором — тоже два: одно объявление может вводить несколько имён, и это ещё одна причина не путать объявление с вводимым им именем (а заодно повод писать одно объявление на строку).
- **«Достаточно ли `class S;`, чтобы написать `S obj;`?»** — нет. Для создания объекта нужен полный тип, то есть определение класса: компилятору требуется знать размер и состав членов.
- **«Можно ли дважды объявить одно и то же?»** — да: `extern int n; extern int n;` и `void f(); void f();` допустимы, потому что это согласованные объявления. А `int n; int n;` в одной области — ошибка, потому что это два определения.

## Связанные термины

- [[Определение]] — объявление, которое вдобавок полностью задаёт сущность.
- [[Идентификатор]] — то, что объявление вводит в качестве имени.
- [[Тип данных]] — одно из свойств, сообщаемых объявлением.
- [[Область видимости]] — часть программы, в которой введённое объявлением имя доступно.
- [[Ключевое слово extern]] — превращает объявление переменной в «только объявление».
- [[Заголовочный файл]] — штатное место для объявлений, используемых несколькими единицами трансляции.
- [[Раздельная компиляция]] — причина, по которой разделение объявления и определения вообще нужно.
- [[Функция]] — её прототип является классическим объявлением без определения.

## Протокол спора

> [!quote]- Как рождалось определение
> **Версия A (Формалист):** «Объявление (*declaration*) — конструкция языка, которая вводит в единицу трансляции одно или несколько имён и задаёт их интерпретацию: вид обозначаемой сущности (переменная, функция, тип, пространство имён и т. д.), её тип и, где это применимо, связывание. Объявление делает имя известным транслятору, но не обязано полностью задавать саму сущность.»
>
> **Версия Б (Педагог-практик):** «Объявление (*declaration*) — конструкция программы, которая вводит в программу имя (или повторно сообщает о нём) и указывает компилятору его свойства: что это за сущность — переменная, функция, тип и т. п. — и какого она типа. Объявление не обязано создавать саму сущность: это делает определение, которое может находиться в другом месте программы.»
>
> **Спорные пункты:**
> 1. Куда объявление вводит имя. A: в единицу трансляции — в другой единице трансляции того же имени может не быть вовсе. Б: «в программу». → **Решение:** прав A; для термина, вся суть которого в раздельной компиляции, это существенная разница.
> 2. Повторное объявление. Б: в определении явно сказано «(или повторно сообщает о нём)». A: признал эту оговорку точнее своей. → **Решение:** взято у Б и вставлено в определение.
> 3. Точка объявления и `int x = x;`. A: точка объявления — сразу после полного объявителя и до инициализатора, поэтому `int x = x;` компилируется и даёт UB, а не ошибку «имя не найдено». Б: пункта нет. → **Решение:** взято у A. Проверено: GCC 13 компилирует строку, выдавая только `warning: 'x' is used uninitialized`. Это самый показательный вопрос на понимание того, что именно делает объявление.
> 4. Правило неполного типа. A: нужно сформулировать правилом — после `struct Point;` можно `Point*`, `Point&`, параметр и возвращаемое значение, нельзя объект, `sizeof` и доступ к члену. Б: показан только указатель в примере. → **Решение:** взято у A как правило.
> 5. Строгость утверждения «объявление вводит имя». A: грамматически не каждое объявление вводит имя (`static_assert`, пустое `;`, using-directive), и оговорку надо дать отдельным пунктом, не ломая определение. Б: оговорку даёт, но определение утверждает обратное. → **Решение:** определение оставлено в рабочей форме («вводит имя»), а исключения вынесены отдельным пунктом примечаний — ровно как требует регламент.
> 6. «Значки `*`, `&`, `[]` относятся к декларатору, а не к типу» — так у Б. → **Решение:** формулировка поправлена: формально они часть записи типа, просто относятся к конкретному объявителю, а не к спецификатору типа. Смысл вывода (`int* p, q;` — указатель только `p`) сохранён.
> 7. Две метафоры об одном. A: «обещание» и «строка в оглавлении книги» дублируют друг друга, причём вторая неточна — по оглавлению как раз нельзя «сослаться», а объявления для обращения к сущности достаточно. → **Решение:** согласен, книжная аналогия убрана, «обещание» сохранено по смыслу в пункте про `extern`.
> 8. Единственное исключение из правила «объявить до использования». A: исключений больше одного — весь контекст полного класса плюс поиск зависимых имён в шаблонах. Б: названо только «тела методов внутри класса». → **Решение:** формулировка расширена, но без ухода в детали шаблонов.
> 9. Лишние ловушки. A: «`int x = 5;` — это присваивание?» относится к термину «Инициализация», «Обязательны ли имена параметров в прототипе?» — к термину «Функция». → **Решение:** обе убраны из ловушек, но ценный довод Б (объявление — не выражение, `=` здесь не оператор присваивания, что видно на `const int c = 5;`) перенесён в примечания: он прямо отвечает требованию регламента не смешивать оператор и инструкцию.
>
> **Итог:** определение — от A, с вставкой Б про повторное объявление. От Б взяты: разбор устройства простого объявления с примером `const int a = 1, *p = &a, arr[3]{};`, тезис «объявление — не выражение», ловушка про `'f' was not declared in this scope`, ловушка «можно ли дважды объявить одно и то же», флаг `-Wvexing-parse` (проверен на GCC 13) и сам пример — он лучше всего показывает главное свойство объявления, возможность пользоваться именем до его определения. От A взяты: «вводит имя в единицу трансляции», оговорка про объявления без имён, точка объявления и разбор `int x = x;`, правило неполного типа, нормативный перечень «объявление, но не определение» и отсутствие tentative definitions в C++. Арбитр уточнил формулировку про `*`/`&`/`[]`, расширил список исключений из правила «объявить до использования» и перенёс в пример A определение `struct Point` — чтобы одна и та же программа показывала и неполный, и полный тип.
