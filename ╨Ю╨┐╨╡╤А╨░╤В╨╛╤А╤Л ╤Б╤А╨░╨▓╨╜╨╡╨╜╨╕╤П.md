# Операторы сравнения

> [!abstract] Определение
> **Операторы сравнения** (*comparison operators*) — группа бинарных [[Оператор|операторов]], которые проверяют, выполняется ли между двумя операндами заданное отношение: операторы равенства `==`, `!=` и операторы отношения `<`, `>`, `<=`, `>=`, дающие результат [[Логический тип|логического типа]] `bool`. К ним же относится введённый в C++20 оператор трёхстороннего сравнения `<=>`, который вместо `bool` даёт значение одной из категорий упорядочения.

## Примечания и тонкости

- **Три раздела стандарта.** Формально это операторы отношения ([expr.rel]), операторы равенства ([expr.eq]) и трёхстороннее сравнение ([expr.spaceship]). Разделение не формальность: у `<`, `>`, `<=`, `>=` один [[Приоритеты операторов|приоритет]], и он **выше**, чем у `==` и `!=`, а `<=>` старше их всех. Все сравнения слабее арифметики и сильнее `&&` и `||`, поэтому `a + 1 < b * 2 && b != 0` читается без скобок; но [[Битовые операторы|битовые]] `&`, `|`, `^` **слабее** сравнений, из-за чего `x & 1 == 0` работает не так, как задумано.
- **`=` и `==` — разные операторы.** `=` — [[Оператор присваивания|присваивание]]. Условие `if (x = 5)` компилируется: оно записывает `5` в `x` и всегда истинно; g++ с `-Wall` выдаёт здесь `-Wparentheses` (см. [[Предупреждения компилятора]]).
- **Результат — `bool`, а не число.** В C результат сравнения имеет тип `int` (0 или 1), в C++ — `bool`; в поток он печатается как `1`/`0`, а после [[Манипуляторы|манипулятора]] `std::boolalpha` — как `true`/`false`.
- **Приведение операндов к общему типу** идёт по тем же правилам, что и в [[Арифметические операторы|арифметических операторах]] ([[Неявные преобразования типов|неявные преобразования]]). Отсюда главная ловушка: при сравнении знакового с беззнаковым знаковое превращается в беззнаковое, и `-1 < 1u` оказывается **ложно** (`-1` становится `UINT_MAX`). g++ предупреждает (`-Wsign-compare`); в C++20 для математически честного сравнения целых разной знаковости есть `std::cmp_less`, `std::cmp_equal`, `std::cmp_greater` и др. из `<utility>`.
- **Сравнения не образуют цепочек.** `a < b < c` означает `(a < b) < c`: сначала получается `bool`, он продвигается до `0` или `1` и сравнивается с `c`. Математическое «`b` между `a` и `c`» записывается через [[Логические операторы|логическое И]]: `a < b && b < c`.
- **Вещественные числа** хранятся приближённо, поэтому `0.1 + 0.2 == 0.3` ложно: `==` сравнивает точные значения, а не «примерно равные». Сравнивают с допуском — `std::abs(a - b) < eps`, для больших по модулю чисел с относительным допуском. Значение `NaN` не равно ничему, даже самому себе: все сравнения с ним ложны, кроме `!=`, которое истинно, — отсюда идиома проверки `x != x`. Подробнее — [[Вещественный тип]].
- **Указатели, массивы, C-строки.** Для указателей `==` и `!=` определены всегда, а `<`, `>`, `<=`, `>=` задают лишь **частичный** порядок: если указатели не ссылаются в один объект или массив, результат **unspecified** — это не UB, программа корректна, но ответ не гарантирован; полный порядок для контейнеров даёт `std::less<T*>`. Сравнение двух [[Встроенный массив|встроенных массивов]] сравнивает адреса и в C++20 объявлено **устаревшим** (g++: `-Warray-compare`), а `<=>` для массивов вообще ill-formed. Для [[C-строки и строковые литералы|C-строк]] `==` сравнивает адреса, а не содержимое: содержимое сравнивают `std::strcmp` или объекты [[std-string|std::string]], у которых сравнения перегружены по значению.
- **Оператор `<=>` («космический корабль»).** Результат `a <=> b` сравнивают с нулём: `< 0` — меньше, `== 0` — равны, `> 0` — больше (как у `strcmp`). Категория зависит от типа: целые, `bool` и указатели одного типа дают `std::strong_ordering`, вещественные — `std::partial_ordering`, потому что `NaN` несравним ни с чем (`std::partial_ordering::unordered`). Нужен `#include <compare>`.
- **Зачем `<=>` на самом деле.** Для своего класса достаточно объявить `auto operator<=>(const T&) const = default;` — работать будут все шесть сравнений: при defaulted-объявлении `<=>` компилятор неявно объявляет и defaulted `operator==` ([class.compare.default]). Если же `<=>` написан вручную, `==` приходится определять самому: из `<=>` он не синтезируется. Остальные сравнения получаются перезаписью выражений — `a != b` как `!(a == b)`, `a < b` как `(a <=> b) < 0`, причём рассматриваются и кандидаты с перевёрнутым порядком операндов. См. [[Перегрузка операторов]].
- **На практике:** сравнения живут в условиях [[Инструкции выбора|инструкций выбора]] и циклов; три типичные ошибки реального кода — `=` вместо `==`, сравнение `int i` с `v.size()` типа `std::size_t` и `==` для `double`.

## Пример

```cpp
#include <compare>
#include <iostream>
#include <limits>
#include <utility>

int main() {
    std::cout << std::boolalpha;
    int i = -1;
    unsigned n = 1;
    std::cout << (i < n) << ' ' << std::cmp_less(i, n) << '\n';    // выведет: false true
    std::cout << (0.1 + 0.2 == 0.3) << '\n';                       // выведет: false

    auto order = 3 <=> 5;                         // тип std::strong_ordering, не bool
    std::cout << (order < 0) << '\n';             // выведет: true
    auto q = 1.0 <=> std::numeric_limits<double>::quiet_NaN();
    std::cout << (q == std::partial_ordering::unordered) << '\n';  // выведет: true

    // if (i = 0) {}          // присваивание, а не сравнение: условие всегда ложно
    // bool r = 0 < n < 3;    // это (0 < n) < 3, то есть всегда true
}
```

Строка `i < n` намеренно оставлена в примере: она компилируется с предупреждением `-Wsign-compare`, и само это предупреждение — главный практический вывод статьи. Результат `<=>` сравнивается не с другим объектом, а с литералом `0`.

## Ловушки на экзамене

- **«Почему `-1 < 1u` ложно?»** — обычные арифметические преобразования приводят левый операнд к `unsigned`, и он становится `UINT_MAX`: сравниваются уже не те числа, что записаны. Честный результат даёт `std::cmp_less`. Тот же механизм ломает `if (-1 < v.size())`.
- **«Что выведет `std::cout << (3 > 2 > 1);`?»** — `0`: `3 > 2` даёт `true`, то есть `1`, а `1 > 1` ложно. Законно и `if (0 <= x <= 10)`, но это всегда истинно. Корректно — `0 <= x && x <= 10`.
- **«Почему тело `if (x = 0)` никогда не выполняется?»** — это присваивание: `x` становится `0`, значение выражения `0` преобразуется в `false`. Переменная при этом испорчена.
- **«Верно ли `0.1 + 0.2 == 0.3`?»** — нет: ни одно из этих чисел не представимо в двоичной системе точно, и погрешности различаются. Нужно сравнение с допуском.
- **«Что даёт `1.0 <=> NaN`?»** — `std::partial_ordering::unordered`. Именно поэтому у вещественных типов категория частичная: «меньше» не является для них полным порядком.
- **«Истинно ли `"abc" == "abc"`?»** — неизвестно: сравниваются адреса двух литералов, а объединит ли их реализация в один объект, стандарт не уточняет (*unspecified*). Для `std::string` сравнение идёт по содержимому и даёт `true`.
- **«Можно ли сравнить оператором `<` указатели на два разных объекта?»** — можно, это не UB, но результат unspecified. Для сортировки указателей нужен `std::less<T*>` с гарантированным полным порядком.
- **«Сколько операторов надо написать в C++20, чтобы у класса работали все шесть сравнений?»** — один, если это `auto operator<=>(const T&) const = default;`: `==` будет объявлен неявно. Если `<=>` написан вручную, нужны два: `<=>` и `==`.

## Связанные термины

- [[Оператор]] — общее понятие, группой которого являются сравнения.
- [[Логический тип]] — тип результата всех сравнений, кроме `<=>`.
- [[Логические операторы]] — соединяют результаты сравнений в составные условия.
- [[Оператор присваивания]] — `=`, который путают с `==`.
- [[Неявные преобразования типов]] — источник знаково-беззнаковой ловушки.
- [[Вещественный тип]] — объясняет, почему `==` и `<=>` для `double` ведут себя особо.
- [[Перегрузка операторов]] — механизм, которым C++20 синтезирует сравнения из `==` и `<=>`.
- [[Инструкции выбора]] — основной потребитель результата сравнения.

## Протокол спора

> [!quote]- Как рождалось определение
> **Версия A (Формалист):** «Операторы сравнения (*comparison operators*) — группа операторов, которые по двум операндам определяют отношение между ними: операторы отношения `<`, `>`, `<=`, `>=` и операторы равенства `==`, `!=`, дающие prvalue типа `bool`, а также введённый в C++20 оператор трёхстороннего сравнения `<=>`, дающий значение одного из типов-категорий упорядочения (`std::strong_ordering`, `std::weak_ordering`, `std::partial_ordering`).»
>
> **Версия Б (Педагог-практик):** «Операторы сравнения (*comparison operators*) — бинарные операторы, которые проверяют, выполняется ли между двумя значениями заданное отношение, и возвращают результат логического типа `bool`: `true` или `false`. Это операторы равенства `==`, `!=` и операторы отношения `<`, `>`, `<=`, `>=`; в C++20 к ним добавлен оператор трёхстороннего сравнения `<=>`, который возвращает не `bool`, а результат упорядочения.»
>
> **Спорные пункты:**
> 1. Сколько операторов нужно написать в C++20 для шести сравнений. A: два — `==` и `<=>`. Б: достаточно `auto operator<=>(const T&) const = default;`, при этом «`==` тоже генерируется». → **Решение:** прав Б, и это главная содержательная правка статьи. Проверено компилятором: у структуры с единственным defaulted `<=>` работают и `<`, и `==`, и `!=`, и `>=`. Основание — [class.compare.default]: defaulted-объявление `<=>` неявно объявляет defaulted `operator==`. Но утверждение Б верно **только** для defaulted-формы: для написанного вручную `<=>` оператор `==` не синтезируется, поэтому у A правильный ответ для его случая. В итог вошли оба случая с явным разграничением, ловушка A переформулирована.
> 2. Сравнение двух массивов. A: `<=>` для массивов ill-formed. Б: `a == b` сравнивает адреса и в C++20 устарело. → **Решение:** оба правы, утверждения о разных операторах; объединены. Устаревание подтверждено компилятором — g++ 13 выдаёт `-Warray-compare` с `-std=c++20`.
> 3. Полнота определения. Б (за понятность): перечисление трёх категорий упорядочения и слово «prvalue» делают определение A непригодным для устного ответа. A (за точность): у Б потерян класс `std::weak_ordering` и не сказано, что `<=>` — тоже оператор сравнения, а не отдельная сущность. → **Решение:** взят каркас Б («проверяют, выполняется ли отношение», результат `bool`), из A добавлено слово «бинарных» в род и формулировка «группа»; перечень категорий перенесён в примечания, где он нужен вместе с объяснением про `NaN`.
> 4. Указатели. У Б этого нет вовсе; A утверждает, что для несвязанных указателей результат `<`, `>` — unspecified, а не UB. → **Решение:** принято A: [expr.rel] действительно говорит об unspecified; различие UB/unspecified — экзаменационно значимое, пункт и ловушка взяты целиком.
> 5. Приоритет битовых операторов относительно сравнений. Есть только у Б (`x & 1 == 0`). A ограничился фразой «`==` слабее `<`». → **Решение:** взято у Б: это самая частая практическая ловушка приоритета; у A соответствующий разбор есть в статье «Битовые операторы», дублировать его не нужно — в итоге оставлена одна фраза со ссылкой.
> 6. Путаница `=` и `==`, «условие Йоды», `-Wparentheses`. Есть только у Б. → **Решение:** принято; из двух ловушек Б оставлена одна («почему `if (x = 0)` не выполняется»), «условие Йоды» как устаревшая стилистика из итога убрана.
>
> **Итог:** определение — Б, с уточнениями A («группа», «бинарных»). От A взяты: три раздела стандарта и приоритет `<=>` выше равенств, unspecified для несравнимых указателей и `std::less<T*>`, `std::partial_ordering::unordered` для `NaN`, идиома `x != x`, перезапись выражений с перевёрнутыми кандидатами, `-Wsign-compare` в циклах по индексу. От Б: `=` против `==`, `bool` вместо `int` как результат (отличие от C) и `std::boolalpha`, сравнение с допуском, устаревание сравнения массивов, ловушки `3 > 2 > 1` и `"abc" == "abc"`. Арбитр исправил утверждение A про «два оператора» и объединил два верных, но частичных утверждения о массивах; итоговый пример проверен компилятором, включая намеренное предупреждение `-Wsign-compare` и вывод `false true / false / true / true`.
