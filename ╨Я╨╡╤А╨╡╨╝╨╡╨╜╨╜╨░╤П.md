# Переменная

> [!abstract] Определение
> **Переменная** (*variable*) — сущность программы, которую вводит [[Объявление|объявление]] [[Объект|объекта]] или [[Левая ссылка|ссылки]], кроме нестатического [[Поле|члена данных]] класса. Имя переменной, если оно есть, обозначает этот объект или эту ссылку; [[Тип данных|тип]] переменной задаётся объявлением и в дальнейшем не меняется.

## Примечания и тонкости

- Определение воспроизводит стандарт C++20 (`[basic.pre]`): «A variable is introduced by the declaration of a reference other than a non-static data member or of an object. The variable's name, if any, denotes the reference or object.»
- **Что характеризует переменную** (частый вопрос устного экзамена): [[Идентификатор|имя]], тип, значение, адрес, [[Область видимости|область видимости]] и время жизни. Имя и тип фиксируются объявлением и не меняются; меняться может только значение. Строго говоря, значение и адрес принадлежат объекту, который переменная вводит, — для переменной ссылочного типа собственного адреса нет.
- **Переменная и объект — понятия разных уровней.** Переменная — понятие уровня [[Текст программы|текста программы]]: то, что введено объявлением. Объект — понятие уровня выполнения: область памяти, имеющая тип и время жизни. Одной локальной переменной при каждом вызове [[Функция|функции]] соответствует новый объект, а при рекурсии — несколько объектов одновременно.
- Переменными **являются**: переменные в области пространства имён и в блоке; параметры функций, в том числе безымянные ([[Передача параметров и возврат значения]]); [[Статический член класса|статические члены данных]]; переменные ссылочного типа.
- Переменными **не являются**, хотя обозначают объекты: нестатические члены данных (у каждого экземпляра — свой подобъект); элементы [[Встроенный массив|массивов]]; объекты, созданные `new` в [[Динамическая память|динамической памяти]]; временные объекты.
- Обычно объявление переменной одновременно является её [[Определение|определением]], то есть выделяет память. Исключения: объявление с [[Ключевое слово extern|extern]] без инициализатора (`extern int x;`) и объявление статического члена данных внутри класса (без `inline`) — они лишь сообщают о переменной, определённой в другом месте.
- Ссылка — переменная, но не объект: это второе имя уже существующего объекта. Занимает ли ссылка память, стандарт не уточняет (*unspecified*), и собственного адреса у неё нет — в примере `&age` и `&alias` совпадают.
- «Переменная» не означает «изменяемая»: `const int n = 5;` — переменная, [[Константность]] является свойством её типа, а не вида сущности.
- Распространённое определение «переменная — именованная область памяти» неверно по двум пунктам: память принадлежит объекту, а не переменной, и имени у переменной может не быть (безымянный параметр).
- **Где «живёт» переменная:** локальные — в [[Стековая память|автоматической памяти]] (создаются при входе в блок, уничтожаются при выходе), глобальные и `static` — в [[Статическая память|статической памяти]] (существуют всё время работы программы); подробнее — [[Глобальные и локальные имена]]. Динамической продолжительности хранения у переменных не бывает: объект из `new` не вводится объявлением.
- Имя переменной, использованное в выражении, — это [[lvalue и rvalue|lvalue]]: оно обозначает конкретный объект, которому можно присвоить новое значение, если его тип не константный.
- Автоматическая переменная скалярного типа без инициализатора имеет неопределённое (*indeterminate*) значение, и его чтение — UB (исключение — `unsigned char` и `std::byte`). Переменные статической продолжительности хранения до любой другой [[Инициализация|инициализации]] получают нулевую, поэтому глобальная `int g;` равна 0.
- **На практике:** переменную объявляют как можно ближе к первому использованию и сразу инициализируют — это снимает целый класс ошибок с «мусорными» значениями. Различие «переменная/объект» становится практическим при работе с [[Указатель|указателями]]: переменная `p` может выйти из области видимости, а объект `*p` продолжить существовать (утечка), или наоборот — объект уничтожен, а переменная-указатель жива (висячий указатель).

## Пример

```cpp
#include <iostream>

int counter = 0;            // переменная статической продолжительности хранения
extern int declared_only;   // объявление без определения: память не выделяется

struct Point {
    int x;                  // нестатический член данных — НЕ переменная
    static int created;     // статический член данных — переменная (здесь объявление)
};
int Point::created = 0;     // определение статического члена данных

void show(int a, int) {     // параметры — переменные; второй не имеет имени
    int& alias = a;         // переменная ссылочного типа: второе имя для a
    alias += 1;
    std::cout << a << ' ' << (&a == &alias) << '\n';   // выведет: 20 1
}

int main() {
    int age = 19;           // переменная: имя age, тип int, значение 19
    const double pi = 3.14; // const-переменная — тоже переменная
    int* p = new int{7};    // p — переменная; *p — объект без имени, не переменная
    ++counter;
    ++Point::created;
    show(age, 0);
    std::cout << *p << ' ' << pi << ' ' << counter << Point::created << '\n';  // выведет: 7 3.14 11
    delete p;
    // std::cout << declared_only;  // ошибка компоновки: определения нет
}
```

Переменными здесь являются `counter`, `declared_only`, `Point::created`, `age`, `pi`, `p`, `a`, безымянный второй параметр и `alias`; переменными не являются `Point::x` и объект `*p`.

## Ловушки на экзамене

- **«Переменная — это именованная область памяти»: верно?** — Нет. Память — атрибут объекта; переменная лишь вводит объект (или ссылку) и, возможно, даёт ему имя. Безымянный параметр — переменная без имени, а объект из `new int` — область памяти, не являющаяся переменной.
- **Является ли поле `x` в `struct P { int x; };` переменной?** — Нет: стандарт явно исключает нестатические члены данных. Оно существует только как часть конкретного объекта, и у каждого объекта своё. Статический член данных — переменная, одна на весь класс.
- **Сколько переменных в `int* p = new int(5);`?** — Одна: `p`. Объект `*p` имеет динамическую продолжительность хранения и никаким объявлением не вводится.
- **Является ли `const double pi = 3.14;` переменной, раз её нельзя изменить?** — Да: `const` меняет тип объекта, но не вид сущности. «Константная переменная» — нормальный термин C++, а не оксюморон.
- **Чему равно значение `int x;` внутри функции? А в глобальной области?** — Внутри функции значение неопределённо, и его чтение — UB (а не «случайный, но безопасный мусор»: компилятор вправе считать, что такого чтения не происходит). Глобальная равна 0 благодаря нулевой инициализации.
- **Можно ли после объявления поменять тип переменной?** — Нет: C++ статически типизирован, тип фиксируется объявлением. `age = "twenty";` для `int age` — ошибка компиляции, а не смена типа.

## Связанные термины

- [[Объект]] — область памяти, которую вводит и обычно именует переменная
- [[Объявление]] — конструкция, вводящая переменную в программу
- [[Определение]] — объявление переменной, выделяющее под неё память
- [[Тип данных]] — задаёт множество значений и допустимых действий
- [[Инициализация]] — задание начального значения при создании переменной
- [[Левая ссылка]] — переменная-псевдоним, которая не является объектом
- [[Область видимости]] — часть программы, где доступно имя переменной
- [[Глобальные и локальные имена]] — где переменная хранится и как долго живёт

## Протокол спора

> [!quote]- Как рождалось определение
> **Версия A (Формалист):** «Переменная (*variable*) — сущность программы, вводимая объявлением объекта или ссылки, если объявляемая сущность не является нестатическим членом данных класса. Имя переменной, если оно есть, обозначает этот объект или эту ссылку.»
>
> **Версия Б (Педагог-практик):** «Переменная (*variable*) — именованный объект или именованная ссылка, введённые объявлением (кроме нестатических полей класса). У переменной есть тип, который фиксируется при объявлении и определяет, какие значения она может хранить и какие действия над ней допустимы.»
>
> **Спорные пункты:**
> 1. Род понятия: «сущность, вводимая объявлением» (A) против «именованный объект или ссылка» (Б). Б возражает, что род у A неинформативен. → **Решение:** род A, он корректен по `[basic.pre]`. Формулировка Б ошибочна дважды: безымянный параметр — переменная без имени, и переменная не *есть* объект (ссылка — переменная, но не объект; сам Б пишет это в примечаниях, противореча своему определению).
> 2. Тип в определении. Б настаивает, что без типа определение не отвечает, чем переменная отличается от прочих сущностей. → **Решение:** принято, второе предложение дополнено словами о типе, фиксируемом объявлением. Это же закрывает вопрос о статической типизации.
> 3. Оговорка про нестатические члены данных внутри определения. Б считает её нарушением регламента. → **Решение:** оставлена, но сжата до «кроме нестатического члена данных класса» — это видовое отличие, а не оговорка, и именно в таком виде она зафиксирована в терминологических соглашениях регламента.
> 4. «Что характеризует переменную» — список из шести пунктов (Б) против «тип, продолжительность хранения, область видимости, связывание» (A). → **Решение:** взят список Б как прямой экзаменационный вопрос, но с уточнением арбитра: значение и адрес принадлежат объекту, а у ссылки собственного адреса нет — иначе список противоречит разделению «переменная/объект».
> 5. Структурированные привязки. A: «`a` и `b` — имена привязок, а переменной является лишь скрытый безымянный объект». → **Решение:** пункт удалён. Б прав: по `[dcl.struct.bind]` вводится переменная с уникальным именем, а не «безымянный объект»; для блока 1 тема преждевременна.
> 6. Обоснование «динамической продолжительности хранения у переменных не бывает». A обосновывал это отсутствием имени, хотя сам считает переменными безымянные параметры. → **Решение:** вывод сохранён, обоснование исправлено на «объект из `new` не вводится объявлением».
>
> **Итог:** определение — A, дополненное требованием Б о типе. От A взяты: разделение «переменная/объект» с объяснением через вызовы функции и рекурсию, опровержение школьного «именованной области памяти» по двум пунктам, перечни «является / не является», второй пример «объявление ≠ определение» (член класса), ловушка про значение `int x;`. От Б: пункт «что характеризует переменную», «где живёт переменная», нормальный случай «объявление есть определение», имя в выражении как lvalue, ловушка про невозможность сменить тип, практический совет первокурснику. Арбитр убрал из версии A ODR, потоковую продолжительность хранения, связывание и *erroneous behavior* C++26 как материал будущих блоков, исправил обоснование про динамическую продолжительность и собрал новый пример: у A он требовал знания структурированных привязок, а суммарный вывод `12` ничего не проверял.
